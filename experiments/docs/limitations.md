# 当前支持范围与限制

本文列出理解和使用当前实验链路所必需的边界。有效行为与模型分别以[需求](requirements.md)和[架构](architecture.md)为准；持续验收场景见[validation](validation.md)。本文不重复保存已完成修复清单，历史材料见[归档入口](history/README.md)。

## 文档与坐标范围

- 当前实验针对数字型 PDF。固定 Docling 基线不开启 OCR，不代表已验证扫描件的完整处理能力。
- 仅确认无旋转且 CropBox 与 MediaBox 一致页面的公共坐标映射。旋转或裁切映射未经验证时，保留原始信息并延后几何处理，不拿未经确认的坐标参与准入。
- 跨页表保留原始结构并延后处理，本阶段不实现跨页拼接。Docling 逐页恢复已做故障注入测试，但未覆盖所有真实 PDF 后端的错误类型。
- Unstructured 当前适配 text_as_html；无可恢复结构时保留 unplaced_text，不伪造网格。可选 table_as_cells 尚未适配。

## 准入与选优的含义

- Docling 是唯一卡位来源。多工具候选只能改善已经发现的卡位，不能补出 Docling 漏掉的表格，也不能仅凭覆盖率识别错误卡位。
- winner 是组内相对最优候选，不是绝对质量认证。现行阈值和评分规则来自有限样本，不能据此承诺最终 RAG 问答效果。
- 正式 RAG 的多 parser、文档与表格融合、表格文本化、chunking 和 embedding 适配尚未在本实验重构中实现。

## 输入身份与历史兼容

- 新版提取记录文件身份、配置与页级事实。历史提取缺少这些信息时显式输出 legacy warning，不补造历史成功页，也不替历史配置背书。
- 同 stem 输出共享位置，来源校验用于防止串用，不是多版本缓存。要同时保存多个版本，应指定不同输出父目录。
- CLI 的 --output-dir 只改变当前阶段输出，不自动成为下游输入；完整 CLI 串联使用默认目录，自定义输入由应用接口显式提供。

## 发布与运行环境

- 发布支持进程内异常回滚，不承诺断电或强杀进程时的跨目录原子提交。
- 四工具仍需要相应 Python 依赖、本地模型及必要系统组件；不是只取得源码就能脱离这些环境运行。
- 临时目录不是项目资产；Docling 处理非 ASCII 路径时会按需创建 experiments/.tmp，无需预先保留旧诊断脚本或日志。

## 数据与复现条件

- 人工标签保存在 data/calibration 并纳入版本管理；原 PDF 位于被忽略的 documents/，派生结果位于被忽略的 output/。克隆仓库后，自动生成样本的单元测试可以运行；真实 PDF 提取和既有校准样本复现需要另行准备源 PDF 和提取结果。
- 历史验收记录描述当时的实际检查，不是每次提交都会自动更新的测试计数。旧 tmp/ 中的对照快照和日志已清理；可重新运行当前链路，但不能仅凭剩余文件重放重构前后的原始哈希比较。
