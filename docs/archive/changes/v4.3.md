- 只靠表格上方批次标题区分的题（DELIV-FONAFE-Q004）：返回命中 chunk 时规则方式漏掉（后续块不带标题与表头），LLM 结构标注把标题标为节标题并在每块重复，命中；返回整表时各组合都覆盖。同一张表首块中的题（Q003）各组合都覆盖。
- 验收 1：PDF、Word 的构建记录不变，入库时"无变化"；PDF、Word 题的完整覆盖、命中、MRR 在 13 种组合下与 V4.2 相同，7 种组合中 1–3 题前 3 名的次序有变化。对照实验：`structured` 去掉 `[xlsx_parser]` 建索引，两种返回单元下 PDF、Word 题与 V4.2 逐题相同（含 BM25 分数），实验配置与索引已删除。
- 验收 2：四份 Excel 的入库审核页经停顿点 1 用户核对；验收 3：评估页与对比页按文档类型分列，Excel 单列，评估页列出超过返回上限的表格（本库没有）；验收 4：438 个测试通过。

**与提案的差异**
- 区域切分（开工前与实施中修订，用户确定）：去掉标题剥离；有边框的空格算占用；外接矩形重叠、或首末行都相同且都至少 2 行的区域合并（只按共边相连会把有隔列的表切碎）。
- 表格上下文（表格前的短文字写入表格 chunk）延后到 V4.4，PDF、Word、Excel 统一改（[v4.4.md](../../changes/v4.4.md)）。
- 显示值：General 写出最多 11 位有效数字；Excel 的 General 显示还受列宽影响，本库题目未涉及此类格。数字格式只用到 openpyxl 给出的编号与字符串；本库四份文件没有按 General 回退的格，也没有缺缓存值的公式。
- excerpt 定位：Excel 片段只在一个格内连贯（同一行的格以 ` | ` 分成片段），多处出现按最小生成树（同提案）；定位提示取提示格的列，合并格取它覆盖的各列。
- 评估：Excel 文档按工作表地址识别，单列为"Excel"；整表返回上限按与每题返回 token 相同的计数（含 `passage: ` 前缀）。
- 出题（停顿点 2 用户修订）：删去证据遍布多处的题；批次标题题拆成首块与后续块两道对比题；增加带前提、两跳、跨工作表比对题；同一张小表上的题减少。

**规则版本**：本版改变输出的步骤只有新的 Excel 解析器 `xlsx_native`（`RULES_VERSION = "v4.3"`，新建）。共用步骤（表格处理、组装、分块、编码、BM25、来源区域）为 Excel 加的分支不改变 PDF、Word 的输出，版本不提升；`whole_table_max_tokens` 是查询设置，不进构建记录。

## 开工前修订（2026-11-16 用户确定）

- **解析只做几何切分，不解读内容**：去掉原第 3 节的"标题剥离"。区域顶部的单行标题、区域内部横跨全宽的分节行都留在表格里，由表格结构环节处理（规则表头判定跳过顶部横跨整表的标题、取样跳过分节行；LLM 结构标注能标出节标题与分节）。规则方式恢复不了这类表的语义，属于规则方式本身的局限，不在解析器中补救。
- Excel 的元素只有三种：工作表名（标题，Excel 本身的结构）、表格区域、正文。表格之外的单格、单行、单列区域都是正文。
- 外接矩形重叠的连通区域合并为一个区域（反复合并到无重叠），使表格网格中不混入别的区域的格子。
- **区域切分补两条几何事实**（2026-11-16 实施中发现、用户确定）：只按共边相连时，空的隔列与表内稀疏的空格把一张逻辑表切碎（`交付清单.xlsx` 的"中信保额度确认"切出 48 张表、28 段正文；TOTALES 每张表被空列切成左右两半）。
  1. 有边框（任一边）的空格也算占用。边框是文件中画出表格的线，只用来确定表格覆盖哪些格，不用来推断表头、分节等语义。只由空的有边框格组成、没有值的区域丢弃。
  2. 首行、末行都相同（上下边对齐）且都至少 2 行的区域，左右并排也合并。不用"行范围有重叠"或"包含"：不同的表可能写在同样的行里（"3 保函…"工作表并排的三节费用表各自独立，行范围互相包含）。单行区域不按此合并（并排的几节标题各自保留）。
  3. 已知局限：同一张逻辑表左右两块高度不同、又没有边框时，切成两张表。
- 合并区域左上角没有值时不算占用。
- 单元格的事实记显示值、缓存值、公式文本（有公式时，含跨工作表引用，原样记录、不解析）；chunk 只写显示值，审核页可展开公式。
- **表格上下文延后到 V4.4**（[v4.4.md](../../changes/v4.4.md)）：表格前的短节点写入表格 chunk，PDF、Word、Excel 统一改。V4.3 的分块规则不变；需要靠表格上方文字区分的 Excel 题照常收录，作为 V4.4 的目标题。
- 测试文档为四份 Excel，编码登记在 `documents/documents.toml`：`FAT plan.xlsx`（FAT2025001）、`交付清单.xlsx`（DELIV2025001）、`ENEL Tender information.xlsx`（TENDER2024001）、`FONAFE普表招标一般贸易概算-20251204.xlsx`（BUDGET2025001，含跨工作表引用的公式、隐藏与深度隐藏的工作表、隐藏行列）。四份都没有 Table 对象。
- 出题不限数量；同一张表上本质相同的问题只出一道，题型拉开；每份 1 道不可回答题。
- 依赖：`pyproject.toml` 显式写入 `openpyxl==3.1.5`。

## 范围的边界

本版只处理"答案写在某几个单元格或某段文字里"的查找型问题。需要对很多行计算的问题（求和、计数、筛选、排序、分组、跨表连接）由 Text-to-SQL 或 pandas 等工具完成，规整后的表格存入数据库，属于主项目，本版不做，测试集也不收这类题。

## 目标

1. `documents/` 中的 .xlsx 入库、检索、问答、评估。
2. 写进 chunk 的是单元格的显示值（与 Excel 屏幕上看到的一致）。
3. 很长的表格不再整表返回。
4. 用户提供的 Excel 文档加入测试集（数据集 4.3.0）。
5. 现有 PDF、Word 文档的 chunk 与指标不变。

## 改什么

### 1. 读取（`rag/ingest/xlsx/reader.py`，解析器与 `anchors` 共用）

- openpyxl 3.1.5 读两遍：`data_only=True` 取缓存值；默认模式取公式，用于找出"有公式但没有缓存值"的格。不用 `read_only` 模式，因为它读不到合并单元格。
- 只遍历有值的单元格，不按 `max_row` × `max_column` 遍历（格式会把已用范围撑得很大）。
- **工作表**：按工作簿顺序读取全部工作表，包括隐藏（`hidden`）与深度隐藏（`veryHidden`）的。图表工作表跳过。
- **隐藏**：工作表状态、隐藏的行（`row_dimensions[r].hidden`）、隐藏的列（`column_dimensions` 各范围的 `hidden`）作为事实记在单元格与元素上。**照常入库**（2026-11-10 用户确定），chunk 文字中不加标记，审核页标出。
- **合并单元格**：取 `merged_cells.ranges`，值在左上角格，区域内其他格视为被占用。
- **Excel Table 对象**（`ws.tables`）：其范围直接作为一个表格区域，表头行数记为事实；表头仍按规则判定。
- 图片、图表、批注、数据验证、条件格式不入库；图片、图表各记一条警告。

### 2. 显示值（`rag/ingest/xlsx/display.py`）

单元格的显示值按单元格的数字格式写出：

| 值 | 显示值 |
|---|---|
| 空 | 空，不占用该格 |
| 文字 | 原样（富文本取纯文字） |
| 布尔 | `TRUE` / `FALSE` |
| 错误值 | 原样（如 `#N/A`） |
| 有公式、没有缓存值 | 空，记警告 `formula_without_cached_value`，审核页列出 |
| 数字、日期 | 按数字格式（下述规则） |

**数字格式**：
- 按 `;` 分成正数、负数、零、文字四节，取对应的节；带条件（`[<100]` 等）的格式按 General 写出，并记警告。
- 支持的记号：`0`、`#`、`?`（数位占位，不足的位写成空格）、`,`（千分位）、`.`、`%`、`E+`/`E-`、引号中的文字、`\` 转义的字符、`_`（留空，写成一个空格）、`*`（重复填充，忽略）、`[$符号-区域码]`（写出符号）；颜色 `[Red]` 等忽略。末尾逗号的缩放、分数 `?/?` 按 General 写出，并记警告。
- 显示值去掉首尾的空白（会计格式用 `_`、`*`、`?` 对齐产生的空格）。会计格式的零值节（`"-"??` 一类）写成 `-`。
- 格式按单元格的 `numFmtId` 判断是否为内置格式：openpyxl 把 14 号报告为字符串 `mm-dd-yy`，只看格式字符串会与自定义格式混淆。
- **General**：整数不带小数；其他数字最多 11 位有效数字，去掉末尾的 0，不加千分位。
- **日期与时间**：记号 `yyyy`、`yy`、`m`、`mm`、`mmm`、`mmmm`、`d`、`dd`、`ddd`、`dddd`、`h`、`hh`、`mm`（在 `h` 之后或 `s` 之前表示分钟）、`ss`、`AM/PM`。区域码 `[$-xxxx]` 指向西班牙文、英文、中文时，月份名与星期名用该语言，否则用英文。
- **跟随系统设置的内置格式**（14 号短日期、22 号日期时间）：在 Excel 中的显示随操作系统的区域设置而变。一律写成 `yyyy-mm-dd`（22 号为 `yyyy-mm-dd hh:mm`）。**标注规则**：这类格子的 excerpt 也按这一写法照抄。
- 小数点、千分位固定为 `.` 与 `,`（openpyxl 不提供区域设置；工作簿里存的格式本身就使用这两个符号）。

### 3. 区域切分（`rag/ingest/xlsx/regions.py`）

在每个工作表上，把被占用的格（有显示值的格、合并区域覆盖的全部格、有边框的空格）切成区域：
1. Excel Table 对象的范围先各自成为一个区域，它覆盖的格不参与后续切分。
2. 其余被占用的格按上下左右相邻（共用一条边）求连通区域。
3. 外接矩形重叠的区域合并；首末行都相同且都至少 2 行的区域合并；反复进行到不能再合并。没有值的区域丢弃。表格的网格取外接矩形，其中未占用的位置为空格。
4. **分类**（按外接矩形）：
   - 至少 2 行、至少 2 列的区域为**表格**；
   - 只有 1 行的区域写成一段文字，各格的显示值以 ` | ` 连接；
   - 只有 1 列的区域，每格写成一段文字。
5. **阅读顺序**：工作表按工作簿顺序；工作表内，区域按左上角的行号、再按列号排列。每个工作表的第一个元素是以工作表名为文字的标题元素，位置为该工作表。
6. 区域与分类结果作为事实写入中间结果。

### 4. 解析器 `xlsx_native`（`rag/ingest/parsers/xlsx_native.py`）

- 表格交给现有的规则表头判定与表格三个环节，标记为 `parser_exact`（V4.2 已有），不经过提取、选优与续表。
- `PrimaryDocument.page_count` 记工作表数。
- **位置**：`xlsx` 种类，为工作表名 + 行 + 列（从 1 开始）+ 字符区间。字符区间只在格内文字被切开时使用。
- **配置**：`[xlsx_parser]`（`use = "xlsx_native"`），七份内置配置都加；`plain_text` 不加。

### 5. 长表格的返回上限

- 新增查询设置 `[retriever] whole_table_max_tokens`（内置默认 4000；按 multilingual-e5 分词器计数，与分块预算相同）。整表文本超过上限的表格，命中时只返回命中的 chunk，与 `table_return_unit = "chunk"` 相同。它是查询设置，改动不需要重建索引；`--whole-table-max-tokens` 可临时覆盖。
- 默认值的依据：现有索引中最大的整表为 1750 token（PO 25-19 数量表，2026-11-10 测量），4000 不改变现有文档的结果；K = 3 时最多返回约 12000 token。
- 评估：超过上限的表格按 chunk 计返回单元。报告中列出超过上限的表格及其 token 数。

### 6. 证据判定与审核页

- **excerpt 定位**（`anchors` 读 .xlsx）：
  - 单元序列由 `reader.py` 与 `display.py` 给出：每个占用的格是一个单元，文字为显示值，按工作表、行、列排序；
  - 片段规范化后与格的显示值匹配。片段可以是一格的全部或一部分（长文字格），也可以按 ` | ` 跨同一行的相邻格；
  - 片段出现在多处时，仍取总长最小的最小生成树。两处的距离：同一工作表内为行差 + 列差 × 0.25；不同工作表之间加 1000；
  - 定位提示：同一表格区域中表头文字所在的列；
  - **excerpt 照抄 Excel 屏幕上的显示值**（第 2 节的内置日期格式除外）。显示值规则若写错，定位会失败，从而把问题暴露出来。excerpt 可以来自隐藏的格。
- **判定**：一个词所在的格（同一工作表、行、列）属于某个 chunk 的区域，就被该 chunk 覆盖；长文字格再按字符区间判定。其余规则不变。
- **入库审核页**（Excel 文档）：每个工作表一个标签页，显示网格。区域按分类着色（表格、正文），隐藏的行、列、工作表加斜纹，以下几类格标出：公式没有缓存值的格、显示值按 General 回退的格、合并单元格。
- **excerpt 审核文件**：同样的网格网页，高亮各片段所在的格。

## 不改什么

- 不支持 .xls、.xlsm、.xlsb、.csv、.ods。
- 不做计算型查询，不把表格存入数据库（主项目）。
- 不重新计算公式，只用缓存值。
- 不按单元格的字体、颜色、边框推断结构（边框只用于确定表格覆盖的范围，见开工前修订）。
- PDF、Word 的处理与指标不变。

## 怎么验收

1. 现有 PDF、Word 文档的 `chunks.json` 与指标不变（`whole_table_max_tokens` 不影响现有表格）。
2. Excel 的入库审核页与 Excel 中看到的一致：显示值、区域、合并、隐藏标记。
3. 新题入库评估，报告按文档类型分列，列出超过返回上限的表格。
4. `uv run pytest` 全部通过。
