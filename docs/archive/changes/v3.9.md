# V3.9 提案：BM25 关键词检索与混合检索

状态：**已完成**（2026-10-12 收尾，待验收）　｜　分支：`retrieval-opt`　｜　基线：`v3.8`　｜　日期：2026-10-10

属于"检索效果优化"主题。现在只有向量检索（bge-m3）。问题是中文，文档是西班牙文和英文，问题里常夹着原文的专有名词、型号、术语和数字（ELCTO、ENSA、HXE34K-S1、Garantía de fiel cumplimiento、Penalidad por Mora 等）。向量检索对这类精确字面匹配不敏感。本版增加 BM25 关键词检索，与向量检索按排名融合，并用评估判定是否改为内置装配的默认检索方式。

## 实施结果

BM25 倒排索引与 `bm25`、`hybrid` 检索器按 2 节实施；Q4 选 C（评估题目去掉文档标题，数据集 3.2.0），Q5 选两套内置装配都默认 `hybrid`，取舍见[决策 009](../../decisions/009-hybrid-retrieval.md)。chunk 与 V3.8 逐字相同。

- structured（混合）：命中 21/24、完整覆盖 19/24、证据组召回 82.6%、MRR 86.8%、Chunk 精确率 48.6%；同一数据集纯向量为 20 / 18 / 78.5% / 81.9% / 47.2%，变好 2 题、变差 0 题。
- plain_text（混合）：命中 12/24、完整覆盖 8/24、证据组召回 40.3%、MRR 80.6%、Chunk 精确率 51.4%；同一数据集纯向量为 14 / 7 / 39.2% / 77.8% / 45.8%，变好 1 题、变差 2 题。
- 跨文档污染 0，文档识别 24/24，文字兜底 0。对比页：`reports/compare/v3.9-hybrid/`。

与提案的差异：

1. 按提案（数据集 3.1.0、分析器去停用词不词干化）的三种混合检索都低于纯向量；原因是问题中的文档标题词主导 BM25，见"实施中的发现"。由此新增 Q4、Q5。
2. 分析器默认改为去停用词 + 词干化（提案为不词干化）；内置装配加入 `[lexical]`。分析器对比的实验配置已删除，评估报告保留。
3. 新增 `--retriever`（`search`、`ask`、`chat`、`eval`）：同一索引上换检索器，不另建配置；检索器不是 `semantic` 时评估目录名带上检索器名，"较上次"只比同一检索器。
4. 首页与 `status` 分别显示向量索引、倒排索引的完整性，并列出配置的索引与默认检索器。
5. BM25 的 k1、b 与 RRF 常数为代码中的固定常数，不作配置参数（提案写作查询配置）。
6. 默认检索器未按 Q2 的判定规则决定：两套装配都改为混合检索（Q5），理由写入决策 009。

## 0. 需要你拍板的问题

### 已确定（2026-10-10 讨论）

- BM25 建立持久化的倒排索引，与向量库并列，纳入现有的入库与一致性机制。
- IDF 按全库统计，不随检索范围变化。
- 做词干化与不做词干化的对比。
- bge-m3 自带的稀疏检索（lexical weights）这一版不做，列入下一步候选。

Q1 选 A、Q2 按推荐规则（2026-10-10 确认）。

### Q1 词干化用哪种语言的规则

**事实**：词干化把单复数、动词变形归并成同一个词干（garantías、garantía → garanti）。常用的 Snowball 词干器是按语言划分的，西班牙文和英文的规则不同。我们的合同、发票是西班牙文，订单是英文；用错语言的规则，词干会切错。

| 选项 | 做法 | 影响 |
|---|---|---|
| A（推荐） | 入库时按停用词比例判定每份文档的语言（西班牙文常见词与英文常见词各数一遍，多者为准），这份文档的 chunk 都用该语言的词干器；查询时，问题的词分别按两种语言取词干，每个 chunk 只用自己语言的词干计分 | 每份文档只用对的规则；判定是确定性规则，不引入语言识别模型；新增依赖 `snowballstemmer`（纯 Python，BSD 许可证） |
| B | 所有文本同时套用两种语言的词干器，两个词干都记入索引 | 实现简单，但同一个词计两次，词频和文档长度被人为放大，结果难解释 |

### Q2 怎么判定胜出、是否改为默认

**推荐规则**（沿用 V3.8；24 题，1 题 = 4.2 个百分点）：

1. 混合检索在两套装配上的命中率、完整覆盖都不低于基线（V3.8，纯向量检索），且 structured 的"变好"题数多于"变差"题数，才算有效提升；差距不超过 1 题视为持平。
2. 多个混合检索配置都有效时，选 structured 完整覆盖更高的；持平时选规则更少的。
3. 有胜出者，两套内置装配都改为混合检索，并按需重建；没有胜出者，内置装配保留纯向量检索，`bm25`、`hybrid` 仍作为可选实现保留在代码中，结论写进决策文档。

无论结果如何都保留实现，理由是：关键词检索是主项目查型号、合同号的基础能力，本版的评估题偏语义，不一定能体现它的价值。

### Q3 去不去停用词

**事实**：IDF 按全库统计，而语料是西、英混合，西班牙文停用词只出现在西文文档中，英文停用词只出现在英文文档中，全库看并不高频。当前索引中（chunk 数 / 总数 → IDF）：

| 词 | structured | plain_text |
|---|---|---|
| de | 35/95 → 0.99 | 145/266 → 0.61 |
| por | 19/95 → 1.59 | 47/266 → 1.73 |
| the | 22/95 → 1.45 | 60/266 → 1.48 |
| garantia | 7/95 → 2.55 | 11/266 → 3.14 |
| mora | 3/95 → 3.31 | 3/266 → 4.33 |

`por` 的权重约为 `garantia` 的六成，停用词靠 IDF 降权的效果不够。

| 选项 | 做法 | 影响 |
|---|---|---|
| A（推荐） | 去停用词：用 Snowball 项目发布的西班牙文、英文停用词表（BSD 许可证，作为数据文件放进仓库），在词干化之前，问题与 chunk 中出现在任一表里的词都去掉；默认开启，配置可关闭；每套装配加一份不去停用词的对比配置 | 问题不带语言标记，所以两侧用同一张合并表。已知代价：西文停用词 `este` 在公司名 ELECTRO SUR ESTE 中意为"东"，会被去掉；该名称其余的词仍可匹配。实验配置由 6 份增加到 8 份，多约 15 分钟入库 |
| B | 不去停用词 | 停用词给含它们多的长 chunk 加分，形成噪声 |

### Q4 识别文档用的文字是否参与 BM25 打分（实施中提出；2026-10-12 结论：选 C）

**结论**：不加剔除规则（A 的规则针对性太强、通用性不够；用户在问题中写出标题时，返回含标题的 chunk 符合 BM25 的检索目标）。改为 C：评估题目去掉文档标题、只保留标识编码，因为题目中写标题原本是为了定位文档，这一作用已由标识编码承担。基线在新题目上重测。局限：实际提问中用文档编号（写在标题里）指代文档时，标题词仍会让标题 chunk 靠前，写入决策文档。

同时确定：BM25 分析器默认去停用词 + 词干化，内置装配加入 `[lexical]`；分析器对比的实验配置删除；新增 `--retriever` 参数，在同一索引上换检索器评估，不另建配置。以下保留拍板时的事实与选项。

**事实**：见"实施中的发现"。标题词只说明"问的是哪份文档"，这个信息已经由检索范围（标识编码）表达；再参与 BM25 打分，就会把标题 chunk 推到前面。现有的标识编码（ORDER2025001 等）不出现在 PDF 中，所以去不去它们都没有影响；起作用的是问题里同时写出的文档标题。

| 选项 | 做法 | 影响 |
|---|---|---|
| A（推荐） | 规则：问题中与已登记标识编码相匹配的文字只用于确定检索范围，从 BM25 查询中去掉（向量查询不变）。你在 `documents/documents.toml` 中把文档上写的标题编号也登记为编码：`CONTRATO N° 105-2025`、`E001-602`、`PURCHASE ORDER N° 24-12-HPE`、`PURCHASE ORDER N° 25-15-HPE`、`PURCHASE ORDER N° 25-19-HPE` | 预计达到诊断中"去标题"的结果，structured 胜出。只有问题里写出已登记的编码时才去掉；用未登记的说法指代文档时，标题词仍会干扰 BM25。标识表不进 git，换机器需随 PDF 拷贝（与现在相同） |
| B | 不去掉；混合检索按 Q2 不胜出，内置装配保留纯向量检索，`bm25`、`hybrid` 作为可选实现保留，结论写进决策文档 | 本版指标不变 |

A 实施后，按 Q2 的规则重新判定；只重跑评估（检索设置不进指纹），不用重建索引。

### Q5 内置装配的默认检索器（实施中提出；2026-10-12 结论：两套装配都改为 hybrid）

**结论**：两套内置装配都默认混合检索。理由：两套装配的证据组召回、MRR、Chunk 精确率都提高；plain_text 命中下降来自 K=3 下不可能完整覆盖的两题，混合检索在这两题返回的相关 chunk 更多。这一决定没有按 Q2 的判定规则执行，24 题下 1–2 题的差距只说明趋势。以下保留拍板时的事实与选项。

**事实**：见"数据集 3.2.0 上的结果"。混合检索按 Q2 不胜出，原因是 plain_text 两题由部分覆盖变为未命中，而这两题混合检索返回的相关 chunk 更多；structured 2 题变好、0 题变差，但幅度在持平范围内。

| 选项 | 做法 | 影响 |
|---|---|---|
| A（推荐） | 按 Q2：两套内置装配保留纯向量检索；BM25 索引照常构建，混合检索可用 `--retriever hybrid` 或配置选用；结论写进决策文档 | 遵守事先定下的判定规则；默认指标不变（新数据集上 structured 20 / 18 / 81.9%） |
| B | structured 改为混合检索，plain_text 保留纯向量 | structured 默认指标升到 21 / 19 / 86.8%；但这是看过结果后放宽规则，24 题下 1 题的差距不足以证明提升 |

## 1. 目标

1. 新增 BM25 检索与混合检索两种检索器，可以在配置中选用。
2. BM25 倒排索引与向量库一样，由入库建立、由 `status` 检查完整性、可以检测并重做。
3. 用评估和对比页回答：BM25 单独能找对哪些题；融合后相对纯向量检索的变好、变差；去停用词、词干化各有没有用。

## 2. 改什么

**分析器（文本 → 词列表）**：问题和 chunk 用同一套规则。规则写进新文件 `docs/rules/lexical.md`。

1. NFKC 归一、统一小写、去掉重音符号。
2. 由字母、数字组成，中间可以用 `-` `.` `/` `,` 连接的一串字符记为一个词，同时把它按连接符拆开的各段也记为词（型号、编号、金额既能整体匹配，也能部分匹配）。
3. 汉字每个字记为一个词。文档几乎不含中文，问题中的中文基本不会命中，不为此引入中文分词库。
4. 去停用词开启时，去掉出现在西班牙文或英文停用词表中的词（Q3）。
5. 词干化开启时，对拉丁字母词按 Q1 的规则取词干。

分析器设置（是否去停用词、是否词干化）影响索引内容，进入构建指纹。

**BM25 索引**：存放在 `.rag/indexes/<配置名>/bm25.sqlite`，使用 Python 自带的 SQLite，不引入搜索引擎。

- 记录每个词出现在哪些 chunk、出现几次，以及每个 chunk 的词数、所属文档和语言。
- 入库顺序改为：处理 → 写中间结果 → 替换向量 → 替换该文档的 BM25 记录 → 更新 manifest（仍然最后写）。全量重建时两个库都清空重建。
- `status`：BM25 索引中的 chunk ID 与 manifest 不一致，记为"索引不完整，需重建"，与向量库的检查规则相同。
- 只有配置了 `[lexical]` 一节的装配才建立 BM25 索引。检索器选 `bm25` 或 `hybrid` 而没有配置这一节时，装配校验报错。

**检索器**：

- `bm25`：在检索范围内的 chunk 中按 BM25 分数排序。IDF、平均 chunk 长度按全库统计。参数 `k1 = 1.2`、`b = 0.75` 属于查询配置，不进指纹。
- `hybrid`：分别取向量检索和 BM25 在检索范围内的排名，按倒数排名融合（RRF）计算得分：每一路的得分为 1 /（60 + 名次），名次从 1 起；两路相加，BM25 分数为 0 的 chunk 不计 BM25 这一路。按得分从高到低排序，同分时按 chunk ID 排序。
- 命中结果保留两路的名次和原始分数。`search` 的输出和评估报告的每条命中都显示这两个名次，便于判断是哪一路找到的。

**评估与对比**：

- 评估的 `result.json` 记录检索器设置。
- `compare` 的分组改为：构建设置中除编码器和 `[lexical]` 之外都相同、检索器可以不同、K 相同的评估放在同一标签页；每列标明编码器和检索器。
- 实验配置（另存新名字，评估目录据此区分；除注明外都去停用词、不词干化）：`structured_bm25`、`structured_hybrid`、`structured_hybrid_stem`（加词干化）、`structured_hybrid_keepstop`（不去停用词），`plain_text` 同样四份。基线为 V3.8 的两份评估。生成对比页 `reports/compare/v3.9-hybrid/`。
- 实施后在本文"实施中的发现"里记录：问题中的文档标题词（24-12-HPE、CONTRATO N° 105-2025 等，每份文档只出现在 1 个 chunk 中，IDF 最高）是否把标题 chunk 推进多题的 Top-3；BM25 是否让短碎片 chunk 更常进入 Top-3。

**依赖**：`snowballstemmer`（Q1 选 A 或 B 都需要）。

## 3. 不改什么

- 分块、表格、编码器不变，chunk 与 V3.8 逐字相同，完整覆盖上限不变（plain_text 17/24、structured 21/24）。
- 检索范围（标识编码过滤）规则不变。
- 不做 bge-m3 稀疏检索、重排模型（Reranker）、查询改写。
- 不引入 Elasticsearch、OpenSearch 或其他向量库。
- 不调 RRF 的常数 60 和 BM25 的 k1、b：样本只有 24 题，调参容易过拟合。
