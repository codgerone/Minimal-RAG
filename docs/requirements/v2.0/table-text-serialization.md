# 结构表格文本化需求

本文完整定义[当前系统需求 T-01](../../requirements.md)的结构表格正文规则。表头来源由[表头判定需求](table-header-detection.md)给出，表格结构来源由[表格提取与选优需求](table-extraction-selection.md)给出。本版不调用 LLM，不依据文件名、公司名、产品名或业务关键词选择模板。

## 1. 输入、输出与不变量

输入为一张结构表格、表头判定结果及来源。输出为一份有序文本表示，后续结构化 chunker 可以按行拆分，但不能重新解释表格。

必须满足：

- 每个非空物理单元格的原文至少出现一次；不能改数、补单位或纠错。
- 合并格只作为一个物理格表达，不复制成多个独立字段值。
- 表头确定时使用字段路径；未确定时使用原始行列编号。
- 原始行列编号固定，不随分块重新编号。
- embedding 和检索后交给 LLM 使用同一份 chunk 正文。
- 表格 ID、candidate ID、工具、评分等审计信息进入 metadata 和审核视图，不写入 embedding 正文。

## 2. 文本语法

每项以中文全角分号 `；` 分隔，每行以中文句号 `。` 结束。字段或位置与值使用 ` = `。多级表头使用 ` / ` 连接。

原单元格内容统一使用 JSON 字符串转义并加双引号，例如：

```text
说明 = "尺寸为 \"大号\"\n第二行"
```

系统生成的空白和缺失标记不加引号：

```text
状态 = 〔空白〕
第3列 = 〔缺失单元格〕
状态 = "〔空白〕"
```

最后一行表示原文确实为 `〔空白〕`，不能与系统标记混淆。序列化器不得把系统标记写回原 cell。

## 3. 已确定表头的普通数据行

按原表数据行顺序输出；一行内按列顺序输出。格式为：

```text
第<原始行号>行：<表头路径> = <值>；<表头路径> = <值>。
```

例如：

```text
第3行：产品 = "A"；数量 / 国内 = "100"；数量 / 海外 = "200"。
```

规则：

- 展示行号和列号为一基编号。
- 每列路径按覆盖该列的表头物理格从上到下组成；同一跨行表头格在该路径中只出现一次。
- 路径中的空白层用该叶列的 `第N列` 补足；整列无有效表头时仅使用 `第N列`。
- 不同物理表头格即使同文，也不去重。
- 数据格只覆盖一列时使用该列路径；横跨多列时按第 5 节表达，不复制到多条字段路径。

## 4. 表头未确定

首先输出：

```text
表头未确定。
```

随后把每一原始行按位置表达：

```text
第1行：第1列 = "ELPU"；第2列 = "3"；第3列 = "Three Phase 3 wires"。
```

原第一行必须保留。单列格使用 `第N列`；合并格按第 5 节表达。不能使用工具的 column_header role 生成字段名。

## 5. 合并单元格

### 5.1 纵向合并

纵向合并格独立表达一次，再输出其余单元格：

```text
第3行至第5行共享第1列，字段 = 地区，内容 = "华东地区"。
第3行：数量 = "100"。
第4行：数量 = "200"。
第5行：数量 = "300"。
```

有可靠表头时使用 `字段 = <表头路径>`；无可靠表头时使用：

```text
第3行至第5行共享第1列，内容 = "华东地区"。
```

数字或货币值也只描述“共享覆盖范围”，不解释为合计。文本或日期不改写成每行独立拥有该值。

### 5.2 横向合并

```text
第8行：第1列至第4列为合并单元格，内容 = "Total CIF (CALLAO)"；Total Amount = "USD 968,000.00"。
```

横向合并格不强制映射到某个表头路径，不解释为分组标题或汇总。其他单列格仍按表头路径或列号表达。

### 5.3 同时跨行和跨列

```text
第3行至第5行、第1列至第2列为合并单元格，内容 = "适用范围"。
```

其覆盖位置不再输出空白或缺失项。

## 6. 空白、占位符与缺失

| 输入事实 | 输出 |
| --- | --- |
| 位置明确、独立物理格的 text 为 null 或去除首尾空白后为空 | 对应字段或位置 `= 〔空白〕` |
| 原文是 `0`、`-`、`N/A` 或任何其他非空内容 | 按原文加引号输出 |
| 逻辑位置由合并格覆盖 | 只在合并格范围中表达，不另输出 |
| 网格位置没有任何物理格覆盖 | 对应位置 `= 〔缺失单元格〕` |

只去除用于判断空白的首尾空白；输出原文不得因空白判断被重写。上游完全无法建立行列位置时，不伪造行列编号，输出可用原文及“结构无法定位”标记，具体承载字段由架构定义。

## 7. 前置全宽行和其他特殊行

表头判定时跳过的顶部全宽行仍按原位置输出：

```text
第1行：第1列至第5列为合并单元格，内容 = "采购明细"。
```

表格中部全宽或部分跨列行按相同规则表达。本版不认定它是表名、分组标题、备注或汇总，不把内容自动传播到后续行。

## 8. 与分块的连接

整表未超限时，上述文本完整进入一个表格 chunk。整表超限时：

- 按原数据行边界拆分，不重复数据行。
- 每个片段重复理解片段所需的表头路径；重复内容计入 token 预算。
- 纵向合并范围被拆开时，各片段重复共享格上下文，同时注明原始覆盖范围和本片段范围，不改写成行级独立值。
- 单行超限时按完整单元格拆；单格仍超限时递归拆其文字，保留原行列和片段次序。
- 表格数据内容不设置 overlap。
- 重复上下文放不下时，退回稳定的行列定位标识；正文必须在全部片段中完整覆盖。

序列化结果是分块前的完整事实；chunker 可以重复上下文和增加片段定位，不能改变字段映射或重新判定表头。

## 9. winner 审核视图

每 PDF 的 winner 审核 HTML 同时展示：结构表格及表头着色、本文定义的完整分块前文本、实际生成的全部表格 chunk。审核页面必须读取同一序列化结果和最终 chunk，不单独重算或使用另一套展示模板模拟 embedding 输入。

## 10. 验收

至少验证：单层和多层表头、空白表头层、表头未确定、三类合并方向、空白/缺失/原文系统同名标记、引号和换行转义、全宽行、超限拆分、重复上下文及单格超限。逐项核对原物理格内容是否完整覆盖、合并值是否被重复为独立事实、最终文本是否可确定性复现。
