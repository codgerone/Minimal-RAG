# 002 文档标识编码放在外置标识表，查询时按 document_id 过滤

日期：2026-10-06　状态：已采用（V3.2）

## 背景

问题中点名了文档，检索却在全库进行，跨文档污染严重。要按文档过滤，系统需要知道"哪个编码对应哪份文档"。编码由用户分配（如 ORDER2025001），PDF 内容中没有。

## 选项

| 选项 | 结论 |
|---|---|
| 从文件名提取编号 | 不采用：文件名与问题中的写法不一致，规则只能贴合现有文件名 |
| LLM 从文档列表中选文档 | 不采用：每次提问多一次 LLM 调用，结果不确定，评估依赖 LLM |
| 写入 PDF 文件内部的元数据 | 不采用：会改写原始业务文件（包括已签字文件） |
| 写入 manifest | 不采用：manifest 是入库自动生成的派生记录，每个装配一份，重建时整体重写 |
| 入库时复制到 chunk 元数据，按编码过滤 | 暂不采用：识别编码前必须先有编码清单，即标识表本身；只限定文档时，chunk 已有的 `document_id` 足够，复制会多一份需要与标识表保持一致的数据 |
| **外置标识表，查询时编码 → document_id → 过滤** | **采用** |

## 决定

1. 标识表 `documents/documents.toml` 与 PDF 放在一起，由用户维护，是编码的唯一来源。
2. 查询时识别问题中的编码，得到 `document_id` 集合，在向量库中按 `document_id` 过滤。标识表不进入构建指纹，修改后不需要重建。
3. 出现按文档属性（类型、客户、日期）过滤的需求时，再由入库把表中字段写入 chunk 元数据，同时让标识表进入构建指纹；标识表仍是数据源。主项目中，标识表由数据库取代。

## 结果

题目加注编码后，24 道题全部识别正确，两份内置装配的跨文档污染降为 0。
