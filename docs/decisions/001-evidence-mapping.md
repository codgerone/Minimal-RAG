# 001 证据映射按 chunk 正文标识，自动判定兜底

日期：2026-10-05　状态：已采用（V3.1）

## 背景

评估需要知道"哪些 chunk 算标准证据"。V3.0 的 test set 把人工审核的映射绑定到 chunk ID 和构建指纹，导致每改一次编码模型或分块参数，都要重新生成 test set 并等待人工审批，下一阶段调优检索时会非常低效。

V3.1 提案（Q1）原本计划改为完全自动判定。实施时用你已审核的两份映射做了校准：按"同文档、同页、文本重合度"自动判定，与人工映射的逐组一致率只有约 60%。分歧主要有两类：

- 人工映射包含语义判断，例如订单 25-19 的价格题，人工认可的 chunk 中并没有出现 excerpt 里的单价；
- `plain_text` 把表格打散成按列排列的文字，纯文本匹配找不回来。

因此完全自动判定不能替代人工映射。

## 决定

1. 已确认的映射保存在 `eval/mappings.json`，用"文档 ID / chunk 正文 SHA-256 前 16 位"标识 chunk。只要正文不变（换编码模型、换检索方式、调整 K 都属于这种情况），就直接沿用，不需要重新确认。
2. 分块变化导致正文改变时，对受影响的证据组自动判定，报告中标为"自动判定"，供抽查。
3. 抽查无误后，运行 `eval --confirm-auto` 把这些判定追加到映射文件。不同分块方式各自确认的组合会累积保存，互不冲突（组合中的 chunk 不在当前索引时会被自然跳过）。

## 结果

迁移后，两份内置装配的 43 个证据组全部使用已确认映射，评估指标与 V3.0 完全一致。
