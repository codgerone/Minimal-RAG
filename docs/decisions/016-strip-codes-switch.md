# 016 去编码作为独立开关（P3.2.0）

日期：2026-10-29　状态：已确定

## 背景

写法提示词 v7 要求改写、翻译、HyDE、step-back 都去掉文档过滤识别出的标识编码，而原句（原问题或子问题）保留编码。于是"原句 → 某种写法"的对照同时改变了两件事：写法本身（语言、句式、假想答案、上位问题）与编码是否出现在检索文本中。编码对检索另有作用（roadmap 第 4 节：编码中的年份数字吸引含同年份日期的 chunk；BM25 可按编码匹配写有该编码的块），两者混在一起无法归因。

## 结论

- 新增 P3.2.0 去编码，是作用于第 2 步全部检索文本（原句与启用的各写法）的开关，不是写法。只开 P3.2.0 即用去编码的原句代替原句检索。
- 写法不再自行去掉编码。写法提示词 v8 只删去 v7 中"这些编码……不要写进任何写法"一行及代码填入的编码，其余不变；对编码不作专门要求：子问题保留限定条件（含编码）是拆解的责任，写法只忠实改写输入，HyDE 是否出现编码由内容决定。
- 去编码在拆解、写法生成之后由代码完成：按文档过滤的规范化（NFKC、忽略大小写与非字母数字字符）在文字中定位编码并删去，合并多余空白。同一份生成得到开、关两个版本，两侧只差编码本身；若先去编码再交给 LLM，两次生成的措辞差异会混入对照。编码前后的说明词不删（判断需要语言知识，不通用）；写法中的编码与问题写法差别超出规范化而定位不到时保留，逐题记录。
- 原问题一路不受影响，仍用带编码的原问题原句（与"兜底不受写法影响"一致）。
- 编号取 P3.2.0 而不把现有编号顺延：P3.2.1–P3.2.4 已用于配置键、页面数据、决策 014/015 与提交记录。

## 影响

- 配置按数据流分三步（问题、每个问题的检索文本、跨问题合并），"融合方式"由勾选的检索文本条数决定；配置数 120 → 240。
- 写法按 v8 重新生成（第 0 次与 3 次独立生成），依赖写法的数据与决策 015 草稿按新数据重算；P3.1 的拆解不变（拆解提示词 v9，走缓存）。
- 可做的单因素对照：原句 → 去编码原句（编码的作用）；去编码原句 → 去编码的翻译 / 改写（语言、句式的作用）；写法开关去编码（写法中保留编码是否有益）。
