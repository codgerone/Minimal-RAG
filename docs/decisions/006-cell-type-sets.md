# 006 表头判定的类型词法：每格判出可能类型的集合

日期：2026-10-09　状态：已采用（V3.6），V3.7 补充

## 背景

表头判定依据"文字标题 → 下方稳定为数字或日期"的类型转变。V3.5 的词法每格只判一种类型，日期只收少数写法，且 `DD/MM/YYYY` 实现成了 `MM/DD/YYYY`。PO 25-19 交货日期表中，`28/02/2026` 被判为文字，其余日期第一段不超过 12，被判为日期，第一条数据行因此被认成表头。

常见写法本身有歧义：全数字日期的日月顺序无法从单个格子确定；八位数字、`YYYY.MM` 既可以是数字也可以是日期。

## 选项

| 选项 | 做法 | 问题 |
|---|---|---|
| 单一类型、固定优先顺序 | 每格按"日期优先于数字"取第一个匹配 | 新增日期写法会把数字列的部分格子改判为日期，原本稳定的数字列变得不稳定；词法越扩越容易出错 |
| 按文档语言推断日月顺序 | 西文文档按日月年，英文按月日年 | 需要可靠的文档语言；同一文档可能混用；仍解决不了数字与日期的重叠 |
| **可能类型的集合** | 每格列出所有合法读法的类型；两者都不成立才是文字；一列的观察有共同类型即稳定 | 判定只依赖"是不是数字/日期"，不确定具体是哪一天 |

## 结论

采用可能类型的集合。表头判定只需要类型，不需要日期的值；扩充格式只会让格子多一种可能类型，不会让已经稳定的列失去稳定。代价是歧义写法组成的列可能同时稳定为数字和日期，这不影响类型转变的判断。

## V3.7 补充：货币金额单独成类型，转变改为类型无交集

类型分为文字、货币金额、其他数字、日期四种。带货币标记的金额与不带货币的数字表达不同的东西，不再共用"数字"；一列的金额有的写货币、有的不写时，该列不稳定。

类型转变由"标题是文字、下方稳定"改为"标题不为空，且它可能的类型与下方的稳定类型没有交集"，日期 → 数字（分批交货表的日期表头）、数字 → 货币金额都算转变。为此千分位分组收紧为每组 3 位，三段两位数的日期不再同时被读成数字。

代价：表格下方不以合并格开头的汇总行（发票的 `Sub Total`、`IGV` 等，金额带货币）被取样时，不带货币的明细列会失去稳定。
