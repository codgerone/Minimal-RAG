# 005 表格文本：去掉中文脚手架，列名写在值前，合并单元格只表达结构

日期：2026-10-09　状态：已采用（V3.5）

## 背景

V3.4 的表格文本（`numbered_fields_v1`，原名 `row_text_v1`）写成 `第N行：字段 = "值"；…`，没认出表头时字段写 `第M列`，合并单元格用中文句子单独说明。表格 chunk 的大部分 token 是脚手架，一个 chunk 只装得下少数几行；问题全部是中文，文档是西班牙语或英语。

## 发现

在内存中只改写表格 chunk 的正文后重新编码，比较单篇文档内的排序：

| 变体 | 非表格题 Top-3 中表格 chunk 的个数 / 总数 |
|---|---:|
| `numbered_fields_v1` 原样 | 25/36 |
| `numbered_fields_v1`，脚手架换成英文 | 5/36 |
| Markdown 竖线行，表头写一次 | 2/36 |
| Markdown 竖线行，块首加一句无关中文 | 24/36 |

1. 只要正文含中文，表格 chunk 就对中文问题普遍靠前，与内容是否相关无关。V3.4 基线中表格题的高排名有一部分来自这一偏向，它同时把正文证据挤出了 Top-3。
2. 去掉中文后，列名写在值旁边比只写一次更利于表格题匹配。

## 选项

| 选项 | 做法 | 正式评估（K=3，过滤开启） |
|---|---|---|
| `numbered_fields_v1` | 中文行列编号 + 逐格字段名 | 命中 12/24，完整覆盖 9/24（含偏向） |
| `markdown_rows_v1` | 竖线行，表头写一次 | 命中 16/24，完整覆盖 7/24；表格文本 4,559 token |
| `labeled_rows_v1` | 竖线行，单列格写 `列名: 值`，无表头行 | 命中 17/24，完整覆盖 7/24；表格文本 7,199 token |

## 决定

1. **表格文本不出现中文脚手架**；删除 `numbered_fields_v1`。
2. **`structured` 使用 `labeled_rows_v1`**，`markdown_rows_v1` 保留为可选实现。两者共用代码，只差"列名写一次"与"列名写在值前"，便于对比。
3. **合并单元格不判定含义**（相同值、合计、分节标题无法用确定性规则区分），只表达结构：值写在左上角，被覆盖的位置写 `←`、`↑`。chunk 从纵向合并中间开始时写 `↑ 原值`，补出的值登记为重复上下文。横跨多列的格不写列名，因为没有哪个列名属于它。
4. 箭头的含义写在回答用的系统提示词里，不写进表格文本，避免参与检索编码。

## 代价

- 完整覆盖从 9/24 降到 7/24：去掉偏向后，部分表格题的证据排名回到内容本身的匹配水平。剩余的表格题失败主要出在表头未认出的表格（没有列名可写）和跨语言匹配。
- 横跨整行的分节行不会带进后续 chunk。
