# Minimal RAG V1.1 技术与架构方案：索引健康引导恢复

## 1. 文档定位

| 项目 | 内容 |
| --- | --- |
| 对应 PRD | `docs/prd/v1.1-index-health-guided-recovery.md` |
| 基线架构 | `docs/architecture/v1.0-minimal-rag-architecture.md` |
| 目标读者 | 负责实现、测试和验收的 Codex / coding agent |
| 状态 | 待实现 |

本文件规定 V1.1 的实现边界、模块契约、状态流与测试要求。实现不得扩大到 OCR、后台任务、Web UI、自动改写结构性配置或无人值守自动修复。

## 2. 架构决策

1. `validate_index()` 仍是 Manifest/Chroma 一致性的唯一核心检查函数；它不做用户交互、不解析 PDF、不写索引。
2. 新增 CLI 预检层，负责将 `validate_index()` 的结果与 `new` / `changed` PDF 的只读解析预检合成为用户可见的索引检查结果。
3. 交互、确认、修复编排属于 CLI 应用层；`Indexer` 仍是唯一索引写入编排器，`Retriever` 仍拒绝不健康索引的检索。
4. 交互式恢复仅在 stdin 和 stdout 都是 TTY 时启用。非交互环境绝不等待输入、绝不写入配置、绝不自动执行修复。
5. API Key 是唯一允许通过交互写入 `.env` 的配置项；写入必须原子化、最小化且不得泄露秘密。
6. `ingest` 是修复命令本身，不使用“修复后重试原命令”协调器。

## 3. 目标模块结构

```text
rag/
├─ cli.py                 # argparse、命令分派、终端输出；调用下面的应用服务
├─ cli_readiness.py       # 新增：CLI 预检、交互、恢复协调、命令续跑结果
├─ config.py              # Settings、读取 .env、原子更新单个 .env 键
├─ models.py              # 新增 DocumentState、检查与恢复相关 dataclass/Enum
├─ manifest.py            # 核心 validate_index() 与阻断性提前返回
├─ indexer.py             # 既有增量、prune、force 重建；不承载交互
├─ retriever.py           # 严格检索；不承载交互
├─ vector_store.py        # 区分 Collection 不存在与数据库不可读
└─ ...

tests/
├─ test_manifest.py
├─ test_cli_readiness.py  # 新增：预检、交互决策、命令续跑
├─ test_config.py
├─ test_cli_runtime.py
└─ ...
```

`cli_readiness.py` 是必要的新模块：它防止 `cli.py` 同时承担诊断、秘密输入、索引恢复、TTY 判断和命令续跑，且可在不启动真实终端、Chroma 或 LLM 的条件下测试。

## 4. 数据模型变更

### 4.1 `DocumentState`

在 `rag/models.py` 新增：

```python
class DocumentState(str, Enum):
    NEW = "new"
    CURRENT = "current"
    CHANGED = "changed"
    MISSING = "missing"
    INVALID = "invalid"
    UNPROCESSABLE = "unprocessable"
    UNASSESSED = "unassessed"
```

- `UNPROCESSABLE`：源 PDF 对 `parse_pdf()` 预检失败；是人工处理状态。
- `UNASSESSED`：全局阻断使逐文档一致性检查未执行；不是“未知成功”，必须令索引不可用。

### 4.2 CLI 预检结果

新增只读应用层模型，建议命名如下：

```python
@dataclass(frozen=True)
class IndexInspection:
    sources: tuple[SourceDocument, ...]
    manifest: Manifest | None
    health: IndexHealth


class ReadinessResult(str, Enum):
    READY = "ready"
    STOPPED = "stopped"
    FAILED = "failed"
```

`IndexInspection` 不复制 `IndexHealth` 字段；它补充 CLI 后续需要的 `sources` 和 `manifest`。`ReadinessResult` 只表示恢复协调的终态，不替代 CLI 退出码。

### 4.3 展示映射

不要把“可用 / 不可用 / 需人工处理”写入 `DocumentState`。在 `cli_readiness.py` 提供纯函数：

```python
def display_status(status: DocumentStatus) -> tuple[str, str]: ...
```

返回 `(用户状态, 用户说明)`：

| DocumentState | 用户状态 | 说明 |
| --- | --- | --- |
| `CURRENT` | 可用 | `-` |
| `NEW` | 不可用 | 新文档，尚未建立索引。 |
| `CHANGED` | 不可用 | 文档内容已变化，原索引已失效。 |
| `INVALID` | 不可用 | 索引数据与文档记录不一致，需要重新建立索引。 |
| `MISSING` | 不可用 | 未在 `documents/` 找到源文件，原索引不可继续使用。 |
| `UNPROCESSABLE` | 需人工处理 | 使用 `detail`，或默认 OCR/文字层说明。 |
| `UNASSESSED` | 不可用 | 使用导致提前返回的全局问题说明。 |

## 5. 核心健康检查

### 5.1 `validate_index()` 的提前返回

修改 `rag/manifest.py::validate_index()`。

#### Manifest 不存在

保留现有提前返回：发现的源文档均为 `NEW`。如果 Collection 中仍有记录，添加 `orphan_collection`。返回 `IndexHealth(usable=False, ...)`。

#### 全局配置不一致

`global_config_matches(manifest, settings)` 为 `False` 时：

1. 添加 `global_config_mismatch`；
2. 为当前目录发现的每个源文档创建 `UNASSESSED` 状态；
3. 为 Manifest 中但目录未发现的每个文档也创建 `UNASSESSED` 状态；
4. 不再执行 Collection 存在性、单文档 chunk、metadata、总数或 unknown-document 检查；
5. 直接返回 `usable=False`。

`UNASSESSED.detail` 必须包含“当前 Embedding 模型、Collection 或分块配置与已有索引不一致，需要全量重建”的用户说明。

#### Collection 缺失

Collection 明确不存在时：

1. 添加 `collection_missing`；
2. 以同样的“当前目录源文档 + Manifest 独有文档”并集构造 `UNASSESSED`；
3. 不执行 per-document `count_document()` 或 `get_metadatas()`；
4. 直接返回 `usable=False`。

注意：必须先解决 `ChromaVectorStore.collection_exists()` 吞掉“数据库不可读”异常的问题。只有“数据库可打开且目标 Collection 明确不存在”才可产生 `collection_missing`；权限、I/O、损坏等错误必须抛出 `VectorStoreError`。

### 5.2 CLI PDF 预检

在 `cli_readiness.py` 实现：

```python
def inspect_index_for_cli(settings: Settings, store: ChromaVectorStore) -> IndexInspection:
    ...
```

步骤：

1. `discover_documents(settings.documents_dir)`；
2. `load_manifest(settings.manifest_path)`；
3. 调用 `validate_index()`；
4. 仅对结果为 `NEW` 或 `CHANGED` 的源文档调用 `parse_pdf()`；
5. 捕获 `PdfParseError` 后，以 `replace()` 将该 `DocumentStatus` 改为 `UNPROCESSABLE`，写入 `detail`；
6. 对每个 `UNPROCESSABLE` 增加 `IndexIssue(code=f"unprocessable:{id}", remediation=人工处理说明)`；
7. 有任一 `UNPROCESSABLE` 时，返回的 `IndexHealth.usable` 必须为 `False`；
8. 其他状态、issue 的稳定排序必须保留。

该函数不生成 embedding、不修改 Chroma、不保存 Manifest。

## 6. CLI 恢复协调器

### 6.1 依赖接口

为了可测试性，`cli_readiness.py` 不应直接绑定 `input()`、`print()`、`getpass()`。定义最小 Protocol：

```python
class Terminal(Protocol):
    def is_interactive(self) -> bool: ...
    def write(self, text: str = "") -> None: ...
    def confirm(self, prompt: str, *, default: bool) -> bool: ...
    def read_secret(self, prompt: str) -> str | None: ...
    def choose(self, prompt: str, choices: set[str], default: str) -> str: ...
```

生产实现包裹 `sys.stdin.isatty()`、`sys.stdout.isatty()`、`input()` 和 `getpass.getpass()`；测试使用 FakeTerminal。所有输入解析大小写不敏感，EOF 与 `KeyboardInterrupt` 均按取消处理。

### 6.2 恢复协调函数

建议入口：

```python
def ensure_index_ready(
    settings: Settings,
    store: ChromaVectorStore,
    terminal: Terminal,
) -> tuple[ReadinessResult, Settings, IndexInspection]: ...
```

返回的 `Settings` 允许携带本次运行临时录入的 API Key，但索引恢复本身不要求 Key。函数循环的上限由“每次写操作后重新检查”决定；禁止自动无限重试。

处理顺序严格如下：

1. `orphan_collection`、`global_config_mismatch`、`unknown_documents` → 询问全量 force；
2. `collection_missing` → 询问普通增量 ingest；
3. `NEW`、`CHANGED`、`INVALID` → 询问普通增量 ingest；
4. `MISSING` → 询问 prune；
5. `UNPROCESSABLE` → 输出人工处理说明并返回 `STOPPED`；
6. `collection_count_mismatch` → 询问全量 force；
7. 每个实际修复后都重新执行 `inspect_index_for_cli()`；仅 `health.usable=True` 时返回 `READY`。

全量、增量和 prune 必须直接调用 `Indexer`，不得启动另一个 Python/uv 子进程。

### 6.3 命令续跑

`cli.py::main()` 应先完成参数解析和不需要 API Key 的 `load_settings(require_api_key=False)`，再按命令类型调用协调器：

| 命令 | 预检通过后的执行 |
| --- | --- |
| `documents` | 输出状态表；在交互模式下可先执行恢复，再重新输出。 |
| `chunks` | 确保索引就绪，再读取指定文档 chunks。 |
| `search` | 使用原始 question、top-k、document 参数检索。 |
| `ask` | 确保索引就绪与 LLM 凭据后，用原始 question、debug 参数回答。 |
| `chat` | 确保索引就绪与 LLM 凭据后进入循环。 |
| `eval` | 确保索引就绪后执行；`--live` 额外要求 LLM 凭据。 |
| `ingest` | 直接执行既有索引逻辑，不调用协调器。 |

用户取消、修复失败或需要人工处理时：`search`、`ask`、`chat`、`eval`、`chunks` 必须以非零退出；`documents` 输出当前状态后可返回 0。

`Retriever.search()` 不改为交互模式；它继续基于核心 `validate_index()` 拒绝不健康索引。CLI 负责在调用 Retriever 前完成恢复。

## 7. API Key 与 `.env` 安全处理

### 7.1 获取与临时使用

新增：

```python
def ensure_llm_credentials(
    settings: Settings,
    terminal: Terminal,
) -> tuple[ReadinessResult, Settings]: ...
```

仅供 `ask`、`chat`、`eval --live` 使用。若 `settings.openrouter_api_key` 已有非空值，直接返回 `READY`。

缺失时使用 `Terminal.read_secret()`，空值、EOF 和中断都返回 `STOPPED`。随后让用户选择：

- `1`：仅本次运行使用；
- `2`：保存到 `.env`；
- `0`：取消。

对选项 `1` 或 `2`，使用 `dataclasses.replace(settings, openrouter_api_key=key)` 构造本次运行 Settings。不得修改 `os.environ`，也不得假设 `python-dotenv` 的 `override=False` 会覆盖已有环境变量。

### 7.2 `.env` 单键原子更新

在 `config.py` 新增：

```python
def update_env_key(path: Path, key: str, value: str) -> None: ...
```

约束：

1. 只允许 `key == "OPENROUTER_API_KEY"`；其他 key 直接抛出 `ConfigurationError`；
2. 读取现有 UTF-8 文件；文件不存在则视为空；
3. 替换第一个有效 `OPENROUTER_API_KEY=...` 行；若不存在则在末尾追加；
4. 保留其他行、注释和换行风格；不打印文件内容或 value；
5. 在同目录写临时文件并用 `Path.replace()` 原子替换；
6. 写入失败必须报 `ConfigurationError`，且本次临时 Key 仍可由用户选择仅本次使用；不得泄露 value。

### 7.3 认证与服务失败

`OpenRouterClient` 或上层必须将认证/授权错误与限流、超时、网络、服务端错误区分为可显示的 `LlmServiceError` 分类。

- 认证失败：询问是否重新录入 Key；确认后重新走 `ensure_llm_credentials()`。
- 临时服务失败：询问是否重试；每次重试都需确认。
- `ask`：重试同一个请求；拒绝或失败后结束。
- `chat`：重试当前轮；拒绝或失败后回到下一轮输入提示。
- `eval --live`：重试时从头运行整个 eval；不得混合两次运行结果。
- 不自动换模型、Provider、Key 或重试次数。

## 8. 非索引阻断实现

| 类别 | 检测位置 | 交互行为 | 禁止行为 |
| --- | --- | --- | --- |
| `documents/` 不存在 | CLI 加载 Settings 后 | 询问是否创建已验证的项目内目录；创建后提示放入 PDF 并停止。 | 不创建项目外路径，不自动索引。 |
| `documents/` 无 PDF | CLI 预检 | 提示放入带文字层的 PDF 并停止。 | 不显示伪修复确认。 |
| 结构性 `.env` 配置无效 | `load_settings()` | 输出错误、约束、`.env` 路径与命令帮助。 | 不交互改 chunk/model/path/collection 配置。 |
| 命令参数无效 | argparse/CLI 参数校验 | 输出具体错误和子命令 help。 | 不追问并改写原命令参数。 |
| Embedding 加载失败 | 创建 Embedder 或索引构建 | 显示模型名并询问是否重试。 | 不自动循环、换模型或改配置。 |
| Manifest 不可解析 | `load_manifest()` | 若有可读 PDF，提供 force 确认。 | 无 PDF 时不得清空 Collection。 |
| Chroma 不可读 | vector store | 显示数据路径和友好错误。 | 不当作 `collection_missing`，不自动重建。 |
| 指定 chunks 为空 | `chunks` | 说明文档未索引并引导 `documents`/ingest。 | 返回无内容的成功结果。 |

“无搜索结果”“基于上下文拒答”“eval FAIL”是正常业务结果，不应进入恢复协调器。

## 9. 终端输出与退出码

### 9.1 `documents` 表格

使用纯标准库输出，避免引入新的表格依赖。默认列为：

```text
文档名称 | 索引状态 | 索引状态说明 | 页数 | Chunks | 索引时间
```

不要显示 Hash。路径中的竖线需安全替换或转义，避免破坏表格。字段未知时输出 `-`。

### 9.2 退出码

- 成功完成原始命令：0；
- `documents` 展示问题但用户未执行/拒绝修复：0；
- 其他命令因索引未就绪、用户取消或人工处理而未开始实际任务：使用 `IndexNotReadyError` 的非零码；
- 参数、配置、目录、向量库、Embedding、LLM 错误：保留对应 `RagError` 子类的非零码；
- 原始命令在恢复完成后自行失败：保留原始失败码。

## 10. 实现顺序

1. 更新 `DocumentState`、测试 fixtures 和展示映射。
2. 改造 `ChromaVectorStore` 的 Collection 不存在/不可读语义。
3. 实现 `validate_index()` 的阻断性提前返回与 `UNASSESSED` 状态。
4. 实现 `inspect_index_for_cli()`，将 PDF 解析失败转换为 `UNPROCESSABLE`。
5. 实现 FakeTerminal、生产 Terminal、确认与秘密输入。
6. 实现 `cli_readiness.py` 的恢复决策，并复用现有 `Indexer`。
7. 实现 `config.update_env_key()` 和 API Key 临时/持久凭据流程。
8. 改造 `cli.py` 分派顺序，使命令在恢复成功后续跑原始参数。
9. 完善 LLM/Embedding 错误分类与显式重试。
10. 更新 README、顶层与子命令帮助、PRD/架构引用；运行全量测试。

每步都必须先补充或更新相应测试；不得在没有测试覆盖的情况下批量重写 CLI。

## 11. 测试矩阵

### 11.1 健康检查

- 全局 chunking/embedding/collection 配置变化产生 `UNASSESSED`，且不调用 per-document Chroma 查询；
- Collection 明确缺失产生 `UNASSESSED`；Chroma 不可读抛出错误而非 `collection_missing`；
- Manifest 缺失保留 `NEW` 与 orphan 检查；
- `NEW`/`CHANGED` PDF 解析失败在 CLI 预检中为 `UNPROCESSABLE`，并令 `usable=False`；
- `CURRENT`、`INVALID`、`MISSING` 既有规则不回归。

### 11.2 交互与恢复

- 非 TTY 不调用 prompt、getpass、Indexer 写操作；
- force、普通 ingest、prune 的确认默认值与拒绝行为正确；
- 任一修复后都重新检查；恢复成功后原始 question、top-k、document、debug、live 参数不丢失；
- `UNPROCESSABLE` 不调用 Indexer；
- `documents` 修复后重新输出表格。

### 11.3 密钥与服务

- Key 隐藏输入不会写入 stdout/stderr、日志或异常；
- 仅本次使用不会写 `.env`；保存模式只更新 `OPENROUTER_API_KEY` 且保留其他内容；
- API 认证失败可重新录入 Key；
- LLM/Embedding 重试只能在用户确认后发生；
- chat 的单轮 LLM 失败不终止会话；live eval 重试从头运行。

### 11.4 回归

- `Retriever.search()` 在核心健康检查失败时仍拒绝检索；
- `ingest` 的增量、`--file`、`--prune`、`--force` 既有语义不被交互协调器改变；
- 默认 pytest 不依赖真实 API Key、网络、Chroma 之外的临时测试存储；
- README 中每条命令均可实际运行或以测试覆盖。

## 12. 禁止事项

- 不把修复逻辑放进 `Retriever`、`Indexer`、`Manifest` 或 `VectorStore` 的底层模块；
- 不通过子进程递归调用 `uv run python -m rag`；
- 不自动删除 missing 文档的索引；
- 不自动保存、回显、打印或记录 API Key；
- 不将不可读 Chroma 误报为 Collection 缺失；
- 不在配置不一致时混入新旧 chunk；
- 不在索引未就绪时继续 search、ask、chat 或 eval。
