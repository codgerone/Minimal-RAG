# 多轮检索

## 规则摘要

- 查询有两路，由查询设置 `[query] mode` 选择：`retrieval` 用原问题检索一次（内置默认）；`multi_round` 为多轮检索（[决策 018](../decisions/018-multi-round-retrieval.md)）。
- 多轮检索的第 1 轮用去编码的原问题检索一次，不调用 LLM。之后每次调用 LLM，读入问题列表与材料，判断哪些问题可回答、接受哪些单元为证据，为不可回答的问题选下一步：等子问题、再检索、派生子问题、撤回或停止。代码维护问题列表与状态，执行检索，LLM 只给判断与文本。
- 一个问题最多检索两次：第 1 次检索，以及一次兜底（往下取、改写、HyDE、step-back 同时检索，Q0 另加补上翻译）。
- Q0 判为可回答时同一次调用给出答案，结束；没有待检索的问题，或调用次数到上限 − 1 时，下一次调用只作答，结束。调用上限 `[multi_round] max_llm_calls` 含作答调用，默认 3。
- 每次调用独立，不带对话历史；跨调用要保留的信息都在问题列表中，由代码每次重新写入输入。

## 问题与状态

问题 `Q0` 为原问题，派生问题按产生顺序编号 `Q1`、`Q2`……，记下直接派生出它的问题。代码记录每个问题的每次检索（各方式的检索文本、交给 LLM 的单元及名次）、已接受的证据（只增不减）；LLM 写问题文本、译文、证据说明（note）、缺口类别。

| 状态 | 含义 |
|---|---|
| `pending` | 待检索：下一轮检索它 |
| `judging` | 已检索，等待下一次调用判断 |
| `waiting` | 不检索；每次调用仍判断它 |
| `answered` | 已回答 |
| `abandoned` | 放弃：上级已回答（`parent_answered`）、上级被撤回（`parent_withdrawn`）、被撤回（`withdrawn`）、检索用尽（`exhausted`） |

每次调用判断全部未结束的问题（`judging`、`waiting`）。

**转移**：
- 新问题为 `pending`，检索后为 `judging`。
- 判为可回答 → `answered`；它下面未结束的问题 → `abandoned`（`parent_answered`）。
- 不可回答时的动作：
  - `wait` → `waiting`：只用于有未结束子问题的问题；
  - `retry` → `pending`：要查的仍是这个问题本身，只是没检索到；只用于还有检索方式可用的问题；
  - `derive` → `waiting`，新问题为 `pending`：还需要的已是另一个问题；
  - `withdraw` → `abandoned`（`withdrawn`）：问题本身规划错了或与另一问题重复；须写理由；Q0 不可撤回；它下面未结束的问题 → `abandoned`（`parent_withdrawn`）；
  - `stop` → `abandoned`（`exhausted`）：不能再检索、没有未结束的子问题、也不再派生。
- LLM 还可在 `withdrawals` 中撤回状态为 `pending` 的问题。
- 有未结束子问题的问题可以 `retry`，父问题与子问题同时检索。

**缺口类别**（不可回答时给出）：`not_found` 没找到答案；`needs_basis` 答案要由材料计算或推理得出，依据尚未找到；`needs_lead` 下一步检索要依据已找到的线索；`partial` 只找到一部分。

## 检索方式

一个问题第 i 次检索的方式由 i 决定：

| 检索 | Q0 | 派生问题 |
|---|---|---|
| 第 1 次 | 去编码原句 | 原句 + 各文档语言的译文，RRF 融合 |
| 第 2 次（兜底） | 往下取、改写、HyDE、step-back、补上翻译 | 往下取、改写、HyDE、step-back |

| 兜底方式 | 检索文本 |
|---|---|
| 往下取 | 无：在该问题第 1 次检索的排名中，从已取到的位置接着往下取 |
| 改写 | 用材料中的说法重述整个问题，补上材料显示需要的限定条件；问题语言一段，加上与问题语言不同的每种文档语言各一段 |
| HyDE | 每种文档语言一段，按材料的格式写答案可能出现的样子，未知的值用方括号占位 |
| step-back | 去掉把问题限定到单个实例的条件，用于各实例的答案写在同一处的情形；语言同改写 |
| 补上翻译 | 与问题语言不同的每种文档语言各一段译文 |

- 兜底文本由 LLM 在选 `retry` 的同一次调用中写出；需要写哪些由代码列出（`retry_texts`）。
- 每段文本先去掉 Q0 识别出的标识编码，再各自检索一次；一种方式有多段文本时，各段排名用 RRF 融合，作为该方式的排名。不同方式之间不融合。
- 每种方式返回 K 个单元（`[multi_round] units_per_attempt`，默认 3）：沿排名往下，跳过本轮之前已交给 LLM 的单元，直到取满 K 个或排名用完。同一轮内各方式互不跳过；同一单元在一次调用的材料中只出现一次，标出返回它的全部问题、方式与名次。
- 检索范围由 Q0 判定一次，所有问题沿用。
- 兜底的分组可配置（`[multi_round] fallback_schedule`：每组为一次检索），内置为一组。

## 调用的输入与输出

**规划调用的输入**：
1. 检索范围：检索的文档，以及选中它们的标识编码（编码是用户给文档的标签，不出现在文档中）；
2. 问题列表：每个问题的编号、上级、文本、状态、note、检索次数、已用过的方式，能否再检索（`retrieval_method_left`）、再检索需写的文本（`retry_texts`）、未结束子问题数（`open_sub_questions`）；
3. 已接受的证据：全部问题已接受的单元，各一次，标出编号、文档、页码、属于哪些问题；
4. 本轮新材料：本轮返回、此前未交给 LLM 的单元，各一次，标出编号、文档、页码、由哪些问题的哪种方式返回；
5. 需判断的问题清单。

交给过 LLM 但未被接受的单元不再出现。单元由代码维护的单元表按编号换成文本；返回整表时一张整表为一个单元。

**规划调用的输出**：每个需判断的问题一条判断（新接受的单元、note、是否可回答、缺口类别、动作、撤回理由、兜底文本），新问题（上级、文本、译文），撤回的待检索问题，Q0 可回答时的答案。新问题与 note 用 Q0 的语言写。答案只依据材料，事实按材料原样陈述，不换算、取整或补全，标出来源。

**作答调用**：输入为检索范围、问题列表与全部已接受的证据，输出答案，写明未找到的部分。

**校验**：引用的问题须存在；接受的单元须已交给过 LLM；每个需判断的问题恰好一条判断；不可回答时须有动作；动作须满足上节的适用条件；`retry` 须写出所列的兜底文本；新问题的上级须在本次输出中选 `derive`，每种文档语言至多一段译文；撤回须写理由；Q0 可回答时须有答案，不可回答时不写答案。不合格时带着问题清单重试一次；仍不合格则本次调用降级：通过校验的判断照常执行，其余问题保持原状态。

每次调用按（提示词版本、模型、输入、生成编号）缓存在 `.rag/llm-cache/`。服务端的临时失败（限流、超时、上游失败）等待后重试，最多 3 次。

## 运行记录

一次运行记下：每轮检索的次数与耗时；每次调用的输入、输出（含推理）token，耗时，花费，是否重试、降级，调用后的问题列表；单元表；终止原因（Q0 已回答 / 没有待检索的问题 / 达到调用上限）；答案。

规划提示词不告诉 LLM 还剩几次调用，所以上限为 L 的运行与上限更高的运行在第 L 次规划调用之前完全相同：评估时按最高上限运行一次，较低上限从同一次运行截取（[evaluation.md](evaluation.md)"多轮检索的评估"）。
