# 表格文本化

> **规则摘要**
> - 两种实现，由装配的 `table_formatter` 选择：`row_text_v1`（逐格写字段名）、`markdown_rows_v1`（Markdown 竖线行，表头只写一次）。
> - 两者都保留每个单元格的内容，并为每行记录它来自哪些表格行和单元格。

## row_text_v1

> - 一张表格变成多行文本，每行对应表格的一行，写成 `第N行：字段 = "值"；字段 = "值"。`
> - 认出表头时，字段名是多级表头路径（如 `数量 / 国内`）；没认出时，字段名写成 `第M列`，并在开头加一行 `表头未确定。`
> - 合并单元格只写一次，用一行单独说明它覆盖的范围。
> - 空格写作 `〔空白〕`，缺失的格写作 `〔缺失单元格〕`，无法定位到网格的文字写在最后。
> - 每个单元格的原文都保留，不改写、不丢失。

代码：`rag/ingest/tables/formatter.py`。

### 示例

```
表头未确定。
第1行至第2行共享第1列，内容 = "MODEL"。
第1行：第2列 = "1st Delivery"；第3列 = "2nd\nDelivery"。
第3行：第1列 = "HXE12ESX"；第2列 = 〔空白〕；第3列 = "-"。
```

### 规则

- 值用 JSON 字符串转义输出，单元格内的换行写作 `\n`。
- 表头行本身不单独输出，它的内容体现在各行的字段名里。
- 合并单元格的说明有三种写法：
  - 纵向合并：`第a行至第b行共享第c列，字段 = …，内容 = …`
  - 横向合并：`第a行：第c列至第d列为合并单元格，内容 = …`
  - 两个方向都合并：`第a行至第b行、第c列至第d列为合并单元格，内容 = …`
- 这段文本会作为表格 chunk 的正文，同时用于检索编码和提供给 LLM。超长表格如何切分，见 [chunking.md](chunking.md)。

## markdown_rows_v1

> - 一行表格写成一行 `| 值 | 值 | … |`，不写行号、字段名、引号。
> - 认出表头时，表头行写在原位置，每列写多级表头路径（各级用 ` / ` 连接），没有路径的列写空；没认出表头时没有表头行，各行原样输出。
> - 合并单元格不判定含义，只表达结构：值写在左上角，同一行被覆盖的位置写 `←`，下面各行被覆盖的位置写 `↑`。
> - 单元格和列名内的换行、连续空白合并成一个空格，这是唯一的改写。

代码：`rag/ingest/tables/markdown_rows.py`。

### 示例

```
| MODEL | 1st Delivery | 2nd Delivery |
| ↑ | 25.09.25 | 10.10.25 |
| HXE12ESX |  | - |
```

### 规则

- 空格写空，缺失的格写 `〔缺失单元格〕`，单元格内的 `|` 写作 `\|`。
- 无法定位到网格的文字原样写在最后一行。
- 每行记录各单元格内容在行内的位置；某行开启新的 chunk 且有纵向合并单元格从上方的数据行延续下来时，分块器按这一行记录的续接写法改写它（见 [chunking.md](chunking.md)）。
- 回答用的系统提示词说明 `←`、`↑` 和 `↑ 值` 的含义；表格文本本身不加图例。

## 已知限制

- `row_text_v1`：中文的"第N行/第M列"脚手架和重复出现的字段名占据大部分 token，稀释 embedding 对内容的表达，也让一个 chunk 只装得下少数几行。
- `markdown_rows_v1`：原文中本来就有的 `←`、`↑` 字符会与合并标记混淆；横跨整行的合并行只覆盖一行，不带进后续的 chunk。
