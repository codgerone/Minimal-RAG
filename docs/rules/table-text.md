# 表格文本化

> **规则摘要**
> - 两种实现，由装配的 `table_formatter` 选择；`structured` 使用 `labeled_rows_v1`。
> - `markdown_rows_v1`：一行表格写成一行 `| 值 | 值 | … |`，认出的表头写成单独一行。
> - `labeled_rows_v1`：与 `markdown_rows_v1` 只差两处——没有单独的表头行；只占一列的格，其值写作 `列名: 值`。
> - 合并单元格不判定含义，只表达结构：值写在左上角，同一行被覆盖的位置写 `←`，下面各行被覆盖的位置写 `↑`。
> - 文本中不出现行号、列号等中文脚手架。单元格和列名内的换行、连续空白合并成一个空格，这是唯一的改写。

代码：`rag/ingest/tables/markdown_rows.py`。决策背景：[005](../decisions/005-table-text-format.md)。

## 示例

`markdown_rows_v1`（表头未认出，第 1 列的 MODEL 纵向跨两行）：

```
| MODEL | 1st Delivery | 2nd Delivery |
| ↑ | 25.09.25 | 10.10.25 |
| HXE12ESX |  | - |
```

`labeled_rows_v1`（表头已认出，`Total CIF (CALLAO)` 横跨前两列）：

```
| Item: 1 | Goods of Description: Single Phase Meter 2 wires | Qty: 80,000 |
| Total CIF (CALLAO) | ← | Qty: 90,000 |
```

## 共同规则

- 每行的格数等于表格列数。空格写空；缺失的格（物理上不存在）写 `〔缺失单元格〕`；单元格内的 `|` 写作 `\|`。
- 认出表头时，表头所在的行不作为数据行输出；表头之上被跳过的行照常输出。没认出表头时，所有行原样输出。
- 无法定位到网格的文字原样写在最后一行。
- 每行记录它来自哪一行表格、各单元格内容在行内的位置；评估按这些位置推出 chunk 的来源区域。
- 某行开启新的 chunk、且有纵向合并单元格从上方的数据行延续下来时，分块器把这一格写成 `↑ 原值`（见 [chunking.md](chunking.md)）。
- 回答用的系统提示词说明 `←`、`↑` 和 `↑ 值` 的含义；表格文本本身不加图例。

## markdown_rows_v1

- 认出表头时，表头行写在原位置，每列写多级表头路径（各级用 ` / ` 连接），没有路径的列写空。

## labeled_rows_v1

- 只占一列、且值非空的格写作 `列名: 值`，列名是该列的多级表头路径（各级用 ` / ` 连接）；续接时写作 `列名: ↑ 值`。
- 横跨多列的格、空格、`←`、`↑`、缺失格不写列名；该列没有表头路径时也不写。
- 没认出表头时，输出与 `markdown_rows_v1` 相同。
- 行内的列名记为该行的来源，所以表头单元格计入含有它的每个 chunk 的区域。

## 已知限制

- 原文中本来就有的 `←`、`↑` 字符会与合并标记混淆。
- 横跨整行的合并行（如分节标题）只覆盖一行，不带进后续的 chunk。
- 表头未认出的表格没有列名可写，两种实现的输出相同；问题与这类表格的匹配只能依靠单元格内容。
