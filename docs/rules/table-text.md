# 表格文本化（row_text_v1）

> **规则摘要**
> - 一张表格变成多行文本，每行对应表格的一行，写成 `第N行：字段 = "值"；字段 = "值"。`
> - 认出表头时，字段名是多级表头路径（如 `数量 / 国内`）；没认出时，字段名写成 `第M列`，并在开头加一行 `表头未确定。`
> - 合并单元格只写一次，用一行单独说明它覆盖的范围。
> - 空格写作 `〔空白〕`，缺失的格写作 `〔缺失单元格〕`，无法定位到网格的文字写在最后。
> - 每个单元格的原文都保留，不改写、不丢失。

代码：`rag/ingest/tables/formatter.py`（被 `TableFormatter` 接口的 `row_text_v1` 实现调用）。

## 示例

```
表头未确定。
第1行至第2行共享第1列，内容 = "MODEL"。
第1行：第2列 = "1st Delivery"；第3列 = "2nd\nDelivery"。
第3行：第1列 = "HXE12ESX"；第2列 = 〔空白〕；第3列 = "-"。
```

## 规则

- 值用 JSON 字符串转义输出，单元格内的换行写作 `\n`。
- 表头行本身不单独输出，它的内容体现在各行的字段名里。
- 合并单元格的说明有三种写法：
  - 纵向合并：`第a行至第b行共享第c列，字段 = …，内容 = …`
  - 横向合并：`第a行：第c列至第d列为合并单元格，内容 = …`
  - 两个方向都合并：`第a行至第b行、第c列至第d列为合并单元格，内容 = …`
- 这段文本会作为表格 chunk 的正文，同时用于检索编码和提供给 LLM。超长表格如何切分，见 [chunking.md](chunking.md)。

## 已知限制（下一阶段优化方向）

- 中文的"第N行/第M列"脚手架和重复出现的字段名，会稀释 embedding 对真实内容的表达。这是检索效果偏低的可疑原因之一，计划在检索优化阶段试验新的格式（新增一种 `TableFormatter` 实现）。
