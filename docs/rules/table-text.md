# 表格文本化

> **规则摘要**
> - 表格的文本由**表格结构**写出。结构来自 `[table_structure]`：`header_rules`（规则表头判定，见 [table-header.md](table-header.md)）或 `llm_annotation`（LLM 结构标注，见 [table-llm.md](table-llm.md)）。结构给出表头行，LLM 标注还可给出分节标题行与隐式合并。
> - 写法由 `[table_formatter]` 选择：`markdown_rows`（规则名 `markdown_rows_v1`）或 `labeled_rows`（`labeled_rows_v1`）。两种写法都是一行表格写成一行 `| 值 | 值 | … |`；`markdown_rows` 把表头写成一行列名路径，`labeled_rows` 不写表头行、只占一列的格写作 `列名: 值`。
> - 返回整表时交给回答 LLM 的**整表文本**另用 `grid_rows_v1`：每行原样写出，不用任何结构判定，与配置无关。
> - 合并单元格不判定含义，只表达结构：值写在左上角，同一行被覆盖的位置写 `←`，下面各行被覆盖的位置写 `↑`。
> - 文本中不出现行号、列号等中文脚手架。单元格和列名内的换行、连续空白合并成一个空格，这是唯一的改写。

代码：`rag/ingest/tables/markdown_rows.py`。决策背景：[005](../decisions/005-table-text-format.md)、[013](../decisions/013-llm-tables.md)。

## 示例

`markdown_rows_v1`（表头两行，`Price (USD)` 横跨两列）：

```
| Model | Price (USD) / FOB | Price (USD) / CIF |
| HX-120 | 72.50 | 44.50 |
```

`labeled_rows_v1`（同一张表）：

```
| Model: HX-120 | Price (USD) / FOB: 72.50 | Price (USD) / CIF: 44.50 |
```

`grid_rows_v1`（同一张表的整表文本）：

```
| Model | Price (USD) | ← |
| ↑ | FOB | CIF |
| HX-120 | 72.50 | 44.50 |
```

## 共同规则

- 每行的格数等于表格列数。空格写空；缺失的格（物理上不存在）写 `〔缺失单元格〕`；单元格内的 `|` 写作 `\|`。
- **列名路径**：某列的表头行中覆盖该列的各单元格文字，自上而下用 ` / ` 连接；空白的表头格不计入；没有任何文字的列路径为空。上层标签在它覆盖的每一列的路径中各出现一次。
- 结构有表头行时，表头行不作为数据行输出；表头之上的行照常输出。结构没有表头行时（规则判不出、LLM 标注未通过校验且规则也判不出），所有行原样输出，表头行与数据行一样写 `←`、`↑`。
- 分节标题行（只来自 LLM 标注）在原位置写出，不带列名。
- 隐式合并（只来自 LLM 标注）：标注为沿用上方值的空格写 `↑`，与纵向合并相同。
- 无法定位到网格的文字原样写在最后一行。
- 每行记录它来自哪一行表格、各单元格内容在行内的位置；评估按这些位置推出 chunk 的来源区域。
- 某行开启新的 chunk、且有纵向合并单元格从上方的数据行延续下来时，分块器把这一格写成 `↑ 原值`（见 [chunking.md](chunking.md)）。
- 回答用的系统提示词说明 `←`、`↑` 和 `↑ 值` 的含义；表格文本本身不加图例。

## markdown_rows_v1

- 结构有表头行时，在第一个表头行的位置写一行，每列为该列的列名路径，没有路径的列写空。

## labeled_rows_v1

- 只占一列、且值非空的格写作 `列名: 值`，列名是该列的列名路径；续接时写作 `列名: ↑ 值`。
- 横跨多列的格、空格、`←`、`↑`、缺失格、分节标题行不写列名；该列没有路径时也不写。
- 结构没有表头行时，输出与 `markdown_rows_v1` 相同。
- 行内的列名记为该行的来源，所以表头单元格计入含有它的每个 chunk 的区域。

## grid_rows_v1

- 等于结构为空（没有表头行、分节与隐式合并）时的 `markdown_rows_v1`：每行原样写出，合并格写 `←`、`↑`。
- 只用作整表库中的整表文本，不分块、不编码。表头怎么写、分节如何，都由回答 LLM 从原表结构自行理解。

## 已知限制

- 原文中本来就有的 `←`、`↑` 字符会与合并标记混淆。
- 结构没有表头行的表格被切成多块时，原表头行只出现在第一块；不猜测哪几行是表头。
- 规则结构没有分节：横跨整行的分节标题只出现在原位置，不带进后续的 chunk。
