# 用 LLM 处理表格

> **规则摘要**
> - 两种调用，每张表各一次（不通过校验时重试一次）：**结构标注**（`[table_structure] use = "llm_annotation"`）返回表头行、分节、隐式合并与一句引导句；**摘要**（`[table_index_text] use = "summary"`）返回一段摘要。
> - LLM 不改写表格文字：chunk 中的表格文字全部由代码按标注从原单元格写出（[table-text.md](table-text.md)）。
> - 输出用 JSON Schema 严格模式约束，开启模型原生推理（中档）。每次调用的原始输出、推理、用量、花费作为事实存入中间结果；校验结论单独记录。
> - 校验不通过时退回：标注 → 规则表头判定的结构；引导句 → 不加；摘要 → 该表改为表格 chunk。退回记为"降级完成"。调用出错（网络、限流、无密钥）不退回，入库失败。
> - 结果按"模型 + 提示词版本 + 推理强度 + 请求内容"缓存在 `.rag/llm-cache/`，重建索引时复用。

代码：`rag/ingest/tables/llm_tables.py`、`rag/ingest/tables/structure.py`。提示词原文见代码中的 `ANNOTATION_SYSTEM`、`SUMMARY_SYSTEM`、`USER_TEMPLATE`。决策背景：[013](../decisions/013-llm-tables.md)。

## 输入

- **表格网格**：Markdown，首行为列号，每行开头为行号；合并单元格的文字写在左上角，同行被覆盖处写 `←`，下方被覆盖处写 `↑`；空格写空。网格由解析出的表格直接生成，不经过表头判定。
- **上下文**：按阅读顺序，表格之前的 2 个节点；跳过解析器标为页眉、页脚的节点；遇到表格即停止；节点超过 200 token 时只保留靠近表格的末尾 200 token。提示词说明上下文只是表前文本、未必与表格有关。
- **文档语言**：解析结果中的语言（见 [lexical.md](lexical.md)）。引导句与摘要用文档语言书写；中文时长度按字数表述，否则按词数。

## 结构标注

| 字段 | 含义 | 校验（不通过的项写进下一次请求） |
|---|---|---|
| `header_rows` | 表头所在的行，连续；可为空 | 行号在表内；连续；其上方的行只能是分节标题行 |
| `sections` | 每节：标题行（连续若干行）与管辖的最后一行；各节平铺列出 | 标题行连续、在表内、不是表头行；最后一行不早于最后一个标题行；标题在表头之上的节须延续到表头之下；任两节的范围嵌套或不相交，不完全相同；一行只属于一节的标题；上下级由范围包含推出 |
| `implicit_merges` | 空格实际沿用上方的值：列、起始行、结束行 | 起始格非空；其下到结束行的格在网格中都为空、不在合并单元格内 |
| `lead` | 一句引导句：表格列出什么、一行代表什么、各列给出什么 | 非空；每串数字在表格或上下文中出现过；不超过 64 token |

另有一项渲染检查：按 `markdown_rows` 与 `labeled_rows` 两种写法分别规划分块，每块需重复的表头与节标题加上一行数据，在留出引导句上限（64 token）后放不下的，视为不通过。两种写法都检查，所以各 `llm_annotation` 配置共用同一份标注。

标注与引导句分别判定，各取最后一次通过的结果：标注通过、引导句未通过时，用标注、不加引导句。

## 摘要

- 一段文字，用文档语言；说明表格关于什么、如何组织（一行代表什么、各列原标签、分组与合计）；照抄问题用来指向某一行或某一组的值（只用于排序的序号不算），逐个列出、不用范围代替；不列其余数值。
- 校验：非空；每串数字在表格或上下文中出现过；作为 passage 计数不超过分块上限（不切分）。

## 引导句与摘要的共同约束

- 不写表格在文档中的位置（章节、条款、表格编号、页码），可以使用标题中的语义。
- 不写识别文档本身的编号；摘要中作为单元格值出现的编号除外。引导句与摘要用于按语义匹配问题；问题指向哪份文档由检索范围（标识编码）决定，不由文本匹配决定。
- 不写表格与上下文都不支持的内容。

## 长度

| 项目 | 提示词中的写法 | 代码接受的上限 |
|---|---|---|
| 引导句 | 24 词（中文 48 字） | 64 token |
| 摘要 | 词数 = 上限 token × 0.5（中文字数 = 上限 token × 1） | 上限 token = 分块上限减 `passage: ` 前缀 |

## 使用方式

- **结构**：标注通过时，表格按标注的结构写出与分块（[chunking.md](chunking.md)）；不通过时用规则表头判定的结构。
- **引导句**：`[table_index_text] use = "rows_with_lead"` 时，写在该表每个 chunk 的开头；其他设置下只记录不使用。
- **摘要**：`summary` 时，该表在索引中只有一个摘要 chunk（类型 `table_summary`），来源区域为整张表；返回单元只能是整表。摘要由 LLM 读原样网格写出，不用任何结构判定；配置中的 `[table_structure]`、`[table_formatter]` 只用于摘要不通过、该表退回表格 chunk 时。

装配约束：`rows_with_lead` 需要 `llm_annotation`（引导句与标注同一次调用）；`summary` 只能搭配 `header_rules`（结构标注的结果在摘要配置中只会用于退回，不值得多一次调用）；两种 LLM 调用都需要 `structured_tokens` 分块器。

## 缓存与指纹

- 缓存键包含模型、提示词版本、推理强度与完整请求（含网格、上下文、长度表述）；`ingest --force` 复用缓存，不重复计费。
- 模型、提示词版本、推理强度、长度设置与上下文规则进入构建指纹。入库用的 LLM 在配置节中设置，与问答的 `[llm]` 分开，不受 `OPENROUTER_MODEL` 影响。temperature 默认为 0，可在配置节中用 `temperature` 设置。
- 请求只发往支持 structured output 的服务方。
