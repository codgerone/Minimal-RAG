# 检索范围（按标识编码过滤）

> **规则摘要**
> - 文档标识表 `documents/documents.toml` 为每份 PDF 登记一个或多个标识编码。编码由用户分配，不从 PDF 内容抽取。
> - 问题中出现某份文档的编码时，只在该文档内检索；出现多份文档的编码时，在这些文档的并集内检索；一个都没有出现时，在全库检索。
> - 开关是配置 `[retriever] document_filter`（内置装配为开启）。它属于查询配置，不进构建指纹。
> - `--document` 由用户显式指定，优先于自动识别。

代码：`rag/query/scope.py`。

## 标识表

```toml
[[document]]
file = "相对 documents/ 的路径"
codes = ["编码1", "编码2"]
```

加载时满足以下任一情况即报错，不做检索：

- 文件不是 `[[document]]` 列表，或某一项缺少 `file`、`codes` 为空；
- 同一文件登记两次（路径比较不区分大小写）；
- 某个编码规范化后少于 4 个字符；
- 同一个规范化后的编码登记给了两份文档。

登记了但不在 `documents/` 中的文件，在检索时忽略；`status` 会列出这类文件，以及没有登记编码的 PDF。

## 识别

1. **规范化**：NFKC 归一，统一小写，只保留 Unicode 字母和数字。问题和编码使用同一规范化。
2. **命中**：规范化后的编码是规范化后问题的子串，就算命中。
3. **范围**：所有命中编码对应的文档构成检索范围；检索在范围内按（距离, chunk ID）取前 K 条，排序规则与全库检索相同。

## 检索范围的五种情况

| 情况 | 条件 | 检索范围 |
|---|---|---|
| 用户指定 | 命令带 `--document` | 该文档 |
| 自动识别 | 过滤开启、有标识表、至少命中一个编码 | 命中的文档 |
| 未识别 | 过滤开启、有标识表、没有命中 | 全库 |
| 未配置标识表 | 过滤开启、`documents/documents.toml` 不存在 | 全库 |
| 过滤已关闭 | `document_filter = false` | 全库 |

`search`、`ask`、`chat` 每次检索都输出属于哪种情况；评估报告逐题记录。
