# 检索评估

> **规则摘要**
> - 题目和标准证据由人工标注，存放在 `eval/ground-truth/`。每道题拆成若干**信息项**（问题要求回答的内容），每个信息项对应一个**证据组**。
> - 证据组由一套或多套**方案**组成，满足任一套即覆盖；每套方案是足以得出该信息项的一段或几段 PDF 原文（excerpt），须全部检索到。
> - 每段 excerpt 在 PDF 上定位为一组词坐标，经人工确认后写入 ground-truth，与配置无关；每个 chunk 在入库时记录内容来自 PDF 的哪些区域。excerpt 的全部词都落在一组 chunk 的区域内，这组 chunk 就算这段 excerpt。
> - 检索结果按**返回单元**计：普通 chunk 是一个单元；`table_return_unit = "table"` 时，表格 chunk 换成它所属的整张表，一张表只占一个单元。整表单元视为返回了该表的全部 chunk。
> - 一个证据组被"覆盖"，指它的某个可接受 chunk 组合**全部**出现在前 K 个返回单元里。
> - 每道题的检索范围与查询相同，按 [document-filter.md](document-filter.md) 由问题中的标识编码确定。
> - 主要指标：命中率、完整覆盖率、证据组召回、MRR、Chunk 精确率、跨文档污染；文档过滤开启且有标识表时，另报文档识别准确率。另报每题返回 token 与逐证据组所需 K。K 取配置文件中的 `[eval] top_k`（内置装配都是 3，与历史基线一致；可用 `--top-k` 临时覆盖）。
> - 多轮检索另有评估：在交给 LLM 的单元序列与 LLM 接受的证据上计算凑齐，报误判可回答、证据被拒、与单轮同 token 的比较、按方式的找回与成本（"多轮检索的评估"）。
> - 改动会使 chunk 分界移动时，按**多预算配对比较**验收：新旧设置各在若干个相邻预算下评估，按档配对比较；只有方向一致的差异才算有效或无效，其余视为分界移动带来的随机扰动。档位与判定门槛在每次的提案中确定。

## 标注规则

1. **信息项**是问题要求回答的内容，由问题和参考答案拆出。并列询问的几项（以连词连接或依次列出）是不同的信息项；问题对多个对象问同一属性（"各自的数量"）时，该属性是一个信息项，覆盖全部对象。作答所需、但问题没有要求回答的中间事实（计算的输入、由描述确定的对象）不是信息项，其出处写进所需信息项的方案。信息项与证据组一一对应；两个证据组的原文相同也不合并。
2. **方案**是足以得出该信息项的 excerpt 集合，且缺一不可：去掉任何一段就不足以得出。是否需要计算、计算几步不影响判定。
3. 一个证据组列出所有能单独构成方案的出处；同一段 excerpt 可被多个证据组引用。
4. 与问题相关、但不能构成任一方案的原文不标注。
5. excerpt 照抄 PDF 原文，可以跨两页。来自表格时，各单元格之间用 ` | ` 或换行分隔。
6. excerpt 分两类：
   - **普通 excerpt**：只写回答所需的原文；来自表格时只写数据单元格，不写表头。
   - **表头 excerpt**：只在表头本身就是答案时使用，只写作为答案的表头文字，并加表头标记（`table_header`）。
   - 同时需要表头和数据才能回答时，拆成一段表头 excerpt 和一段普通 excerpt，放在同一套方案里。
7. 表格数据 excerpt 的值在同一行的多列中重复、只靠列才能区分时，加**定位提示**（`locate_hint`）：所在列的表头文字。它只用于在 PDF 上定位，不属于证据，不参与判定。

代码：`rag/eval/`（`dataset.py` 加载标注，`anchors.py` 定位 excerpt，`judge.py` 判定证据对应的 chunk，`metrics.py` 计算指标，`runner.py` 编排一次评估）；chunk 来源区域在 `rag/ingest/regions.py`。

## excerpt 定位

`python -m rag anchors` 在 PDF 文字层中定位每段 excerpt，生成审核文件 `tmp/anchor-review/`（逐段高亮的页面截图和整份 PDF 高亮副本）；人工核对后用 `--write` 写入 ground-truth。

1. 文字比较前两边都做 NFKC 规范化、统一小写，只保留字母和数字。
2. excerpt 按 ` | ` 和换行切成**片段**，每个片段单独匹配。PDF 的词按内容流顺序读取。
3. 一个片段匹配一串在页面上连贯的词：相邻两词在同一行且间距不超过 2.5 个字高，或换到下一行（行距不超过 1.5 个字高）且起点不比这串文字的左边缘靠左超过 4 个字高。匹配的起止都在词的边界上。
4. 片段整体匹配不到时，拆成能匹配的最长连贯部分；完全找不到的词报告为"找不到"，存在找不到的片段时不能写入。
5. 片段在页面上出现多处时，从各片段的出现位置中各选一处，使所选位置的最小生成树总长最小，且同一个 PDF 词不被选两次。距离计算：两处在同一行时取水平距离的 0.25 倍；否则取欧氏距离，垂直距离乘以 4，不同页之间加 2000 点。
6. 有定位提示时，先在页面上找到提示文字（须恰好出现一处），多处出现的片段只保留与提示所在列水平重叠的位置。
7. 写入的坐标字段按片段记录片段原文和它的词坐标（页码、x0、y0、x1、y1，PyMuPDF 页面坐标，单位为点），并记录 excerpt 原文的哈希。excerpt 原文改动后坐标失效，评估报错，需重新定位和确认。

## chunk 来源区域

入库时由 chunk 的来源记录（内容来自哪个元素的哪段文字）和解析器给出的坐标推出，记在中间结果 `chunks.json` 中，不进向量库。区域分两级：**细**区域恰好框住这部分内容；**粗**区域只说明内容在框内某处（没有框时为整页）。

| chunk 的内容 | 区域 |
|---|---|
| 有词坐标的文字（`pymupdf_pages`） | chunk 文字区间覆盖到的每个词的框，细 |
| 完整的段落、列表项 | 元素的框，细 |
| 段落、列表项的一部分 | 元素的框，粗 |
| 表格的完整行 | 该行各单元格的框，细 |
| 表格行的一部分 | 该行各单元格的框，粗 |
| 没有坐标的单元格 | 表格的框，粗；表格也没有框时为整页 |
| 没有坐标的段落、列表项 | 整页，粗 |
| 已认出的表头 | 表头单元格的框计入该表格的第一个 chunk，细 |
| 分块器加的定位说明文字 | 无 |

## 证据判定

先确定每段 excerpt 对应的 chunk 组合（只看与 excerpt 同一文档的 chunk）：

1. 一个词的框中心落在某个 chunk 的细区域内（容差 0.5 点），这个词就被该 chunk 覆盖。
2. 一个词不在任何细区域内、但在某些 chunk 的粗区域内时，**文字兜底**：这些 chunk 中，正文里按原顺序依次出现该词所在片段的全部词（比较方式同定位第 1 条）的那一个覆盖它。没有这样的 chunk，或有不止一个，这段 excerpt 记为"找不到对应 chunk"并说明原因；不止一个时需给 excerpt 补环境文字。
3. 一组 chunk 覆盖了 excerpt 的全部词，就是一个可接受组合；只保留最小组合。
4. **表头 excerpt** 另外扩展：找出与第 3 步组合中的 chunk 来自同一个被切分单元（`parent_unit_id` 相同）的其他 chunk；其中正文逐字包含该 excerpt 全部片段的（比较方式同定位第 1 条），各自单独构成一个可接受组合。普通 excerpt 不扩展。
5. 有 excerpt 找不到对应 chunk 时，评估报错并列出原因。

再由 excerpt 推出证据组：

- 一套方案的可接受组合 = 从方案内每段 excerpt 各取一个组合，取并集；方案内任一 excerpt 找不到组合，该方案不可用。
- 证据组的可接受组合 = 各方案可接受组合的并集（只保留最小组合）。没有可用方案的证据组无法被覆盖。
- 证据组的可接受组合中最少的 chunk 数大于 K 时，该组在这个 K 下不可能被覆盖，报告中单独标出。
- 用到文字兜底的 excerpt 与证据组在报告中标为"文字兜底"，供抽查。

## 指标

### 计算方式：先逐题算分，再对题目取算术平均

所有指标都分两步计算：

1. **逐题**：每道可回答题算出一个 0–1 之间的分数；
2. **汇总**：把这些分数相加，再除以可回答题的数量 N（数据集 3.4.1 为 N = 32）。

```
指标 = (第 1 题的分数 + 第 2 题的分数 + … + 第 N 题的分数) / N
```

每道题权重相同（宏平均），汇总的分母始终是题数。每次评估的 `result.json` 记录了各指标的分子与分母。不可回答题（标注为 `answerable: false`）不参与这些指标。

### 符号

对某一道题：

| 符号 | 含义 |
|---|---|
| H | 前 K 个返回单元，按排名 1…K 排列；\|H\| 为实际返回的单元数（检索范围内的单元不足 K 个时会小于 K） |
| G | 这道题的证据组数 |
| 覆盖 | 一个证据组的某个可接受 chunk 组合，全部出现在 H 中 |
| C | H 覆盖的证据组数（0 ≤ C ≤ G） |
| 相关 chunk | 属于任一证据组、任一可接受组合的 chunk（只要是某个组合的成员就算，不要求整个组合都被检索到） |
| R | H 中含相关 chunk 的单元个数 |
| r₁ | H 中第一个含相关 chunk 的单元的排名；没有时不存在 |
| X | H 中来自"证据所在文档"以外的单元个数 |

### 定义

| 指标 | 单题分数 | 汇总（对 N 道题取平均） | 一句话含义 |
|---|---|---|---|
| **命中率** | C ≥ 1 记 1，否则记 0 | 至少覆盖一组证据的**题数** / N | 有多少题，至少找到了一条完整的证据 |
| **完整覆盖率** | C = G 记 1，否则记 0 | 所有证据组都被覆盖的**题数** / N | 有多少题，回答所需的证据全部找到了 |
| **证据组召回** | C / G | 各题"覆盖组数 / 证据组数"的平均值 | 平均每题找到了多大比例的证据 |
| **MRR** | 1 / r₁；没有相关 chunk 时记 0 | 各题倒数排名的平均值 | 第一条有用结果平均排得多靠前 |
| **Chunk 精确率** | R / \|H\| | 各题"相关条数 / 返回条数"的平均值 | 返回的结果里平均有多少是有用的 |
| **跨文档污染**（越低越好） | X / \|H\| | 各题"跨文档条数 / 返回条数"的平均值 | 返回的结果里平均有多少来自无关文档 |

**文档识别准确率**（只在文档过滤开启且存在标识表时报告）：

```
文档识别准确率 = 检索范围为"自动识别"、且识别出的文档集合等于证据所在文档集合的题数 / N
```

注意：

- **命中率和完整覆盖率都按题数统计**，不是按证据组数统计。
- **证据组召回是"每题比例的平均"**，不是"全部被覆盖组数 / 全部证据组数"。
- **MRR 看的是"相关 chunk"，而不是"覆盖的证据组"**。一个 chunk 只要属于某个可接受组合，即使组合里的其他 chunk 没被检索到，也算相关。因此可能出现 MRR > 0、但命中率为 0 的题目。

### 返回 token 与所需 K

- **每题返回 token**：H 中各单元文本的 token 数之和，按 multilingual-e5 分词器计数（与分块预算相同，含 `passage: ` 前缀和特殊 token）。汇总报全部可回答题之和除以 N，以及单题最大值。
- **所需 K**：在检索范围内的全量排名（全部返回单元）中，某个证据组被覆盖所需的最少前几个单元；全量排名中仍覆盖不了时记为无法覆盖。

### 表格证据指标

**表格 excerpt**：词中心全部落在同一文档中解析器给出的某个表格框内的 excerpt。含表格 excerpt 的证据组为**表格证据组**，含表格证据组的题为**表格题**。下列指标都只看表格 excerpt，读检索范围内的全量排名。

| 指标 | 单位 | 定义 |
|---|---|---|
| 指标 1 表格 chunk 名次 | 每个表格证据组 | 全量 chunk 排名中（换成返回单元之前），覆盖该组表格 excerpt 中任一词的 chunk 里最靠前者的名次 |
| 指标 2 所需返回单元数 | 每道表格题 | 每个表格证据组：只看各方案中的表格 excerpt，全量返回单元排名中全部覆盖所需的最少前几个单元，取各方案的最小值；每题取其表格证据组的最大值；有组始终覆盖不了时记为无法覆盖 |
| 指标 3 所需 token | 每道表格题 | 全量返回单元排名中前"指标 2"个单元的 token 之和 |
| 所需单元下限 | 每道表格题 | 每组取一个可接受组合，这些组合的 chunk 所属返回单元个数的最小值，与排名无关 |
| K–覆盖–token 曲线 | 每个 K | 表格证据在前 K 个单元内全部覆盖的表格题数、完整覆盖的可回答题数、可回答题前 K 个单元的 token 之和 |
| 入库成本 | 每张表 | 一次入库的 LLM 费用、耗时、调用次数（含重试）各除以处理的表数；每次调用的费用、耗时为总数除以调用次数；另报退回规则的表数 |

汇总：指标 1 报各组名次的平均、中位数（只计找得到的组）、排第 1 与排进前 3 的组数；指标 2、3 报各题的平均、中位数（不计无法覆盖的题）与指标 2 ≤ 3 的题数。分母都写明是组数还是题数。

**对照计数**（两次评估只差一个因素时）：计数单位都是表格题。

- 指标 1：一题中至少一个表格证据组名次变小、没有组变大为**变好**；反之为**变差**；两者都有为**有好有坏**。另报可能变好的题数：N 减去比较前表格证据组已全部排第 1 的题数（这些题只可能不变或变差）。
- 指标 2、3：数值变小为变好，变大为变差。指标 3 另报所需单元数不变、token 仍有变化的题数，即变化只来自返回单元本身长度的题。
- 判断以平均值、中位数为主，计数为辅。

### 多档预算

`eval --budgets B1,B2,...` 每题检索一次，取全量排名，每档预算 K 各出一份评估，每份按上述定义计算。

### 查询侧的比较

用于比较两种查询方式（`query-compare`）。与 K 无关，不设阈值。名次都在全量排名中计算，不截断。

**定义**：
- **凑齐名次**：一个信息项（即一个证据组）的某个可接受 chunk 组合全部出现时的最小名次。逐层计算：
  - 每段 excerpt：取它的各个可行 chunk 组合中，组合内最靠后的返回单元名次，再在各组合间取最小值；
  - 每个方案：取它各段 excerpt 名次中的最大值；
  - 信息项：取各方案中的最小值。
  
  全量排名中凑不齐记为"未凑齐"，排在任何名次之后。
- **首块名次**：第一个含该信息项任一可接受组合中任一 chunk 的返回单元的名次。只作诊断，不参与判定。
- **凑齐向量**：一题各信息项的凑齐名次按升序排列。第 j 位是凑齐 j 个信息项需要返回到的名次，末位是完整覆盖所需的 K。

**判定**（右侧相对左侧，逐位比较凑齐向量）：
- **变好**：至少一位更早，没有一位更晚；等价于任意 K 下右侧凑齐的信息项数都不少于左侧，且某个 K 下更多；
- **变差**：至少一位更晚，没有一位更早；
- **各有优势**：既有更早的位，也有更晚的位；
- **不变**：每一位都相同。

**不合并的分解**：没有返回顺序。每段 excerpt 的名次改为在该信息项对应的各子问题一路中分别计算（一个可行 chunk 组合须在同一路中全部出现），取其中最好的；方案、信息项的取法不变。子问题与信息项的对应逐题人工标注；没有子问题对应的信息项按全部子问题各路计算，并记为分解遗漏。需要 K 的指标不计算。

**跨组合汇总**：每种组合各自判定、各自计数，再按组合取平均。
- 一次生成中的题数：变好、变差、各有优势、不变的题数，按组合取平均；**净值** = 变好的平均题数 − 变差的平均题数。
- 组合共用同一批题，彼此不独立：平均值是更合理的点估计，有效样本仍是题数。

**多次生成**：规划含 LLM 时，在冻结的第 0 次生成之外另做独立生成（缓存隔离）。
- 报告各次生成的平均题数与净值，以及净值在各次生成中的范围。
- **稳定**、**翻转**也按组合各自计数再取平均：在一种组合中，一题在全部生成中都变好（或都变差）计入稳定；在一次生成中变好、另一次变差计入翻转。
- 分解得到的子问题在各次生成中不同，稳定与翻转只在全部生成中文字相同的子问题上计数。

### 多轮检索的评估

用于 `[query] mode = "multi_round"`（[multi-round.md](multi-round.md)）。每题按调用上限 L_max 运行一次；上限 L < L_max 的结果从同一次运行截取：规划调用超过 L − 1 次的运行在第 L 次规划调用之前截止，取第 L − 1 次规划调用之后的状态，再为该档作答一次；否则即为该次运行本身。

**定义**：
- **展示序列**：一次运行中交给 LLM 的单元，按第一次交给 LLM 的先后排列；同一轮内先按问题编号，再按方式，再按名次。上限 L 的展示序列只含第 L − 1 次规划调用之前交出的单元。
- **凑齐名次**按"查询侧的比较"的定义在展示序列上计算；另记凑齐时最后一块所在的检索轮次。
- **已接受的证据**：截止状态下全部问题已接受的单元。信息项在已接受的单元中凑齐，记为"证据凑齐"。
- **完整覆盖**：一题全部信息项在展示序列（或已接受的证据）中凑齐。
- **误判可回答**：Q0 判为可回答，但有信息项未在已接受的证据中凑齐。只用于可回答题；无答案题判为可回答时单列答案，答案说明材料中没有即为正确，本规则不判定。
- **证据被拒**：信息项在展示序列中凑齐、在已接受的证据中未凑齐。
- **与单轮比较**：
  - 同样 token：单轮排名中累计 token 不超过本题展示序列 token 的前若干单元，比较完整覆盖与凑齐的信息项；
  - 支配关系：多轮的凑齐向量在展示序列上计算（未凑齐排在任何名次之后），单轮在全量排名上计算，按"查询侧的比较"判定。
- **按方式的找回**：按单元第一次交给 LLM 时由哪种方式返回计，同一轮被几种方式返回的单元，各方式都计。证据单元为含某信息项任一可接受 chunk 的单元。往下取是兜底的基线：其他兜底方式返回、而同一轮往下取没有返回的证据单元，才计为该方式的贡献。另计每个信息项凑齐时最后一块由哪种方式交出。
- **成本**：每次运行的 LLM 调用次数（规划、作答分列）、耗时、花费，每次调用的输入 token，检索次数与耗时。花费为服务商报告的计费金额，命中缓存的调用记首次调用时的金额。

**汇总**：题数按生成各自计数，报各次生成的平均与范围；稳定、翻转按"多次生成"的定义。

### 排序规则

检索器的结果按（距离, chunk ID）升序排列，返回单元按其排名最靠前的 chunk 排列。第 K 位如果出现距离相同的结果，会先扩大候选范围再排序，保证结果确定、可复现。

## 评估前检查

- 索引必须是最新的：所有文档的状态都是"已入库"；索引的中间结果要带 chunk 来源区域（V3.4 之前建的索引需 `ingest --force`）。
- 标注涉及的 PDF 必须都在 `documents/` 中，且与标注时的文件哈希相同；PDF 改过时评估报错，需重新标注和定位。
- 每段 excerpt 都要有有效的坐标；缺失或原文改过时评估报错。

## 分块改动的验收：多预算配对比较

chunk 分界移动时，原本落在同一块的证据可能被切开，原本分开的可能合上，单次评估的升降里混有这种偶然性。规则不变、只小幅改变预算，题目状态也会有升有降。因此会使分界移动的改动，按以下方法验收。

**适用**：改变分块规则或分块参数、使 chunk 分界移动的改动。chunk 不变的改动（换编码器、检索器等）仍按单次评估比较。

**做法**：

1. 新设置与基线设置各取若干档预算，全量入库并评估，其他设置不变。每档围绕各自的预算取值，档间只移动分界、不明显改变 chunk 长度；两套设置的预算不同时（如比较不同的 chunk 长度），按相对位置配对（各自的最小档对最小档，依此类推）。
2. 实验配置另存为新名字，评估目录才能区分。
3. 档数、各档预算、判定门槛（第 3、4 条中的净数）在提案中写明，由用户确认后再运行。

**判定**（指标为该装配默认检索器下的完整覆盖题数）：

1. 扰动范围 N：基线设置在各档与其原预算之差，取绝对值最大者。
2. 每一档 b，Δ(b) = 新设置在 b 档的完整覆盖 − 基线设置在 b 档的完整覆盖。Δ > 0 的档数记为 n₊，Δ < 0 的记为 n₋。
3. **方向性变差**：n₋ − n₊ 达到提案中确定的净数，或各档 Δ 之和 < −N。不接受，查明原因。
4. **方向性变好**：n₊ − n₋ 达到该净数，或各档 Δ 之和 > N。作为改进接受。
5. **随机扰动**：不满足 3、4。是否接受取决于改动的设计理由，写入决策文档，注明接受依据不是指标提升。

命中率、证据组召回、MRR 和其他检索器下的结果同样按档列出，不参与判定。

**逐题**：同一档内，题目状态按 未命中 < 部分覆盖 < 完整覆盖 比较。在多数档中朝同一方向改变、且没有反向的题，记为系统性变化，在验收记录中逐一说明原因。

各次验收所用的档位与门槛记录在对应的提案和决策文档中。
