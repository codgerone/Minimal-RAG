# 检索评估

> **规则摘要**
> - 题目和标准证据由人工标注，存放在 `eval/ground-truth/`。每道题拆成若干**信息项**（问题要求回答的内容），每个信息项对应一个**证据组**。
> - 证据组由一套或多套**方案**组成，满足任一套即覆盖；每套方案是足以得出该信息项的一段或几段 PDF 原文（excerpt），须全部检索到。
> - 每段 excerpt 在 PDF 上定位为一组词坐标，经人工确认后写入 ground-truth，与配置无关；每个 chunk 在入库时记录内容来自 PDF 的哪些区域。excerpt 的全部词都落在一组 chunk 的区域内，这组 chunk 就算这段 excerpt。
> - 一个证据组被"覆盖"，指它的某个可接受 chunk 组合**全部**出现在前 K 条结果里。
> - 每道题的检索范围与查询相同，按 [document-filter.md](document-filter.md) 由问题中的标识编码确定。
> - 主要指标：命中率、完整覆盖率、证据组召回、MRR、Chunk 精确率、跨文档污染；文档过滤开启且有标识表时，另报文档识别准确率。K 取配置文件中的 `[eval] top_k`（内置装配都是 3，与历史基线一致；可用 `--top-k` 临时覆盖）。

## 标注规则

1. **信息项**由问题和参考答案拆出。问题对多个对象问同一属性（"各自的数量"）时，该属性是一个信息项，覆盖全部对象。信息项与证据组一一对应；两个证据组的原文相同也不合并。
2. **方案**是足以得出该信息项的 excerpt 集合，且缺一不可：去掉任何一段就不足以得出。是否需要计算、计算几步不影响判定。
3. 一个证据组列出所有能单独构成方案的出处；同一段 excerpt 可被多个证据组引用。
4. 与问题相关、但不能构成任一方案的原文不标注。
5. excerpt 照抄 PDF 原文，可以跨两页。来自表格时，各单元格之间用 ` | ` 或换行分隔。
6. excerpt 分两类：
   - **普通 excerpt**：只写回答所需的原文；来自表格时只写数据单元格，不写表头。
   - **表头 excerpt**：只在表头本身就是答案时使用，只写作为答案的表头文字，并加表头标记（`table_header`）。
   - 同时需要表头和数据才能回答时，拆成一段表头 excerpt 和一段普通 excerpt，放在同一套方案里。
7. 表格数据 excerpt 的值在同一行的多列中重复、只靠列才能区分时，加**定位提示**（`locate_hint`）：所在列的表头文字。它只用于在 PDF 上定位，不属于证据，不参与判定。

代码：`rag/eval/`（`dataset.py` 加载标注，`anchors.py` 定位 excerpt，`judge.py` 判定证据对应的 chunk，`metrics.py` 计算指标，`runner.py` 编排一次评估）；chunk 来源区域在 `rag/ingest/regions.py`。

## excerpt 定位

`python -m rag anchors` 在 PDF 文字层中定位每段 excerpt，生成审核文件 `tmp/anchor-review/`（逐段高亮的页面截图和整份 PDF 高亮副本）；人工核对后用 `--write` 写入 ground-truth。

1. 文字比较前两边都做 NFKC 规范化、统一小写，只保留字母和数字。
2. excerpt 按 ` | ` 和换行切成**片段**，每个片段单独匹配。PDF 的词按内容流顺序读取。
3. 一个片段匹配一串在页面上连贯的词：相邻两词在同一行且间距不超过 2.5 个字高，或换到下一行（行距不超过 1.5 个字高）且起点不比这串文字的左边缘靠左超过 4 个字高。匹配的起止都在词的边界上。
4. 片段整体匹配不到时，拆成能匹配的最长连贯部分；完全找不到的词报告为"找不到"，存在找不到的片段时不能写入。
5. 片段在页面上出现多处时，从各片段的出现位置中各选一处，使所选位置的最小生成树总长最小，且同一个 PDF 词不被选两次。距离计算：两处在同一行时取水平距离的 0.25 倍；否则取欧氏距离，垂直距离乘以 4，不同页之间加 2000 点。
6. 有定位提示时，先在页面上找到提示文字（须恰好出现一处），多处出现的片段只保留与提示所在列水平重叠的位置。
7. 写入的坐标字段按片段记录片段原文和它的词坐标（页码、x0、y0、x1、y1，PyMuPDF 页面坐标，单位为点），并记录 excerpt 原文的哈希。excerpt 原文改动后坐标失效，评估报错，需重新定位和确认。

## chunk 来源区域

入库时由 chunk 的来源记录（内容来自哪个元素的哪段文字）和解析器给出的坐标推出，记在中间结果 `chunks.json` 中，不进向量库。区域分两级：**细**区域恰好框住这部分内容；**粗**区域只说明内容在框内某处（没有框时为整页）。

| chunk 的内容 | 区域 |
|---|---|
| 有词坐标的文字（`pymupdf_pages`） | chunk 文字区间覆盖到的每个词的框，细 |
| 完整的段落、列表项 | 元素的框，细 |
| 段落、列表项的一部分 | 元素的框，粗 |
| 表格的完整行 | 该行各单元格的框，细 |
| 表格行的一部分 | 该行各单元格的框，粗 |
| 没有坐标的单元格 | 表格的框，粗；表格也没有框时为整页 |
| 没有坐标的段落、列表项 | 整页，粗 |
| 已认出的表头 | 表头单元格的框计入该表格的第一个 chunk，细 |
| 分块器加的定位说明文字 | 无 |

## 证据判定

先确定每段 excerpt 对应的 chunk 组合（只看与 excerpt 同一文档的 chunk）：

1. 一个词的框中心落在某个 chunk 的细区域内（容差 0.5 点），这个词就被该 chunk 覆盖。
2. 一个词不在任何细区域内、但在某些 chunk 的粗区域内时，**文字兜底**：这些 chunk 中，正文里按原顺序依次出现该词所在片段的全部词（比较方式同定位第 1 条）的那一个覆盖它。没有这样的 chunk，或有不止一个，这段 excerpt 记为"找不到对应 chunk"并说明原因；不止一个时需给 excerpt 补环境文字。
3. 一组 chunk 覆盖了 excerpt 的全部词，就是一个可接受组合；只保留最小组合。
4. **表头 excerpt** 另外扩展：找出与第 3 步组合中的 chunk 来自同一个被切分单元（`parent_unit_id` 相同）的其他 chunk；其中正文逐字包含该 excerpt 全部片段的（比较方式同定位第 1 条），各自单独构成一个可接受组合。普通 excerpt 不扩展。
5. 有 excerpt 找不到对应 chunk 时，评估报错并列出原因。

再由 excerpt 推出证据组：

- 一套方案的可接受组合 = 从方案内每段 excerpt 各取一个组合，取并集；方案内任一 excerpt 找不到组合，该方案不可用。
- 证据组的可接受组合 = 各方案可接受组合的并集（只保留最小组合）。没有可用方案的证据组无法被覆盖。
- 证据组的可接受组合中最少的 chunk 数大于 K 时，该组在这个 K 下不可能被覆盖，报告中单独标出。
- 用到文字兜底的 excerpt 与证据组在报告中标为"文字兜底"，供抽查。

## 指标

### 计算方式：先逐题算分，再对题目取算术平均

所有指标都分两步计算：

1. **逐题**：每道可回答题算出一个 0–1 之间的分数；
2. **汇总**：把这些分数相加，再除以可回答题的数量 N（目前 N = 24）。

```
指标 = (第 1 题的分数 + 第 2 题的分数 + … + 第 N 题的分数) / N
```

每道题权重相同（宏平均），汇总的分母始终是题数。每次评估的 `result.json` 记录了各指标的分子与分母。不可回答题（标注为 `answerable: false`）不参与这些指标。

### 符号

对某一道题：

| 符号 | 含义 |
|---|---|
| H | 检索返回的前 K 条结果，按排名 1…K 排列；\|H\| 为实际返回条数（索引里 chunk 不足 K 个时会小于 K） |
| G | 这道题的证据组数 |
| 覆盖 | 一个证据组的某个可接受 chunk 组合，全部出现在 H 中 |
| C | H 覆盖的证据组数（0 ≤ C ≤ G） |
| 相关 chunk | 属于任一证据组、任一可接受组合的 chunk（只要是某个组合的成员就算，不要求整个组合都被检索到） |
| R | H 中相关 chunk 的个数 |
| r₁ | H 中第一个相关 chunk 的排名；H 中没有相关 chunk 时不存在 |
| X | H 中来自"证据所在文档"以外的 chunk 个数 |

### 定义

| 指标 | 单题分数 | 汇总（对 N 道题取平均） | 一句话含义 |
|---|---|---|---|
| **命中率** | C ≥ 1 记 1，否则记 0 | 至少覆盖一组证据的**题数** / N | 有多少题，至少找到了一条完整的证据 |
| **完整覆盖率** | C = G 记 1，否则记 0 | 所有证据组都被覆盖的**题数** / N | 有多少题，回答所需的证据全部找到了 |
| **证据组召回** | C / G | 各题"覆盖组数 / 证据组数"的平均值 | 平均每题找到了多大比例的证据 |
| **MRR** | 1 / r₁；没有相关 chunk 时记 0 | 各题倒数排名的平均值 | 第一条有用结果平均排得多靠前 |
| **Chunk 精确率** | R / \|H\| | 各题"相关条数 / 返回条数"的平均值 | 返回的结果里平均有多少是有用的 |
| **跨文档污染**（越低越好） | X / \|H\| | 各题"跨文档条数 / 返回条数"的平均值 | 返回的结果里平均有多少来自无关文档 |

**文档识别准确率**（只在文档过滤开启且存在标识表时报告）：

```
文档识别准确率 = 检索范围为"自动识别"、且识别出的文档集合等于证据所在文档集合的题数 / N
```

注意：

- **命中率和完整覆盖率都按题数统计**，不是按证据组数统计。
- **证据组召回是"每题比例的平均"**，不是"全部被覆盖组数 / 全部证据组数"。
- **MRR 看的是"相关 chunk"，而不是"覆盖的证据组"**。一个 chunk 只要属于某个可接受组合，即使组合里的其他 chunk 没被检索到，也算相关。因此可能出现 MRR > 0、但命中率为 0 的题目。

### 排序规则

检索结果按（距离, chunk ID）升序排列。第 K 位如果出现距离相同的结果，会先扩大候选范围再排序，保证结果确定、可复现。

## 评估前检查

- 索引必须是最新的：所有文档的状态都是"已入库"；索引的中间结果要带 chunk 来源区域（V3.4 之前建的索引需 `ingest --force`）。
- 标注涉及的 PDF 必须都在 `documents/` 中，且与标注时的文件哈希相同；PDF 改过时评估报错，需重新标注和定位。
- 每段 excerpt 都要有有效的坐标；缺失或原文改过时评估报错。
