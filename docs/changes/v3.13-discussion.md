## 第 5 轮（2026-10-19）

- 用户问：标注 + 代码渲染会削弱 LLM 的理解（封闭集合表达不了的都丢了），直接由 LLM 输出是否更好、有何弊端。
- 助手：确实有损。直接输出（即样例已跑的 llm_records_v1）的弊端：
  数值可能被改错 / 张冠李戴而校验发现不了（数字检查只查"表里有这个数"）；来源区域靠 LLM 引用单元格，引用错则坐标评估错；

  折中：标注 + 限定范围的自由文本说明（引导句即全表范围的说明，可再允许节范围的说明，随该节重复），数值仍原样。

## 第 6 轮（2026-10-19）—— 已定

- **路线：LLM 输出结构标注 + 代码渲染**，不做直接输出，样例也不再跑直接输出。提案要写清：
  - 不选直接输出的原因：数值错放校验查不出（静默数据错误）；来源区域靠 LLM 自报，影响坐标评估；输出量随表增大、大表要分段；
    仍需代码打包；无法保留原始结构。
  - 本选择的局限：封闭类型集合之外的理解表达不了（只适用于部分行的注释、缩写含义、写在别处的单位等），这些表格的块退回规则序列化的效果；
    LLM 标错只影响重复范围，不影响文字。

## 第 7 轮（2026-10-19）—— 引导句、摘要的长度限制
