# V3.13 提示词草稿（待审）

三份提示词：序列化、引导句、摘要。每份分 system 与 user 两部分，`{...}` 为代码填入的内容。提示词用英文写：输出语言要求与文档一致（西班牙文或英文），中文提示词容易把输出带成中文。每份后面附中文说明，供审核。

三份共用的输入块：

```
<context>
Section heading: {最近的标题节点，没有则写 (none)}
Text before the table: {紧挨表格之前的正文或列表节点，没有则写 (none)}
</context>

<table>
{表格网格 JSON：每格一项}
</table>
```

表格网格每格一项，按行、列排序：

```json
{"id": "c17", "row": 3, "col": 0, "rowspan": 1, "colspan": 11, "text": "ITEM 1: SINGLE PHASE METER 2 WIRES - MODEL HXE12ES"}
```

`id` 是本表内的短编号，由代码映射回单元格 ID；空格也列出（`text` 为空串），让 LLM 看到完整网格。

## 1. 序列化

### system

```
You convert a table extracted from a PDF into self-contained records for a retrieval index.
Each record will be embedded and searched on its own, so a reader who sees only one record
must understand what it states without seeing the rest of the table.

Rules:
1. A record normally corresponds to one data row. Write into it everything needed to understand
   that row: the column labels (all header levels that apply), the group or section title the row
   belongs to, and the values of merged cells that cover the row.
2. Header rows and group/section title rows are not records of their own; their text goes into
   the records they govern. Decide from the meaning of the text whether a full-width row is a
   title for the rows below it or a total/summary of the rows above it. A total or summary row
   is a record of its own and states what it totals.
3. Copy every cell's text exactly as it appears, including numbers, units, codes, dates and
   their punctuation. Do not compute, convert, round, translate or correct values. You may only
   join words that the extraction split by a stray space.
4. Omit empty cells. Do not add information that is not in the table, except a short generic
   label for a column that has no header when its meaning is evident from the table or context.
5. List in "cells" the id of every cell whose text you used in the record, including header and
   title cells. Every non-empty cell must be used by at least one record.
6. Write in {language}. Prefer the compact form "label: value; label: value" and keep the
   original wording of labels.
7. Each record must stay under {record_max_tokens} tokens (multilingual-e5 tokenizer;
   roughly {record_max_words} words). This is a limit, not a target.
8. Group consecutive records that belong together (for example the rows under one group title)
   into one segment. Keep the original row order.

Return only JSON in this form:
{"segments": [{"records": [{"text": "...", "cells": ["c1", "c2"]}]}]}
```

```
{共用输入块}
```

### 说明

- 第 2 条是本项的核心：分组标题与合计的区分交给 LLM 按含义判断（roadmap C2）。
- 第 3 条"只允许合并被错误拆开的词"对应 Docling 把 `REQUERIMIENTO` 拆成 `REQUERIMI ENTO` 这类情况；校验时去掉全部空白再比较，所以合并后仍能通过。
- 第 4 条允许给没有表头的列补一个通用标签（如交货地址表第一列没有表头，内容是 ELSE 等公司简称）。这是唯一允许的"补充"，审核样例时请重点看是否越界。
- 第 6 条推荐"标签: 值"的紧凑写法而非完整句子：句子会多出大量虚词，占预算，BM25 也不受益。如果你希望写成句子，改这一条即可。
- `{record_max_words}` 由代码按上限的 0.6 倍粗略换算，只是给 LLM 的提示；以分词器校验为准。

## 2. 引导句

### system

```
You write one short lead sentence for a table extracted from a PDF. The sentence will be placed
at the start of every retrieval chunk cut from this table, so it must tell a reader what the
table is about and what it is part of.

Rules:
1. One sentence, in {language}, under {lead_max_tokens} tokens (multilingual-e5 tokenizer;
   roughly {lead_max_words} words).
2. Say what the table lists and, when the context shows it, which section, clause or purpose of
   the document it belongs to. Use the context to tell this table apart from similar tables.
3. Do not include any values from the table body (quantities, prices, dates). Names of the
   things listed may be mentioned only if they fit; do not enumerate them.
4. Do not invent anything that is not supported by the table or the context.

Return only JSON: {"lead": "..."}
```

- 第 2 条针对 c0004 / c0006：两表内容几乎相同，只能靠上下文说出"合同标的"与"技术规格"的区别。

## 3. 摘要

### system

```
You write a retrieval summary for a table extracted from a PDF. The summary replaces the table
in the search index: a question about anything in the table should be able to find this summary.
After it is found, the full table is shown to the reader, so the summary does not need to carry
the values themselves.

Rules:
1. In {language}, one paragraph, under {summary_max_tokens} tokens (multilingual-e5 tokenizer;
   roughly {summary_max_words} words). This is a limit, not a target.
2. State what the table is and, when the context shows it, which section, clause or purpose of
   the document it belongs to.
3. State how the table is organized: what a row is, what the columns are (with their original
   labels), and any groups or totals.
4. Name every distinct entity that appears in the table, copied exactly: companies, item numbers,
   product models, descriptions, delivery or batch names, places. If there are too many to fit,
   name the kinds and as many as fit, keeping the original order.
5. Do not list quantities, prices or dates; you may say which kinds of values the table gives.
6. Do not invent anything that is not supported by the table or the context.

Return only JSON: {"summary": "..."}
```

### user

```
{共用输入块}
```

### 说明

- 第 4 条是摘要能被找到的关键：问题里的公司名、型号、Item 编号要原样出现在摘要中，BM25 才能匹配。
- 第 5 条不列数值：一张 12 块的大表放不进一个 chunk，数值只能靠返回的整表；小表也照此处理，所以小表换成摘要后按数值提问可能变差，这是要观察的结论之一。
- PO 25-19 数量表有 4 个产品分组 × 约 9 家公司，实体可以全部列出，预计远低于 512 token。
