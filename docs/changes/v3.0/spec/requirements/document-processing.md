# 文档解析与组装需求

状态：V3.0 需求已审核通过。本文件完整定义[总需求第 4 节](../requirements.md#4-文档解析与组装)的文档语义行为；表格候选和选优公式见[表格需求](table-selection.md)，表头与文本化分别见[表头需求](table-header.md)和[表格正文需求](table-text.md)。

## 1. 目标、输入、输出与前置条件

输入为 Registry 已确定身份、内容 hash 与项目内路径的一份可打开数字型 PDF，以及已通过校验的能力组合。主解析器读取整份文档并提供有序主内容；被接入的局部提取器提供局部候选；选择器确定采用内容；必接组装器输出完整、不可变、按阅读顺序排列的语义文档与可追溯处理事实。下游 [Chunker](chunking.md) 只消费完成的语义文档，不继续补做解析决定。

主解析、候选提取和组装不得把两个不同源文件、不同 file_hash 或不同构建身份的数据混用。适配器把工具事实转换成项目公共表达；不能借统一模型虚构页码、bbox、跨度或阅读关系。原始事实、决策证据、系统最终认定内容分别保留；审核视图不能反向充当解析输入。

## 2. 纯文本主解析

PyMuPDF 按物理页顺序读取 `page.get_text("blocks", sort=True)`，按返回顺序拼接非空文本块，统一换行和整页首尾空白，保存一基物理页码。没有可用文本的 PDF 为不可处理，不调用 OCR。每页实际文字必须以可区分页边界的公共主文档表示；必接组装器在没有补充结果时保持每页正文、页次和来源，供[按页字符分块](chunking.md#10-纯文本能力的按页字符分块)。

即使统一语义模型允许表格和列表，纯文本解析也不自行造结构节点或把页内文本重新解释为表格。不得因接口统一而跨页合并或追加类型标签。

## 3. Docling 主解析

Docling 使用无 OCR、启用准确模式表格结构和 cell matching、关闭页图生成的既有选项。它提供节点阅读顺序、文本、列表、表格占位、原生结构和 provenance；原始 SDK 对象不得作为下游公共输入。标题、段落、图注、表注、脚注、页眉、页脚保留；图片元素排除，独立文字图注仍保留。一个 Docling 列表组及其嵌套子列表构成完整 List，相邻独立列表不自行合并。Docling 已经形成的跨页节点保持完整并保存全部来源；不自行连接独立续表。

每个原生表格占位及原生结构应在同一主解析结果中有可验证关联。缺失 cell 页码、bbox、阅读关系或表格结构时记录缺失事实，不推断伪数据。无法形成整份主解析结果时该文档本次构建失败；不得自动改用纯文本预设。部分页面 Docling 失败尚无已确认发布政策，不提前增加“部分成功可发布”状态。

## 4. 局部提取、选优与组装

已接入的多个表格提取器从同一 PDF 获取候选，候选按固定工具和策略顺序汇集，不能按异步完成时间改变最终顺序。Docling 原生表格候选来自该文档的同一次转换，不能让版面与表格使用互相矛盾的转换事实。各页、各策略成功零表、成功有表与执行失败要区分；可继续的页级失败保留成功页候选，是否有评分组按[表格需求](table-selection.md)决定。

表格选优器同时使用主解析占位、提取候选及原 PDF 指定区域文字参照，执行准入、分组、评分和唯一 winner 判定；不得让组装器重新比较候选。每个表格占位恰好对应一个最终表格节点：可评分组用 winner 替换原生表格，未评分组使用对应 Docling 原生结构并记录原因；不重复输出原表格文字，也不把回退结果标为 winner。

组装器遍历主解析的唯一阅读顺序。普通文字与 List 保留，表格采用上述最终结构后，依次进行[表头判定](table-header.md)和[规则文本化](table-text.md)，一次性形成完整表格节点。winner 和原生回退使用相同表头及文本化规则。表格节点必须保存采用来源、关联选择证据、实际结构、表头判定、文本化正文和来源。无补充提取插件时组装器仍必接，保持主解析内容与来源语义不变。

## 5. 失败与降级

- PDF 不存在、损坏、无页、无可用内容分别保留事实；不能合并成泛化“解析失败”。无可用内容不发布空索引。
- Docling 整文转换或主文档映射失败，当前文档失败，清理本次 staging；其他文档可按批量入库规则继续，已有 active build 保留。
- 单个可选提取策略在某页失败，记录该页和策略，继续其他页、策略与工具；成功页候选仍参与选择。全部候选为空不等于主解析失败，原生表格按既有回退规则处理。
- 缺失 winner 不等于没有表格；没有可靠表头时 `undetermined` 并按行列兜底文本化，不把正常规则拒绝当异常。
- 决策引用缺失、winner 不属于组、必需原生回退缺失、组装结果不完整或不满足来源不变量时，本次文档失败，不交付给 Chunker。

## 6. 验收

同一固定 PDF 与配置下，纯文本页正文、页序和来源与历史基线一致；结构化节点阅读序、列表层级、winner/原生回退、表头、文本化正文及来源一致。测试须覆盖零表、单/多候选、工具页失败、整文主解析失败、缺失 provenance、跨页来源和同一占位重复内容禁止。构建失败时不应出现新 chunk、向量或 manifest 成功记录。
