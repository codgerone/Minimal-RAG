# 能力装配需求

状态：V3.0 需求已审核通过；逐阶段快照增补已完成一致性复审。本文件完整定义[总需求第 2 节](../requirements.md#2-能力选择与装配)的装配行为；接口/插件/绑定模型和校验过程的字段契约属于架构。

## 1. 目标、输入和输出

系统接收一份能力组合选择及该组合的参数，为当前命令形成唯一、可追踪的运行配置。接口定义职责及可接入位置；插件定义实现与参数；装配选择插件及参数。组合配置不能重写接口方向、输入输出契约或条件接入规则。

合法配置通过校验后，命令只调用本次选中的插件及其必需依赖；非法配置在打开向量库、加载模型、读取源 PDF 或修改存储前报配置错误，指出有问题的接口和原因。运行期间组合固定；chat 每轮继续使用会话建立时选中的组合。插件是否可接入由其契约与能力决定，不能只检查名称或方法签名。

## 2. 接入规则与依赖

每个插槽独立定义接入规则与数量：必接、无条件选接、条件接入；启用时 one 或 multi。one 不能接两个，multi 可以接多个但每个绑定身份必须唯一；可选未接入与接入后成功零结果、执行失败是不同事实。条件接入在装配时求值，条件为真时按该条件明确必须或允许接，条件为假时明确禁止或允许接，不得留成“按需”。

DocumentProcessor 始终接一个主解析器和一个组装器。表格提取分支可缺席；接入一个或多个表格提取器时，必须接一个表格选优器；未接提取器时选优器禁止接入。主解析器和表格提取器都消费同一份源 PDF，可按依赖关系并接；选优器依赖主解析定位和提取候选，组装器依赖主解析结果和可选的选优结果，因而串接在它们之后。组装器无论补充结果是否存在都必须运行。并接是输入依赖上的独立，不承诺实际并发。

组装器声明可消费表格结构时，必须具备表格内容准备能力，其中表头判定之后执行文本化。结构化 token Chunker 必须获得与实际 E5 Embedder 相同模型名、不可变 revision、passage 前缀和 special-token 行为的计数能力；字符 Chunker 不因此改变分块规则。所有可入库组合均必须接入产物构建与存储，并在索引发布前完成与实际接入阶段相符的可审计快照；不能按主解析器或预设名称关闭整条审核支路。

各连接只定义一次，下游从该连接取得上游输出；禁止维护可互相矛盾的两份方向事实。装配必须拒绝缺口、循环、类型不匹配、能力不足及以无约束私有载荷掩盖契约差异的组合。

## 3. 本轮预设与插件能力

纯文本等价预设：本地 PDF 发现；PyMuPDF 按页主解析；无表格提取与选优；必接组装器；按页递归字符分块；主解析原生、公共解析、完整组装和分块的必需快照及分块审核页；E5 文档/查询编码；Chroma 存储；确定性语义检索；证据问答、健康检查、恢复与评估。不伪造未接入的表格阶段文件。

结构化等价预设：本地 PDF 发现；Docling 主解析；PyMuPDF、Camelot、Docling、Unstructured 四个工具按九策略提供表格候选；现有准入、分组、评分和选优；必接组装器与表头/文本化；结构化 token 分块；上述公共必需快照及实际接入的表格提取/选优/内容准备快照和审核页；其余 E5、Chroma、检索、问答、健康及评估能力与前一预设共享契约。四工具执行不能因先得到候选而提前结束。

预设是数据选择，不运行旧系统。两份预设各有独立的 active collection、manifest、健康状态、发布恢复及评估映射。V3.0 初始最佳装配指向结构化预设；之后升级时可明确调整该指向，但仅安装新插件或保存新配置不会自动改变默认值。命令省略选择参数时使用当前最佳装配；`--config NAME` 选择已保存配置，`--configure` 交互式选择已有配置或创建新配置。旧 `--pipeline v1|v2` 不再是受支持参数。默认指向的改变不得重解释既有索引；每个已发布索引始终绑定构建配置身份。组合注册和配置文件字段由架构定义。

`NAME` 是供人选择配置的稳定名称，不是插件标识或构建指纹。系统内置并保存 `plain_text`、`structured` 两个预设名称；自定义配置在向导完成装配并通过校验后由用户输入名称。名称须非空，仅含英文字母、数字、`_` 或 `-`，在项目内按大小写不敏感规则唯一；自定义配置不得占用内置预设名称。CLI 在命名前展示已有名称，重名或非法名称要求重新输入，不覆盖已有配置。已用于建索引的配置不得以原名称改写装配；实验变体须另存新名称。名称可用于查找和展示，但索引兼容性必须按实际构建插件、规则和参数形成的构建身份判断，不得仅凭名称相同或不同推断。完整配置的查询侧差异可另存名称，而相同构建身份可复用同一物理索引。

创建配置的引导按接口依赖顺序进行。每步只列出与已选择插件、接口契约及必接下游可完成性相兼容的候选；必接接口选择插件，选接接口先决定是否接入，再选择插件，multi 接口允许在约束内选择多个。完整校验通过后才提示命名并保存；取消或失败不得留下半成品配置。已保存配置的名称、适配器组成及其索引状态应可供 CLI 查看。配置无索引与系统无任何已保存配置须分别识别，不得通过自动切换到其他索引掩盖。

本轮可入库配置指其构建侧接入完整、静态校验通过且具有建立索引所需资源的已保存配置。仅修改查询、Prompt 或展示参数的配置不应无谓复制相同物理索引；物理索引身份由构建配置决定，而命令仍记录所选完整配置。`ingest --all-configs` 的目标是所有已保存、已校验且可入库的配置，不包含向导中未保存的草稿或仅查询侧配置；每个目标独立提交或回滚，一个目标失败不阻止其他目标，但最终返回失败汇总。具体索引复用和身份规则由架构定义。

本轮只承诺两份等价预设的效果。其他配置即使满足静态接口约束，也需要数据和索引兼容检查；未验证的交叉组合不能标为正式可比较基线。新增符合现有接口契约的插件可以注册并被配置选用；若新能力需要不同的输入、判断或持久化结果，应先演进相关需求与接口。

## 4. 配置身份和影响范围

构建配置必须覆盖所有会改变解析正文、来源、候选/决策、chunk、向量及持久化输出的插件身份、规则与参数。解析器、表格规则、分块、tokenizer、embedding 模型或不可变 revision 变化都使原索引构建不兼容，须报告受影响组合并引导重建，不能拿旧向量继续查询。

查询 K、Prompt、LLM、终端显示、日志及诊断开关不触发索引重建；其中影响查询或回答的参数应记录在相应请求/评估运行中。普通代码搬移而规则及输出不变，不应单凭源码位置变化触发重建。两个向量模型即使维度相同，也不能因此被视为可互换。

## 5. 失败与验收

- 必接缺失、one 多接、条件违反、未知插件或能力不匹配时，不接触索引与源文档，返回可定位的配置错误。
- 表格分支未接入时，组装器仍输出主解析内容；接入后零 winner 时执行明确的原生回退，不将已接入分支当作不存在。
- 插件执行失败依[文档处理](document-processing.md)、[索引生命周期](index-lifecycle.md)或[运行操作](operations.md)的阶段规则处理，不在装配层悄悄切换插件。
- 固定同一预设和输入重复装配，得到相同连接、能力校验及构建身份；改变影响索引输出的参数，健康检查报告不兼容，另一组合不受影响。
- 向导对必接、选接及 multi 插槽给出正确且可完成后续装配的候选；配置未完整校验通过不得保存。改变默认指向不改变旧索引的构建身份；仅查询侧参数不同的配置不得无故重复构建相同索引。
