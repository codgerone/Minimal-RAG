## 需要你拍板的问题

2026-10-22：问题 1–4 按推荐确定；问题 4 在出题过程中修订为 10 题（2026-10-24）。2026-10-24：问题 5 按推荐（A）确定。

### 1. 规划用的模型

**结果**：规划用 `google/gemini-3.8-flash`（结构化输出 + 推理），问答模型 `google/gemini-2.5-flash-lite` 不变。

### 2. 预算按返回单元计

**结果**：预算 K 是每题返回的单元数（整表算一个单元），每档同时报每题返回 token。对比页的曲线取 K = 3–10、12、15、20；验收与归类用其中的 K = 3、6、9、12。

### 3. 每个模块的归类规则

**事实**：V3.13 中 LLM 重新生成一次文字的扰动是 1–2 题、1–2 名。

**规则**：比较最终配置与去掉该模块后的配置（与 K 无关，2026-10-26 修订）：
- 变差题数 ≤ 1 且变好题数 > 变差题数：固定启用；
- 变好题数 ≥ 1 但变差题数 ≥ 2：不在本版启用，记为 V3.15 补救阶梯的候选（只对一轮之后仍缺的子问题使用）；
- 变好题数 = 0：不采用。

变好、变差（2026-10-26 修订，原为"K = 6 下完整覆盖翻转或某证据组所需单元数减少"：以 K 为界会使结论随 K 翻转；证据组共用 excerpt 时同一变化被重复计数；不计变化幅度）：
- 同一组合中，一题的**证据单元**是返回顺序中含任一证据 chunk（任一 excerpt 的任一可接受 chunk 集合中的 chunk）的返回单元；名次是它在返回顺序中的位置。检索返回的是返回单元的排名，整表中的多个证据 chunk 是一个证据单元。
- 一题的变化量 = Σ ln(左侧名次 / 右侧名次)，对该题每个证据单元计一次；左侧为去掉该模块的配置。
- 变化量 > ln 1.5 为变好，< −ln 1.5 为变差，其余为无变化。阈值 ln 1.5 是本次实验的参数：相当于一个证据单元的名次变为原来的 2/3 或 1.5 倍，排除轮流取在第 3 名之后造成的 ±1 位移动（≤ ln(4/3)）；第 5 项得到 3 次独立生成的扰动范围后核对。

### 4. 新题数量

**结果**：在现有 5 份文档中出 10 题，数据集升为 3.3.0（34 题），见"新题与题型"。

### 5. 13 种组合上的归类规则

**事实**：基线是 13 种组合（见"评估"）。问题 3 的门槛按一种组合定出。13 种组合里返回整表 7 种、返回命中 chunk 6 种；同一返回单元下的组合高度相关（RM-T 与 LM-T 四档逐项相同），同一模块在两种返回单元下的效果可能相反。

**选项**：
- A（推荐）：在每种组合上分别按问题 3 的规则归类，取 ≥ 7 种组合给出的类别；不一致的逐组列出；另按返回整表、返回命中 chunk 两组分别报告各组的多数类别。两种返回单元使用同一份最终配置。
- B：只在一种组合上归类，其余只报告。
- C：返回整表、返回命中 chunk 各自归类（各组取多数），各得一份最终配置。

**影响**：A、B 只产生一份内置配置；C 的内置配置随 `table_return_unit` 变化，配置项增加一层。

## 模块

| 层 | 编号 | 模块 | 作用 |
|---|---|---|---|
| 第一层 | P3.1 | 分解 | 决定子问题。不开时原问题是唯一的子问题 |
| 第二层 | P3.2.1 | 改写 | 子问题的一种写法 |
| | P3.2.2 | 翻译 | 子问题的一种写法 |
| | P3.2.3 | HyDE | 子问题的一种写法 |
| | P3.2.4 | step-back | 子问题的一种写法 |
| 第三层 | P3.3 | 重排 | 在子问题内、写法融合之后重新打分 |

- 六个模块可任意组合，互不依赖：第二层不开第一层时作用于原问题；只开 P3.3 即对原问题的排名重排。
- **P3.3 搁置**（2026-10-26）：实测 bge-reranker-v2-m3 在本机 CPU 上每对（问题, 单元）约 0.8 秒（约 400 token 的 chunk；整表最长 1746 token，约 5 秒；批量不更快；本机无 GPU），一个子问题的检索范围约 18 个单元即约 15 秒，作为一次检索的延迟不可接受。先评估其余五个模块，再决定重排是否实施、如何实施。实施时用整表文本打分，截断长度取模型上限 8192（各单元都不超过）。
- 第二层的写法都由子问题原句直接生成，彼此独立，可以叠加；各写法分别检索后用 RRF 融合，与叠加的先后无关。由一种写法再生成另一种写法（如改写后的译文）不在本版。
- 原问题一路：开 P3.1 时，原问题另作一路、优先级最低。先用对照（只开 P3.1，有无原问题一路，按问题 3、5 的规则）决定保留与否，此后固定，不作为模块。对照与取舍见 [决策 014](../decisions/014-original-question-route.md)，待你决定。

## 已确定的事项

- 规划与问答分开：规划 LLM 负责分解和写出各写法；问答仍用现行提示词，只调用一次。
- 第一轮只分解问题中明说的信息项。
- 同一子问题的各写法各检索一次，用 RRF（k = 60）融合成该子问题的排名；不同子问题之间不合成一个排名。
- 跨子问题按轮流取，已入选的单元跳过。
- 检索范围由原问题按 [rules/document-filter.md](../rules/document-filter.md) 判定一次，所有子问题沿用。
- 规划与检索执行分开：检索执行的输入是一组子问题、各自的写法和检索范围，便于主项目把规划交给 Agent。
- 一次检索包括换算返回单元：检索器排出 chunk 后随即换成返回单元（返回整表时一张表只占一个位置、名次取最靠前的成员，见 [design.md](../design.md)；`-C` 下单元即 chunk），之后的融合、重排、选取都以返回单元为对象。
- 重排对子问题融合排名的前 30 个返回单元打分，每个单元取它对各写法得分的最大值；整表单元如何打分在实施重排时另行确定。
- 最终回答的正确性不在本版评估范围内。

## 新题与题型（2026-10-24 确定）

题型按检索行为划分，出题时用 RM-T、LM-T、LM+-T、LM-C、LM+-C 实测判定：

- **分解题**：原问题检索时某信息项排在 3 名之后，按信息项拆开的子问题能取到。
- **回答上的多跳**：作答要先由一段证据得出中间结论，但第二跳的证据不借助中间结论也能检索到。
- **检索多跳**：同时满足：第一跳证据用原问题或其子问题能进入前 3；第二跳证据用原问题、以及只依据问题原文写出的各种子问题都排在 3 名之后；把第一跳得出的具体值写进子问题后进入前 3。
- **隐含前提**：作答必需、问题未提的信息。
- **无答案**：`answerable: false`。

| 题 | 题型 |
|---|---|
| PO-25-19-Q005、CONTRACT-105-Q011 | 分解题 |
| PO-25-19-Q006、CONTRACT-105-Q013、CONTRACT-105-Q014 | 回答上的多跳 |
| PO-25-19-Q009 | 检索多跳，在 LM-C、LM+-C 下按判定条件实测成立；返回整表时数量表整表进入前 2。供 V3.15 使用 |
| PO-25-19-Q007、CONTRACT-105-Q012 | 隐含前提；Q007 在 LM-C、LM+-C 下同时是分解题 |
| PO-25-19-Q008、E001-602-Q003 | 无答案，不参与检索指标 |

在当前数据上，检索多跳题很难构造：文档过滤后每题的检索范围是一份文档（11–22 个返回单元）；返回整表使表内跳转不需要第二轮；第二跳要问的内容总会出现在问题里，凭常识写出的子问题就能取到。只靠第一跳得出的具体值才能找到的第二跳，主要出现在跨文档引用中（发票的"Orden de Compra 221"指向 PO 25-15），当前的检索范围规则排除了这类题；第二轮是否允许扩大检索范围记入 roadmap。

## 怎么做

### 流程

1. **检索范围**：由原问题判定。
2. **规划**（结构化输出）：拆解（P3.1 开启时）得到若干问题，否则原问题是唯一的问题；再为每个问题写出全部写法：
   - **原句**：拆解得到的问题只问一个信息项、补全省略的限定条件、问可读到的事实而不问计算结论；
   - **改写**：去掉标识编码、疑问词和赘语，写成陈述或名词短语，名称、其他编码、数字、引用的术语原样保留；
   - **翻译**：译成检索范围内与问题语言不同的每种文档语言，用该语言文档的术语，名称、编码与数字不译，去掉标识编码；
   - **HyDE**：每种文档语言写一段答案在文档中可能的样子，未知的值用方括号占位，去掉标识编码；
   - **step-back**：针对同一批文档、去掉把问题限定到单个实例（且各实例的答案写在同一处）的限定条件后的上位问题，不问一般知识，去掉标识编码。
3. **检索**：每个问题的原句与启用的写法各做一次检索，每次得到检索范围内全部返回单元的排名（混合检索内部已用 RRF 融合向量与 BM25 排名，随后换算为返回单元）。同一问题的各条排名按返回单元用 RRF 融合：得分 = Σ 1 / (60 + 名次)，60 是常数而非条数上限；融合结果仍是全部返回单元的排名，不截断。不同问题之间不融合。开 P3.3 时对融合排名的前 30 个返回单元重排（得分取该单元对本问题各条检索文本得分的最大值），不截断。开 P3.1 时原问题一路单独检索，不参与融合。每题检索次数 = 3N + N·M′ + N·M（+1 原问题一路），N 为问题数，M 为文档语言数，M′ 为需要翻译的语言数。
4. **选取**：按问题顺序轮流取各自排名的下一个单元，原问题一路排在每一圈最后；已入选的单元跳过，直到取满 K 个单元或候选取尽。K 是整个原问题返回的单元总数，不是每个问题的名额。返回顺序取到候选取尽为止，各档 K 取其前 K 个。
5. **作答**：返回单元按入选顺序交给问答 LLM，提示词不变。

### 冻结与复现

- 规划分两步，13 种组合共用：开启 P3.1 时先调用一次拆解（输入为原问题，输出为问题列表，个数不设上限）；不开启时问题列表只有原问题。问题列表（每个问题带编号）作为统一的输入交给一次写法调用，写法调用按编号返回每个问题的各写法。检索范围内的文档语言（入库时判定；未识别出编码时取全库出现的语言）与文档过滤识别出的标识编码由代码填入写法提示词。翻译译成各文档语言，问题已是该语言时跳过；HyDE 每种文档语言各一段。
- 拆解或写法输出不合格时带着问题清单重试一次；拆解仍不合格则退回原问题，写法仍不合格则该问题只用原句，都记为规划降级，单独列出。
- 提示词只描述任务本身，不写特定领域、文档类型或测试集中的例子。
- 每次 LLM 调用按（提示词版本、模型、输入）缓存在 `.rag/llm-cache/`，重跑评估不重新调用。
- 规划结果写入评估结果，逐题可查：子问题、各写法、每个返回单元来自哪个子问题和写法。
- 另做 3 次独立生成（不走缓存），得到各配置的扰动范围：某个值的扰动范围 = 4 次生成（正式一次加 3 次）中该值的最大值减最小值。对比页中变化的绝对值不超过左右两侧扰动范围之和时标灰。
- 全量运行之前，先把 CONTRACT-105-Q001、PO-25-19-Q001、CONTRACT-105-Q014、PO-25-19-Q008 四题的规划输出交你抽查。

### 全组合实验

- **配置**：P3.1、P3.2.1–P3.2.4 五个模块各取开、关，共 2⁵ = 32 种配置（全关即 V3.13；P3.3 搁置，含 P3.3 的配置不评估）；每种配置在 13 种组合上评估，K 取到 20。
- **规划只调用一次**：每题一次规划写出全部子问题和写法，各配置只选用其中一部分，因此各配置的子问题相同，差异只来自启用的模块。P3.1 关闭的配置用另一次规划（原问题本身的各写法）。每个查询文本在每份索引上的全量排名、每个（查询文本, chunk）的重排得分各算一次，供所有配置复用。
- **选取方式对照**：在最终配置上另比较每个子问题固定取前 k 个（k = 1、2、3）、全部子问题合成一个 RRF 排名，与轮流取对照。
- **归类**：按问题 3、5，在最终配置上逐个去掉模块判定。不按 32 种配置中得分最高的一种直接选定，以免在 32 题上挑中随机波动。

- RM-T 与 LM-T 四档逐项相同。

**指标**：
- 主指标：各档 K 下的完整覆盖题数，并列每题返回 token。
- 逐证据组：所需单元数，即按返回顺序第几个单元时该证据组补全；基线下等于原来的所需 K。
- 变好、变差：按问题 3 的定义（证据单元名次的变化量，与 K 无关）计题数；各档 K 下完整覆盖由否变是、由是变否的题在"逐题变化"中列出。
- 命中题数、MRR 照常列出，不作为取舍依据；轮流取时首个相关的名次含义改变，MRR 只作参考。
- 查询成本：每题 LLM 调用次数、LLM 输入输出 token 与费用、检索次数、规划 / 检索 / 重排各阶段耗时；汇总为全部题之和除以题数，另报单题最大值。同一组合左右两侧的入库成本相同，只在悬浮提示中显示。
- 分解对照：逐题列出子问题与标注信息项的对应关系，统计漏项数（没有子问题对应的信息项）、多余数（不对应任何信息项的子问题）、一问多项数；对应关系由助手逐题标注。
- V3.13 的表格证据指标（指标 1–3、覆盖全部表格证据的 K–token 曲线）衡量表格处理，不适用于本版，查询侧不计算。

### 对比页

一个页面，数据预先算好嵌入页面，由使用者在页面上选择比较的两侧。

**标签**：页面顶部左右两组勾选框，各列 P3.1、P3.2.1–P3.2.4、P3.3（含 P3.3 的配置未评估，按“未评估”标黄）。合法的标签：
- 两侧全空：显示 V3.13 基线（每格只显示一个值）；
- 左侧是右侧的真子集（右侧包含左侧的全部模块，且至少多一个）：每格显示左值、右值和变化。左侧全空即为相对 V3.13 的总效果。

其他选择不显示结果，提示不合法的原因。

**模块**：
1. **整体指标矩阵**：13 种组合各一行；列为命中题数、完整覆盖题数、MRR、每题返回 token、变好、变差、查询成本；上方选择 K（默认 3）。
2. **K–完整覆盖曲线**：13 种组合各一行；列为 K = 3、4、5、6、7、8、9、10、12、15、20。
3. **逐题变化**：选定 K 下，逐题列出各组合的完整覆盖由否变是、由是变否；可按题型筛选；展开一题可看两侧返回的单元。
4. **查询过程**：右侧配置下逐题的子问题、各写法、每个返回单元来自哪个子问题和写法，以及分解对照。
5. **扰动标注**：变化的绝对值不超过左右两侧扰动范围之和的单元格标灰。
6. **选取方式对照**：固定为最终配置，13 种组合各一行，比较轮流取、每个子问题固定取前 k 个（k = 1、2、3）、全部子问题合成一个 RRF 排名在各档 K 下的完整覆盖题数。

第 2 步生成的 `reports/compare/v3.14-baselines/`（以 RM-C 为基线比较 13 种组合）不回答本版的问题，已删除；13 种组合在四档 K 下的评估目录保留。

## 改什么

- `rag/query/`：规划（分解与写法）、写法融合、跨子问题选取、重排；检索执行与规划分开。
- 接口按替换价值划分：
  - **写法**：子问题原句、改写、翻译、HyDE、step-back 是同一类东西，用一份列表选择启用哪些；代码对它们一视同仁。
  - **跨子问题选取**：轮流取、固定名额、全局 RRF 三种实现，定义接口。
  - **规划**：现在只有 LLM 一种实现；检索执行的输入独立成型，主项目接入 Agent 时再抽象。
  - 子问题内融合（只有 RRF）、重排（开关加模型名）、分解（开关）、原问题一路（开关）用普通设置，不定义接口。
- 配置：新增查询侧设置（分解、写法列表、原问题一路、选取方式、重排、规划模型）；属于查询配置，不进指纹。
- `ask`、`chat`、`eval` 使用这套流程；`eval` 支持按预算评估（第 2 步已完成）。
- 新的对比页（上节），替换按运行并列的对比方式用于本版。
- 数据集 3.3.0：新增 10 题。
- 收尾时更新 `overview.md`、`design.md`，新增 `rules/query-planning.md`，写决策 015（各模块的归类）；roadmap 写入 V3.15（P5）与"第二轮是否扩大检索范围"。

## 不改什么

- 入库、分块、表格处理、索引、指纹；chunk 与现有索引不变，不需要重新入库。
- 文档过滤规则。
- 问答提示词。
- 不实现多轮检索（V3.15）、按句检索（P4）、对话记忆，不评估最终回答的正确性。
