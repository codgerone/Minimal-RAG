## 需要你拍板的问题

2026-10-22：前四个问题都按推荐确定。第 4 题在出题过程中修订为 10 题（2026-10-24 确定，见下文"新题与题型"）。第 5 题待定。

### 1. 规划用的模型

**事实**：问答用 `google/gemini-2.5-flash-lite`；V3.13 表格结构标注用 `google/gemini-3.8-flash`（结构化输出 + 推理），代码已支持这种调用。规划要做分解、判断材料够不够、写下一轮子问题，比作答更依赖推理。数据集 30 题左右，每题最多 3 次规划调用，费用可忽略。

**选项**：
- A（推荐）：规划用 `gemini-3.8-flash`，问答模型不变。
- B：规划也用 `gemini-2.5-flash-lite`。
- C：两者都跑，比较规划质量。

**影响**：只影响规划结果；问答模型不变，最终回答与现在可比。

### 2. 预算按返回单元计，还是按 token 计

**事实**：基线每题返回 1255 token，单题最多 2365；PO 25-19 数量表整表 4968 token，一个单元就超过 4500。按 token 设上限时，取到超限的单元要么截断整表，要么跳过它，都会改变返回整表的语义。

**选项**：
- A（推荐）：预算 B 按返回单元计，取 B = 3、6、9、12 四档，每档同时报每题返回 token，比较时把覆盖与 token 并列。
- B：预算按 token 计，下一个单元放不下就停止。

### 3. 每种变换固定启用还是作为补救的判定门槛

**事实**：V3.13 中 LLM 重新生成一次文字的扰动是 1–2 题、1–2 名。

**规则（推荐）**：在 B = 6 下，把某种变换加入第一轮，与不加相比：
- 变差题数 ≤ 1 且变好题数 > 变差题数：放进第一轮，固定启用；
- 变好题数 ≥ 1 但变差题数 ≥ 2：放进补救阶梯，只对常规检索后仍缺的子问题使用；
- 变好题数 = 0：不采用。

"变差"指完整覆盖由是变否，或某证据组在全量排名中所需的单元数增加；"变好"相反。

### 4. 新题数量

**结果**：在现有 5 份文档中出 10 题，数据集升为 3.3.0（34 题），题型见下文"新题与题型"。题目从销售运营的实际需求出发，不针对本版方法设计。无答案题不参与现有指标，只报告判断结果与轮数。

### 5. 五套基线上的归类规则

**事实**：基线由一套改为五套（见"评估"）。拍板问题 3 的门槛按一套基线、LLM 重新生成扰动 1–2 题定出；同一变换在返回整表与返回命中 chunk 下的效果可能相反。

**选项**：
- A（推荐）：在每套基线上分别按拍板问题 3 的规则归类，取多数（≥ 3 套）给出的类别；不一致的逐套列出。返回整表与返回命中 chunk 的流程使用同一份最终配置。
- B：只在 RM-T 上归类，其余四套只报告。
- C：返回整表、返回命中 chunk 各自归类，各得一份最终配置。

**影响**：A、B 只产生一份内置配置；C 的内置配置随 `table_return_unit` 变化，配置项增加一层。

## 已确定的事项（2026-10-22 讨论）

- 规划与问答分开：规划 LLM 负责分解、判断够不够、写下一轮子问题；问答仍用现行提示词，只调用一次。
- 最多 3 轮。每题 LLM 调用最多 4 次：第一轮之前规划 1 次，第一、二轮之后各判断 1 次，作答 1 次。第三轮之后不再判断，直接作答。
- 升级以子问题为单位：子问题常规检索后仍缺，下一轮按补救阶梯升级。用哪种检索由规则决定，不交给 LLM 选择。阶梯的最后一级是按句检索（P4），本版为空，升到这一级的子问题保持"缺"。
- 第一轮只分解问题中明说的信息项；隐含前提由读过材料之后的判断派生。
- 同一子问题的多种问法各检索一次，用 RRF（k = 60）融合成该子问题的排名；不同子问题之间不合成一个排名。
- 原问题单独作为一路，优先级最低；是否保留由有无对照决定。
- 跨子问题按预算轮流取，已入选的单元跳过。
- 检索范围由原问题按 [rules/document-filter.md](../rules/document-filter.md) 判定一次，所有子问题与各轮沿用。
- 规划与检索执行分开：检索执行的输入是一组子问题、各自的问法和检索范围，便于主项目把规划交给 Agent。
- 重排作为 P3.5，在每个子问题内、问法融合之后，对前 30 个 chunk 打分，每个 chunk 取它对各问法得分的最大值，再换成返回单元。
- 最终回答的正确性不在本版评估范围内。

## 新题与题型（2026-10-24 确定）

题型按检索行为划分，用三套整表基线与两套命中 chunk 基线（见"评估"）实测判定：

- **分解题**：原问题检索时某信息项排在 3 名之后，按信息项拆开的子问题能取到。
- **回答上的多跳**：作答要先由一段证据得出中间结论，但第二跳的证据不借助中间结论也能检索到。
- **检索多跳**：同时满足：第一跳证据用原问题或其子问题能进入前 3；第二跳证据用原问题、以及只依据问题原文写出的各种子问题都排在 3 名之后；把第一跳得出的具体值写进子问题后进入前 3。
- **隐含前提**：作答必需、问题未提的信息。
- **无答案**：`answerable: false`。

| 题 | 题型 |
|---|---|
| PO-25-19-Q005、CONTRACT-105-Q011 | 分解题 |
| PO-25-19-Q006、CONTRACT-105-Q013、CONTRACT-105-Q014 | 回答上的多跳 |
| PO-25-19-Q009 | 检索多跳，只在 LM-C、LM+-C 下成立；返回整表时数量表整表进入前 2 |
| PO-25-19-Q007、CONTRACT-105-Q012 | 隐含前提 |
| PO-25-19-Q008、E001-602-Q003 | 无答案 |

在当前数据上，检索多跳题很难构造：文档过滤后每题的检索范围是一份文档（11–22 个返回单元）；返回整表使表内跳转不需要第二轮；第二跳要问的内容总会出现在问题里，凭常识写出的子问题就能取到。只靠第一跳得出的具体值才能找到的第二跳，主要出现在跨文档引用中（发票的"Orden de Compra 221"指向 PO 25-15），当前的检索范围规则排除了这类题；第二轮是否允许扩大检索范围记入 roadmap，本版不处理。

## 目标

1. 实现可装配的查询侧流程：分解、改写、翻译、HyDE、step-back、问法融合、跨子问题选取、重排、最多 3 轮的判断与派生。每一项都能单独开关，用于消融。
2. 逐项度量 P3.1–P3.5 与 P5 在相同预算下对检索的贡献，按拍板问题 3 决定每种变换固定启用、作为补救还是不采用。
3. 度量成本：LLM 调用次数、检索次数、各阶段耗时、累计返回 token。

## 怎么做

### 流程

1. **检索范围**：由原问题判定。
2. **规划**（第一轮之前，1 次调用，结构化输出）：子问题列表；每个子问题给出启用的问法：
   - **分解原句**：只问一个信息项、补全主语与限定条件、问可检索的事实而不问计算结论；
   - **改写**：去掉标识编码和疑问、修饰成分，写成陈述或名词短语，型号、公司名、数字、原文术语原样保留；
   - **译文**：检索范围内每种文档语言一份（语言取入库时判定的文档语言），用该类文档的术语，实体与数字不译；
   - **HyDE**：用文档语言、按文档体裁写出答案所在原文可能的样子，数值用占位符；
   - **step-back**：去掉与答案组织方式无关的限定条件后的上位问题。
3. **检索**：每个（子问题, 问法）做一次混合检索，得到全量排名；子问题内 RRF 融合；启用重排时在融合后重排。原问题一路单独检索。
4. **选取**：按子问题顺序轮流取各自排名的下一个单元，原问题一路排在每一圈最后；已入选的单元跳过，直到本轮取满 B 个单元或候选取尽。
5. **判断**（第一、二轮之后，各 1 次调用，结构化输出）：读累计取回的全部单元，对每个子问题判定已找到或仍缺，写出由材料派生的新子问题，给出材料是否足够作答。足够时停止。
6. **下一轮**：只检索仍缺的子问题（按补救阶梯升级）和新子问题，本轮再取 B 个此前未返回的单元。
7. **作答**：累计单元按轮次、轮内按入选顺序交给问答 LLM，提示词不变。

### 冻结与复现

- 每次 LLM 调用按（提示词版本、模型、输入）缓存在 `.rag/llm-cache/`，重跑评估不重新调用。
- 规划结果与每轮的判断写入评估结果，评估页逐题展示：子问题、各问法、每轮新增的单元、判断结论。
- 主要结论另做 3 次独立生成（不走缓存），报告波动范围。

### 消融顺序

每一步在上一步的基础上增加一项，都只改查询设置，不重新入库：

| 步骤 | 增加 |
|---|---|
| 基线 | 原问题检索一次，K = B |
| P3.1 | 分解（每个子问题只用分解原句）+ 原问题一路 |
| P3.1′ | 去掉原问题一路（对照） |
| P3.2 | 改写 |
| P3.3 | 译文 |
| P3.4 | HyDE；step-back（各自单独加入，分别比较） |
| P3.5 | 重排 |
| P5 | 多轮判断与派生 |

另设两个选取方式的对照：每个子问题固定取前 k 个（k = 1、2、3）、全部子问题合成一个 RRF 排名。

### 组合实验（第一轮）

逐项累加的结果依赖加入的顺序，看不出两项之间的叠加或抵消，所以第一轮另做全组合实验：

- **因子**：分解、原问题一路（只在分解开启时有意义）、改写、译文、HyDE、step-back、重排，各取开、关。分解开启时 2⁶ = 64 种，关闭时（各问法作用于原问题）2⁵ = 32 种，共 96 种；每种在四档 B 下评估。
- **规划只调用一次**：每题的规划调用一次输出全部问法，各组合只选用其中一部分，因此各组合的子问题相同，差异只来自启用的问法与步骤。每个查询文本的全量排名、每个（查询文本, chunk）的重排得分各算一次，供所有组合复用。
- **报告**：
  - 主效应：某项开启的全部组合的平均完整覆盖题数，减去关闭的全部组合的平均；
  - 两两交互：两项都开 − 只开第一项 − 只开第二项 + 都不开，各取对应组合的平均；
  - 四档 B 下完整覆盖最高的 5 种组合。
- **归类**：拍板问题 3 的规则改在最终组合上逐项去掉来判定：在 B = 6 下比较最终组合与去掉该项后的组合。逐项累加只作为过程记录。不按 96 种组合中得分最高的一种直接选定，以免在 24 题上挑中随机波动。
- 多轮（P5）不做全组合，只在第一轮最终组合上评估。

## 评估

**基线**：五套，都是混合检索、过滤开启、用原问题检索一次、K = B，数据集 3.3.0 上先重跑：

| 名称 | 配置 | 返回单元 |
|---|---|---|
| RM-T | structured | 整表 |
| LM-T | structured_llm | 整表 |
| LM+-T | structured_llm_lead | 整表 |
| LM-C | structured_llm | 命中的 chunk |
| LM+-C | structured_llm_lead | 命中的 chunk |

消融、组合实验、多轮都在五套基线上分别进行。

**返回集合**：一题最终返回的全部单元（多轮时为各轮的并集），记为 H，现有指标的定义不变（[rules/evaluation.md](../rules/evaluation.md)），K 换成 B。多轮时另报每轮结束时的完整覆盖题数。

**新增报告项**：

| 项 | 定义 |
|---|---|
| 分解对照 | 逐题列出子问题与标注信息项的对应关系，统计漏项数（没有子问题对应的信息项）、多余数（不对应任何信息项的子问题）、一问多项数；对应关系由助手逐题标注，在对比页中列出供抽查 |
| 判断对错 | 每次判断的"足够 / 不足"与当时累计单元是否完整覆盖的四格表；"判断足够但未完整覆盖"记为过早停止 |
| 无答案题 | 每题使用的轮数、是否曾判断足够 |
| 成本 | 每题 LLM 调用次数、检索次数、规划 / 检索 / 重排 / 判断各阶段耗时、累计返回 token、LLM 输入输出 token 与费用；汇总为全部题之和除以题数，另报单题最大值 |

**对比页**：`python -m rag compare` 按消融顺序并列，四档 B 分页，每档列出状态变化的题与所需单元的变化。

## 验收

1. **P3（第一轮）**：在五套基线上分别比较，最终组合在 B = 3、6、9、12 四档下完整覆盖题数都不低于该基线，且至少两档比该基线多 2 题及以上；3 次独立生成的结果都满足。各变换按拍板问题 3、5 归类。
2. **P5**：在五套基线上，与只做第一轮相比，四档完整覆盖都不降低。检索多跳题只有 PO-25-19-Q009 一道，它在 LM-C、LM+-C 下是否由第二轮补全逐题报告，作为观察项，不作为通过条件；回答上的多跳题、隐含前提题的轮数与判断、过早停止次数、无答案题的判断逐题报告，由你判断是否可以接受。
3. **13 种组合**：第一轮与多轮的最终配置用 `scripts/eval_tables.sh` 在七份现有索引上跑 13 种组合并出对比页。
4. 审核页用 Chrome 无头截图自查后再交给你。

## 改什么

- `rag/query/`：规划、问法融合、跨子问题选取、重排、多轮判断与派生；检索执行与规划分开。
- 接口按替换价值划分：
  - **问法**：分解原句、改写、译文、HyDE、step-back 是同一类东西（同一个子问题的一种写法），用一份列表选择；第一轮用哪些、补救阶梯用哪些各是一份列表。固定启用与补救的区别只在内置配置的取值，代码对它们一视同仁。
  - **跨子问题选取**：轮流取、固定名额、全局 RRF 三种实现，定义接口。
  - **规划**：现在只有 LLM 一种实现；检索执行的输入独立成型，主项目接入 Agent 时再抽象。
  - 子问题内融合（只有 RRF）、重排（开关加模型名）、分解（开关）、最大轮数用普通设置，不定义接口。
- 配置：新增查询侧设置（问法列表、补救列表、原问题一路、选取方式、预算、重排、最大轮数、规划模型）；属于查询配置，不进指纹。
- `ask`、`chat`、`eval` 使用这套流程；`eval` 支持按预算评估。`chat` 仍是每轮独立检索。
- 评估结果、评估页、对比页增加上节的报告项。
- 数据集 3.3.0：新增 10 题。
- 收尾时更新 `overview.md`、`design.md`，新增 `rules/query-planning.md`，写决策 014。

## 不改什么

- 入库、分块、表格处理、索引、指纹；chunk 与现有索引不变，不需要重新入库。
- 文档过滤规则。
- 问答提示词。
- 不实现按句检索（P4），不实现对话记忆，不评估最终回答的正确性。
