# V3.4 提案：证据映射改为按 PDF 坐标判定

状态：**待审**　｜　分支：`retrieval-opt`　｜　基线：`v3.3`　｜　日期：2026-10-08

属于"检索效果优化"主题。下一步要改表格文本的脚手架，会改变 chunk 正文；现行的自动判定（文字重合）在这类改动下不可靠，所以先把证据映射改成对任意配置都能自动、准确算出。

## 0. 已拍板的问题

| # | 问题 | 结论 |
|---|---|---|
| Q1 | chunk 的某部分内容没有来源坐标时怎么办 | **在粗略区域内用文字匹配兜底**，规则见 1.4 |
| Q2 | `eval/mappings.json` 和 `--confirm-auto` 是否保留 | **删除**，映射每次由坐标算出 |

Q1 的事实：内置工具中，已知缺细坐标的只有 `unstructured` 表格提取器的单元格（现有文档的候选表格中 596 个单元格全无坐标），它给出了整张表格的坐标框；它的单元格文字来自页面图像的 OCR，与 PDF 文字层不一定一致，所以不能在入库时用 PDF 原文反推单元格坐标。Docling 的段落、列表项在代码上允许缺坐标，现有文档中为 0 次。`unstructured` 在现有文档上从未被选中。

## 1. 已确认的规则

### 1.1 excerpt 分两类

| 类别 | 何时使用 | 写法 |
|---|---|---|
| 普通 excerpt | 默认 | 只写回答所需的原文；来自表格时只写数据单元格，**不写表头** |
| 表头 excerpt | **只在表头本身就是答案时** | 只写作为答案的表头文字，并加"表头"标记 |

- 同时需要表头和数据才能回答时，拆成一段表头 excerpt 和一段普通 excerpt，放在同一套方案里。
- 两类 excerpt 都可以跨两页。
- 表格数据 excerpt 的值在同一行的多列中重复、只靠列才能区分时，加**定位提示**：所在列的表头文字。它只用于在 PDF 上确定位置，不属于证据，不参与映射判定。

### 1.2 两类共用的坐标判定

1. 每段 excerpt 在 PDF 上定位为一组**词**，每个词有页码和坐标框。这组坐标经你确认后写入标注，与配置无关。
2. 每个 chunk 带有**来源区域**（页码 + 坐标框）：chunk 的内容来自 PDF 的哪些位置，就列出哪些区域。表格被切成多个 chunk 时，表头单元格的区域只计入该表格的第一个 chunk。
3. 一个词的坐标框中心落在 chunk 的某个来源区域内，这个词就被该 chunk 覆盖。
4. 一组 chunk 覆盖了 excerpt 的**全部**词，就是一个可接受组合；只保留最小组合。

普通 excerpt 的可接受组合就是第 4 步的结果，不做任何扩展。

### 1.3 表头 excerpt 的扩展

表格被切成多个 chunk 时，每个 chunk 都带着表头，所以该表格的每个 chunk 都应当能单独回答。对**带"表头"标记的 excerpt**，在 1.2 的结果之外再做：

1. 由 1.2 找到包含该表头的 chunk（表格的第一个 chunk）；
2. 找出与它来自同一张表格的全部其他 chunk（`parent_unit_id` 相同）；
3. **逐字核对**：对每个这样的 chunk，检查其正文是否逐字包含该 excerpt 的全部表头文字（比较前两边都去掉空白和标点、统一小写）；
4. 通过核对的 chunk，各自单独构成一个可接受组合；未通过的不收。

表格没有被切分时，第 2 步找不到其他 chunk，结果与普通 excerpt 相同。

### 1.4 缺少细坐标时的文字兜底

1. chunk 的某部分内容没有细坐标（单元格、段落级）时，这部分记为**粗略区域**：有表格坐标框时用表格坐标框，没有任何框时用整页。
2. 只有当 excerpt 的某个词没有被任何 chunk 的细坐标覆盖、又落在某个粗略区域内时，才对这个词所在的片段触发兜底；excerpt 的其余部分照常走 1.2。
3. 兜底只和粗略区域包含这个词的 chunk 比对：片段去掉空白和标点、统一小写后，在 chunk 正文中逐字出现，即被该 chunk 覆盖。片段按 ` | ` 和换行切分。
4. 一个片段在多个候选 chunk 中都出现时，用 excerpt 的"环境文字"字段（excerpt 前后的更多原文）判断属于哪一个。这个字段只在实际出现这种情况时才补，不预先填写。
5. 经兜底判定的 excerpt 在报告中标为"文字兜底"，供你抽查。
6. 兜底后仍有片段未被覆盖时，评估报错，列出这些 excerpt 和候选 chunk，由你决定是否人工给出映射（届时再设计）。

### 1.5 不变的部分

方案、证据组由 excerpt 组合推出的方式，以及各项指标的公式都不变。

## 2. 改什么

| 部分 | 改动 |
|---|---|
| 标注数据（数据集 3.0.0 → **3.1.0**） | 按 1.1 修改含表头的 excerpt；在 `eval/ground-truth/` 各文件中给每段 excerpt 加坐标字段，写入已确认的 PDF 词坐标和 excerpt 原文哈希；原文或 PDF（文件级已记录哈希）变化后坐标失效，评估报错 |
| excerpt 定位（新命令） | 在 PDF 文字层中逐段定位 excerpt：先整段查找；找不到时按 ` \| ` 和换行拆成片段，再按词查找；片段在页面上出现多次时，选与其他片段位置最紧凑的那一处。结果先进入审核文件，你确认后写入标注 |
| 定位审核文件 | 每份 PDF 生成一份副本，用**黄色高亮**标出每段 excerpt 的定位，高亮的批注写明题号和 excerpt 号；另有一个 HTML 页面，逐段 excerpt 展示：题号、excerpt 原文、所在页面的截图（只高亮这一段）。歧义或找不到的片段用红色标出，并排在最前。文件放在 `tmp/anchor-review/`，不提交 |
| chunk 来源区域（入库） | 每个分块器为 chunk 输出来源区域，写入中间结果 `chunks.json`，不写入向量库，也不写进 chunk 正文。`pymupdf_pages` 解析器补充词级坐标，供 `characters` 分块器按文字区间取用；`structured_tokens` 分块器取段落、列表项和表格单元格的坐标框。缺细坐标时记录粗略区域（1.4） |
| 判定 `rag/eval/judge.py` | 自动判定（文字重合）和已确认映射替换为第 1 节的坐标判定 |
| 删除 | `eval/mappings.json`、`eval --confirm-auto`、报告中的"自动判定"状态；映射状态改为：坐标判定 / 文字兜底 / 找不到对应 chunk |
| 文档 | `rules/evaluation.md` 的标注规则和证据判定；`design.md` 第 6 节；新增 `decisions/004-coordinate-mapping.md`（取代 001）；`overview.md` 的验收步骤和数据位置表；`eval/README.md` |

入库和检索耗时：解析器本来就要算这些坐标，入库只是多保存一些数字，检索时不读取，预计没有可察觉的变化，实施时实测。两套配置都需要用 `ingest --force` 重建，`RULES_VERSION` 提升。

## 3. 不改什么

- 题目、参考答案、信息项、方案结构不变，只改含表头的 excerpt。
- 分块方式、表格文本、检索都不变；chunk 正文与 v3.3 逐字相同。
- 表格脚手架的调整是下一个提案。

## 4. 实施顺序与验收

1. **excerpt 修改与定位**（先做，你确认后再做后续步骤）：你核对修改后的 excerpt（改前、改后并排），并用审核文件逐段检查 57 段及新拆出的 excerpt 的黄色高亮是否正确。
2. **与旧映射对照**：删除 `mappings.json` 前，对原文未修改的 excerpt，在两套配置上把坐标判定结果与其中的已确认组合逐段比较，报告一致率（分子：结果完全相同的 excerpt 数；分母：原文未修改的 excerpt 数，按配置分别统计）。每处不一致都列出原因，归为"新判定有误，需修正"或"旧映射含语义判断，按新规则应当不同"。前一类必须清零，后一类由你逐条确认。
3. 测试全部通过；两套配置的 chunk 正文哈希集合与 v3.3 相同。
4. 在数据集 3.1.0 上重跑两套配置（K=3，过滤开启），作为新基线；指标变化逐题说明原因。评估页 Chrome 截图自查后交你验收。
