# V3.11 提案：跨页续表检测与合并

状态：**待审（第 2 稿）**　｜　分支：`table-continuation`　｜　基线：`v3.10`　｜　日期：2026-10-15

属于"检索效果优化"主题，对应 roadmap 的 P2.1。Docling 按页识别表格，跨页的表格被拆成几张互不相关的表。后一页的部分没有表头，写不出列名，单元格只剩裸值；它与前表也没有关联，后续的"返回整表"（P2.2）、"表格摘要"（P2.5）都会漏掉它。本版判定续表，并把续表与前表合并成一张表，之后的表头判定、文本化、分块都按一张表处理。

已确定（第 1 稿审阅）：不做多预算配对比较；判定续表后与前表合并成一张表；判定规则单独写成 `rules/table-continuation.md`；逐证据组所需 K 推迟到 P2.2。

## 需要你拍板的问题

**Q1 位置条件的字符上限取多少？**

- 事实：本库中，表格各页相邻的 4 对表格（前一页最靠下的表、后一页最靠上的表），按 PDF 文字层统计非空白字符：

  | 前表 → 后表 | 前表以下 | 后表以上 | 列数 | 是否续表 |
  |---|---:|---:|---|---|
  | PO 25-19 p2 数量表 → p3 | 84（页脚） | 143（页眉，含"Page: 3 of 6"） | 11 / 11 | 是 |
  | PO 25-19 p1 产品表 → p2 数量表 | 957 | 174（页眉 + 节标题） | 5 / 11 | 否 |
  | PO 25-15 p1 产品表 → p2 交货表 | 465 | 148（页眉 + 节标题） | 5 / 7 | 否 |
  | 合同 p2 → p3 | 1 | 252（条款正文） | 2 / 3 | 否 |
  | 合同 p3 → p4、p4 → p5 | 2570、1288 | 791、1419 | 3/5、5/10 | 否 |

  两侧一起看，本库的续表与非续表分得很开：续表两侧为 84、143，非续表的前表以下都在 465 以上，按位置条件就能排除。页眉、页脚本身有 80–175 字符，上限要高于它。
  位置条件分不开的情况本库没有出现：前表恰好排到页底、后一页开头是带短标题的另一张新表。这时两侧字符数与"中间有一行'续表'"的续表相同，只能靠列几何、列类型和"后表没有自己的表头"三条区分。
- 选项：A（推荐）每侧 300 字符，给更长的信头留余量，本库所有非续表仍被排除（最小 465）；B 每侧 200 字符，更严，信头稍长的文档会漏判。
- 影响：上限过小会漏判续表；过大则可能放进前表以下有一段短正文的表格对，交给后三条检查。

**Q2 续表重复印了前表表头时，怎么处理？**

- 事实：本库没有这种情况。后表认出了自己的表头，按第 4 条就不判为续表。
- 选项：A（推荐）本版不处理，写进已知限制，遇到实际文档再做；B 本版处理：后表顶部各行的文字与前表表头逐格相同时，去掉这几行再合并。
- 影响：选 A 时，重复印表头的跨页表仍是两张表，但两张都有表头，各自都写得出列名，损失只在"整表"不完整。

**Q3 要不要补几份含跨页表格的 PDF 用于检查判定？**

本库只有 1 个正例，规则的各条件只能靠构造的单元测试覆盖。如果你手上有含跨页表格的 PDF（尤其是重复印表头、中间有"续表"字样、页眉较长的），放进 `documents/` 后只看入库审核页，不加评估题。

## 改什么

### 1. 在架构中的位置

```
采用各表格位置的表格（选优胜者或 Docling 原生）─→ 续表检测与合并 ─→ 表头判定 ─→ TableFormatter ─→ Chunker
```

- 现在 `prepare_tables`（`rag/ingest/tables/prepare.py`）对每个表格位置依次做"采用 → 表头判定 → 文本化"。改为三步：先采用全部表格；再做续表检测与合并（新模块 `rag/ingest/tables/continuation.py`）；最后对合并后的表判定表头、文本化。
- 续表检测需要的输入：采用后的表格、各表格在阅读顺序中的位置，以及 PDF 每页的文字层单词。文字层与选优评分用的是同一来源。
- 组装文档（`compose_document`）：一条续表链只在第一张表的位置产出一个表格节点，其余位置不再产出节点；审核页记录它们并入了哪张表。两表之间的文字节点（页眉、"续表"字样等）照常留在阅读顺序中，排在合并后的表格之后。
- 原始的选优结果和各页表格不改；续表判断单独记录，合并后的表是由判断派生的新结构。

### 2. 判定规则（写入 `rules/table-continuation.md`）

对每一对相邻页：前表 A 取第 N 页最靠下的表格，后表 B 取第 N+1 页最靠上的表格。A、B 各自只在一页上。以下四条同时满足时，B 判为 A 的续表：

1. **位置**：第 N 页上中心低于 A 下边界的单词，以及第 N+1 页上中心高于 B 上边界的单词，两侧各自的非空白字符数不超过 Q1 确定的上限。统计 PDF 文字层的全部单词，不区分页眉、页脚、正文，所以不受 Docling 判错节点类型、页码变化的影响，也容许两表之间有少量文字。
2. **列几何**：列数相同，且每列的左、右边界相差都不超过 2 pt。列边界取该列只占一列的单元格的左边界最小值、右边界最大值；有任何一列取不到时，不判为续表。
3. **列类型一致**：沿用表头判定的类型词法（文字、货币金额、其他数字、日期）和取样规则：汇总、分节行整行跳过，横向合并格不取样，空格和占位符跳过。A 取表身最后至多 8 行，B 取最前至多 8 行，各自得出每列的稳定类型。对两边都稳定的列，稳定类型必须有交集；有一列没有交集，就不是续表。两边都稳定的列一个也没有时，这一条不否决。
4. **后表没有自己的表头**：B 单独做表头判定，结论不是"已认出"。

续表可以连成链（B 续 A，C 续 B），整条链合并成一张表。

第 3 条只用来否决，不要求有列支持。原因：续表常有大片空格（如 PO 25-19 各批次数量列），全文字的表也没有稳定类型；要求支持会漏判。它防的是列数和列宽恰好相同、内容却不同的两张表。

本库中，只有 PO 25-19 p2 → p3 满足第 1、2 条，其余表格对都在列数上被排除。第 3、4 条没有本库的反例可检验，只能靠单元测试。

### 3. 合并

- B 的各行接在 A 的各行之后，列按序号对齐；单元格保留各自的文字和坐标。单元格要记录自己所在的页（现在只有表格级的页码），chunk 的来源区域据此按单元格所在页推出。
- 跨页处不合并单元格：前页最后一行和后页第一行各自独立；纵向合并格不跨页延续。
- 合并后的表按一张表做表头判定、文本化和分块，规则都不变。续表各行因此带上列名；前表最后一块可能接上续表的前几行，分界移动只发生在这张表内部。
- 合并后的表格记录它由哪几张表组成；"整表"天然包含续表，P2.2 不需另做关联。

### 4. 审核页

入库审核页的表格页列出每对相邻页表格的判定：四条条件各自的实际值（两侧字符数、列数与列边界最大差、各列稳定类型、后表的表头结论），以及结论和不满足的条件。合并后的表标出由哪几页的哪几张表组成。

### 5. 其他

- 提升 `RULES_VERSION`，两套装配都 `ingest --force`。plain_text 的 chunk 预期不变。
- `overview.md`：从"不做什么"中删去"跨页表格拼接"，"两份内置装配"的表格一栏加上"跨页续表合并"；"已知限制"写入本版不处理的情况。
- `design.md` 数据主链加入"续表合并"；`rules/table-selection.md` 已知限制中"跨页表格不做拼接"改为指向新规则。

## 不改什么

- 表格提取、选优、表头判定、文本化、分块的规则本身。
- 检索与问答。
- 合并单元格的含义：续表第一行（ELPU，Item 3）属于前页的"ITEM 3"分组。合并后它和分组标题在同一张表里，但分组标题仍不写进各行，留给 P2.2 / P2.3。
- 评估：本版不新增"逐证据组所需 K"。

## 已知限制（拟写入规则文档）

- 后表重复印了前表表头时不判为续表（取决于 Q2）。
- 一行内容被分页切开（单元格文字跨页）时不拼接，两半各成一行。
- 第 N 页有多张表时只看最靠下的一张，第 N+1 页只看最靠上的一张。
- 字符上限、2 pt 容差只在本库 1 个正例、5 个反例上检查过，没有做校准。

## 怎么验收

1. 审核页：PO 25-19 第 2、3 页的数量表合并为一张表；其余表格对都未判为续表，且各自标出不满足的条件。
2. 单元测试：构造的表格对覆盖正例、四条条件各自单独不满足的反例、续表链、两表之间有短文字、页码不同的页眉。
3. chunk 对比：PO 25-19 数量表以外，两套装配的 chunk 与 V3.10 逐字相同；合并后数量表各块的每一行都带列名；来源区域按单元格所在页落在第 2、3 页，没有"文字兜底"。
4. 评估：structured（混合检索、K=3）跑一次，与 V3.10 对比，确认没有异常变化。不以指标升降作为验收依据。
5. `pytest` 全部通过。
