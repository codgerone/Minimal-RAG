# V3.11 提案：跨页续表检测与合并

状态：**待审（第 3 稿）**　｜　分支：`table-continuation`　｜　基线：`v3.10`　｜　日期：2026-10-15

属于"检索效果优化"主题，对应 roadmap 的 P2.1。Docling 按页识别表格，跨页的表格被拆成几张互不相关的表。后一页的部分没有表头，写不出列名，单元格只剩裸值；它与前表也没有关联，后续的"返回整表"（P2.2）、"表格摘要"（P2.5）都会漏掉它。本版判定续表，并把续表与前表合并成一张表，之后的表头判定、文本化、分块都按一张表处理。

已确定：
- 不做多预算配对比较；
- 判定续表后，与前表合并成一张表；
- 判定规则单独写成 `rules/table-continuation.md`；
- 逐证据组所需 K 推迟到 P2.2；
- 位置条件按坐标判定：前表在上一页正文区的末尾，后表在下一页正文区的开头。两表之间的文字只做辅助限制，每侧不超过 300 字符；
- 后表重复印了前表表头的情况，本版不处理；
- 含跨页表格的 PDF 由用户另找，找到后补充。

## 需要你拍板的问题

**Q1 "末尾 / 开头"的距离上限取多少？**

- 事实：本库中，表格各页相邻的表格对（前一页最靠下的表、后一页最靠上的表），按第 2 节第 1 条测得：

  | 前表 → 后表 | 前表下边界到正文区底 | 后表上边界到正文区顶 | 两表之间的正文 | 是否续表 |
  |---|---:|---:|---|---|
  | PO 25-19 p2 数量表 → p3 | 4 pt | 0 pt | 无 | 是 |
  | 合同 p2 → p3 | 29 pt | 69 pt | p3 表上方有条款正文 252 字符 | 否 |
  | PO 25-15 p1 产品表 → p2 交货表 | 209 pt | 30 pt | p1 表下方 381 字符；p2 有节标题"4. Delivery Date:" | 否 |
  | PO 25-19 p1 产品表 → p2 数量表 | 332 pt | 22 pt | p1 表下方 873 字符；p2 有节标题 | 否 |
  | 合同 p3 → p4、p4 → p5 | 497、326 pt | 229、334 pt | 大段正文 | 否 |

  后一页开头是"节标题 + 新表"时，后表到正文区顶只有 22–30 pt，与"一行'续表'字样 + 续表"无法区分。这时要靠前表一侧（209、332 pt）和第 2–4 条排除。
- 选项：A（推荐）36 pt，约两行正文的高度，容得下一行"续表"字样；本库的续表 4 / 0 pt 通过，合同 p2 → p3 因后表一侧 69 pt 被排除。B 24 pt，更严，容不下两表之间的文字。
- 影响：上限过小，两表之间有说明文字的续表会被漏判；过大则放进前表下方或后表上方有一两段正文的表格对，交给第 2–4 条检查。

## 改什么

### 1. 在架构中的位置

```
采用各表格位置的表格（选优胜者或 Docling 原生）─→ 续表检测与合并 ─→ 表头判定 ─→ TableFormatter ─→ Chunker
```

- 现在 `prepare_tables`（`rag/ingest/tables/prepare.py`）对每个表格位置依次做"采用 → 表头判定 → 文本化"。改为三步：先采用全部表格；再做续表检测与合并（新模块 `rag/ingest/tables/continuation.py`）；最后对合并后的表判定表头、文本化。
- 续表检测需要的输入：采用后的表格及其页码和边框，以及 PDF 每页的文字层单词。文字层与选优评分用的是同一来源（PyMuPDF）。
- 组装文档（`compose_document`）：一条续表链只在第一张表的位置产出一个表格节点，其余位置不再产出节点，审核页记录它们并入了哪张表。两表之间的文字节点（页眉、页脚、"续表"字样等）照常留在阅读顺序中，排在合并后的表格之后。
- 原始的选优结果和各页表格不改；续表判断单独记录，合并后的表是由判断派生的新结构。

### 2. 判定规则（写入 `rules/table-continuation.md`）

**页眉页脚与正文区**（只依据 PDF 文字层和坐标，不依据 Docling 的节点类型）：

- 把每页的文字层单词按行归并，表格边框内的单词不计。
- 一行同时满足以下两条，就是页眉页脚行：
  - 整行位于页面顶部或底部 20% 的高度内；
  - 文档的另一页上有一行与它位置相同（上边界相差不超过 2 pt，横向有重叠），且把数字统一替换后文字相同。页码"Page: 2 of 6"、"Page: 3 of 6"因此视为相同。
- 其余的行是正文行。
- **正文区**：全文档所有正文行和表格中，最高的上边界是正文区顶，最低的下边界是正文区底。

本库中，按此规则认出的页眉页脚行恰好是各订单的信头、信尾和合同的页码，没有正文行被误认。

**判定**：对每一对相邻页，前表 A 取第 N 页最靠下的表格，后表 B 取第 N+1 页最靠上的表格。A、B 各自只在一页上。以下四条同时满足时，B 判为 A 的续表：

1. **位置**：
   - 正文区底 − A 的下边界 ≤ Q1 确定的上限；
   - B 的上边界 − 正文区顶 ≤ 同一上限；
   - 辅助条件：第 N 页 A 以下的正文行、第 N+1 页 B 以上的正文行，两侧各自的非空白字符数不超过 300。
2. **列几何**：列数相同，且每列的左、右边界相差都不超过 2 pt。列边界取该列只占一列的单元格的左边界最小值、右边界最大值；有任何一列取不到时，不判为续表。
3. **列类型一致**：沿用表头判定的类型词法（文字、货币金额、其他数字、日期）和取样规则：汇总、分节行整行跳过，横向合并格不取样，空格和占位符跳过。A 取表身最后至多 8 行，B 取最前至多 8 行，各自得出每列的稳定类型。对两边都稳定的列，稳定类型必须有交集；有一列没有交集，就不是续表。两边都稳定的列一个也没有时，这一条不否决。
4. **后表没有自己的表头**：B 单独做表头判定，结论不是"已认出"。

续表可以连成链（B 续 A，C 续 B），整条链合并成一张表。

几点说明：
- 正文区取全文档的上下界，而不是本页最后一行文字。这样"表格之后本页留白"不会被当成"在页尾"。各页正文区顶基本一致（合同 124 pt，订单 87–101 pt）；正文区底随分页位置变化，取最低者。
- 第 3 条只用来否决，不要求有列支持。续表常有大片空格（如 PO 25-19 各批次数量列），全文字的表也没有稳定类型，要求支持会漏判；它防的是列数、列宽恰好相同但内容不同的两张表。
- 本库中，第 1 条已排除全部非续表，第 2 条又在列数上排除全部非续表。第 3、4 条在本库没有可检验的反例，只能靠单元测试。

### 3. 合并

- B 的各行接在 A 的各行之后，列按序号对齐；单元格保留各自的文字和坐标。单元格要记录自己所在的页（现在只有表格级的页码），chunk 的来源区域据此按单元格所在页推出。
- 跨页处不合并单元格：前页最后一行和后页第一行各自独立，纵向合并格不跨页延续。
- 合并后的表按一张表做表头判定、文本化和分块，规则都不变。续表各行因此带上列名；前表最后一块可能接上续表的前几行，分界移动只发生在这张表内部。
- 合并后的表格记录它由哪几张表组成；"整表"天然包含续表，P2.2 不需另做关联。

### 4. 审核页

入库审核页的表格页列出每对相邻页表格的判定：四条条件各自的实际值，以及结论和不满足的条件。
- 第 1 条：两个距离、两侧正文字符数；
- 第 2 条：列数与列边界最大差；
- 第 3 条：各列稳定类型；
- 第 4 条：后表的表头结论。

各页认出的页眉页脚行也列出，供抽查。合并后的表标出由哪几页的哪几张表组成。

## 不改什么

- 表格提取、选优、表头判定、文本化、分块的规则本身。
- 检索与问答。
- 合并单元格的含义：续表第一行（ELPU，Item 3）属于前页的"ITEM 3"分组。合并后它和分组标题在同一张表里，但分组标题仍不写进各行，留给 P2.2 / P2.3。
- 评估：本版不新增"逐证据组所需 K"。
- 页眉页脚行只用于续表判定，不改变它们在阅读顺序和分块中的处理。

## 已知限制（拟写入规则文档）

- 后表重复印了前表表头时，不判为续表。
- 一行内容被分页切开（单元格文字跨页）时不拼接，两半各成一行。
- 第 N 页有多张表时只看最靠下的一张，第 N+1 页只看最靠上的一张。
- 只有一页的文档、或页眉页脚在各页文字与位置都不同的文档，认不出页眉页脚，页眉页脚的字符计入第 1 条的辅助条件；正文区顶、底也会被它们撑大，距离条件仍然有效。
- 后一页开头是"短节标题 + 新表"时，位置条件无法与"'续表'字样 + 续表"区分，靠前表一侧和第 2–4 条排除。
- 距离上限、2 pt 容差、20% 页眉页脚带、300 字符，只在本库 1 个正例、5 个反例上检查过，没有做校准。

## 怎么验收

1. 审核页：PO 25-19 第 2、3 页的数量表合并为一张表；其余表格对都未判为续表，且各自标出不满足的条件。认出的页眉页脚行与 PDF 一致。
2. 单元测试：构造的表格对覆盖以下情况：
   - 正例；
   - 四条条件各自单独不满足的反例；
   - 表后留白的反例；
   - 续表链；
   - 两表之间有短文字；
   - 页码不同的页眉。
3. chunk 对比：PO 25-19 数量表以外，两套装配的 chunk 与 V3.10 逐字相同；合并后数量表各块的每一行都带列名；来源区域按单元格所在页落在第 2、3 页，没有"文字兜底"。
4. 评估：structured（混合检索、K=3）跑一次，与 V3.10 对比，确认没有异常变化；不以指标升降作为验收依据。
5. `pytest` 全部通过。
