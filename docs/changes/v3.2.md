## 2. 目标

问题中点名了文档编号时，只在该文档内检索，消除跨文档污染。

## 3. 改什么

1. **文档标识表** `documents/documents.toml`：放在 PDF 旁边，和 PDF 一样不进 git。每份 PDF 一项，写文件名和一个或多个编号。
   - 加载时校验：每个编号规范化后至少 4 个字符；同一编号不能登记给两份文档，否则报错。
   - 标识表登记了 `documents/` 中不存在的文件时，`status` 会给出提示，检索时忽略这一项。
2. **识别规则**（写入新文件 `docs/rules/document-filter.md`）：
   - 问题和编号都做规范化：NFKC、统一小写、只保留字母和数字；
   - 规范化后的编号是规范化后问题的子串，就算命中；
   - 命中一份或多份文档时，只在这些文档内检索；一份都没命中时，按 Q2 处理。
3. **检索**：检索接口的文档过滤从"单个文档"改为"文档集合"；确定性排序规则不变。
4. **命令**：
   - `search` / `ask` / `chat` 的输出显示本次检索范围。
   - 检索范围区分五种情况：用户指定、自动识别（列出文档）、未识别、未配置标识表、过滤已关闭。
   - `--document` 由用户显式指定，优先于自动识别。
5. **评估**：
   - 评估走与查询相同的识别和过滤流程；
   - 报告逐题显示"识别出的文档"和"证据所在文档"；
   - 新增指标"文档识别准确率" = 识别出的文档集合恰好等于证据文档集合的题数 / 可回答题数 N。
6. **配置**：`[retriever]` 新增开关 `document_filter`，内置装配设为开启。它属于查询配置，不进构建指纹。

## 4. 不改什么

- 解析、表格、分块、编码都不改，chunk 正文不变：已确认的证据映射全部沿用，不会出现"自动判定"，不需要重建索引。
- 不引入 LLM 路由、关键词或混合检索。
- 不从 PDF 内容自动抽取编号。
- 不改评估映射流程（上次讨论的逐组确认问题，等改动 chunk 正文时再提）。

## 5. 验收

1. 两份装配各运行一次 `eval`：文档识别准确率 24/24；各项指标等于第 1 节"过滤到正确文档"一行，跨文档污染为 0；"含自动判定"为 0。
2. 把 `document_filter` 设为关闭后再评估，指标与 V3.1 基线完全一致。
3. `pytest` 全部通过；新增测试覆盖识别规则、标识表校验、多文档过滤，以及检索范围的五种情况。
4. 评估报告用 Chrome 无头截图自查后再交给你。
