## 0. 已拍板的问题

| # | 问题 | 结论 |
|---|---|---|
| Q1 | 系统怎么知道问题问的是哪份文档？ | **文档标识表**：每份 PDF 登记一个或多个标识编码，问题中出现某个编码，就只在对应文档内检索。编码由用户分配，不来自 PDF 内容 |
| Q2 | 问题中没有识别出任何编码时怎么办？ | **在全库检索**，输出标明"未识别" |
| Q3 | 内置装配是否默认开启过滤？ | **开启**；开关在 `[retriever]`，属于查询配置 |

### 标识表为什么外置、为什么不写进索引

- 标识编码是用户分配的业务数据，PDF 中没有，只能来自文档以外的记录；主项目中这张表由数据库取代。
- 不写进 PDF 文件自身的元数据：那会改写原始业务文件（包括已签字文件）。
- 不写进 manifest：manifest 是入库自动生成的派生记录，每个装配一份，重建时整体重写。
- 不复制到 chunk 元数据：识别编码必须先有编码清单，即标识表本身；过滤目标是"限定到哪些文档"，chunk 已带 `document_id`。出现按文档属性（类型、客户、日期）过滤的需求时，再由入库把表中字段写入 chunk 元数据，并让标识表进入构建指纹。

## 1. 现状与预期

**事实**：

- 24 道题都点名了文档的原始编号（合同号、订单号或发票号）；正文中会引用其他文档的编号，不能用"正文出现过的编号"认文档。
- 以证据所在文档为过滤条件（识别完全正确）实测，K=3，题目为 V3.1 版本：

**局限**：所有题目都含编码，本次评估只衡量识别正确时的收益，不衡量无编码问题。

## 2. 目标

问题中出现已登记的标识编码时，只在对应文档内检索，消除跨文档污染。

## 3. 改什么

1. **文档标识表** `documents/documents.toml`（与 PDF 同目录，不进 git）。每份 PDF 一项：文件名和一个或多个编码。现有 5 份文档登记为：

   | 文件 | 编码 |
   |---|---|
   | ORDER PERU 24-12 ANDET.pdf | ORDER2025001 |
   | ORDER PERU 25-15 ANDET VF.pdf | ORDER2025002 |
   | 签字-ORDER PERU 25-19 FONAFE.pdf | ORDER2025003 |
   | Contrato N 105-2025 … HEXING ELECTRICAL (1)[R][R].pdf | CONT2025001 |
   | E001-602.pdf | INVOICE-E001-602 |

   加载时校验：编码规范化后不少于 4 个字符；同一编码不能登记给两份文档；不满足则报错。`status` 列出未登记编码的 PDF，以及登记了但不在 `documents/` 中的文件（检索时忽略该项）。
2. **识别规则**（新文件 `docs/rules/document-filter.md`）：问题和编码都做 NFKC、统一小写、只保留字母和数字；规范化后的编码是规范化后问题的子串即命中；命中的全部文档构成检索范围，一份都没有命中时在全库检索。
3. **检索**：检索接口的文档过滤由"单个文档"改为"文档集合"；确定性排序规则不变。
4. **命令**：`search` / `ask` / `chat` 输出本次检索范围，区分五种情况：用户指定（`--document`，优先于自动识别）、自动识别、未识别、未配置标识表、过滤已关闭。
5. **评估**：走与查询相同的识别和过滤流程；报告逐题显示"识别出的文档"与"证据所在文档"；新增指标"文档识别准确率" = 识别出的文档集合等于证据文档集合的题数 / 可回答题数 N。
6. **配置**：`[retriever]` 新增 `document_filter`（默认开启），不进构建指纹。
7. **标注**：每道题在原始编号后加注标识编码，写成"原始编号（标识编码）"；参考答案和证据不变；ground-truth 清单的 `dataset_version` 升为 2.1.0 并更新内容哈希。

## 4. 不改什么

- 解析、表格、分块、编码不改，chunk 正文不变：已确认的证据映射全部沿用，不重建索引。
- 不引入 LLM 路由、关键词或混合检索；不从 PDF 内容抽取编号。
- 不改评估映射流程。

## 5. 验收

1. **新基线**：题目更新后、`document_filter` 关闭，两份装配各评估一次，作为本主题的基线。
2. 开启过滤后评估：文档识别准确率 24/24；跨文档污染为 0；"含自动判定"为 0；各项指标与新基线并列给出。
3. `pytest` 全部通过；新增测试覆盖识别规则、标识表校验、多文档过滤和检索范围的五种情况。
4. 评估报告用 Chrome 无头截图自查后交付。
