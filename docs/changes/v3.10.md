# V3.10 提案：列表不再单独成块，按预算与相邻正文合并

状态：**实施完毕，按 Q1 判定无效，待定**　｜　分支：`retrieval-opt`　｜　基线：`v3.9`　｜　日期：2026-10-14

属于"检索效果优化"主题，对应 roadmap 的 P1（根因 C1）。现在 `structured_tokens` 把列表强制单独成块，列表前的引导句、条目标签留在别的 chunk：被修饰的列表项失去含义，只剩标签的短块总排在最后。本版只改列表；表格保持单独成块。

**结论**：列表合并后，按预算贪心装填使 chunk 分界整体移动。它解决了 Q004 这类"标签与列表被切开"的问题，同时把原来恰好落在同一块的证据（Q001 的买卖双方、Q007 的两条时限）切开。在 24 题上收益和损失相近，且损失来自分界位置的偶然变化，不是列表合并本身。

### 预算扰动对照实验（2026-10-15）

**目的**：判断 V3.10 的"变好 1、变差 2"是否超出 chunk 分界偶然移动带来的波动。

**做法**：在 V3.9 的代码（`main`）上只改 `max_tokens`（480、544），其他设置与 structured 相同，全量入库后评估。同时在同一份代码上按 512 重建，确认与 V3.9 基线逐题相同（已确认，指标与每题结果完全一致）。

"改变的块"指基线中在变体里找不到逐字相同 chunk 的块，基线共 95 块。

| 变体 | 改变的块 | 其中合同 | 混合 变好 / 变差 | 纯向量 变好 / 变差 | 混合 命中 / 完整覆盖 |
|---|---:|---:|---:|---:|---:|
| V3.9，480 | 17 | 6 | 1 / 1 | 1 / 1 | 22 / 18 |
| V3.9，544 | 13 | 10 | 0 / 0 | 0 / 0 | 21 / 19 |
| V3.10，512 | 56 | 17 | 1 / 2 | 1 / 3 | 20 / 18 |

- 480：CONTRACT-105-Q010 未命中 → 部分；PO-25-19-Q002（表格题，产品表的切分位置变了）完整 → 部分。
- 544：没有题改变状态，CONTRACT-105-Q001 首个相关由第 3 名升到第 2 名。

**结论**：

1. 只改预算、规则不变时，改变 13–17 块就会使 0–2 题改变状态，方向有正有负。V3.10 改变了 56 块，3 题改变状态，按改变的块数折算，翻转的比例与预算扰动相近。
2. 在这 24 题上，V3.10 的净效果（−1 题）与分界偶然移动造成的波动区分不开。Q1 的规则"变好多于变差"在这个量级上取决于 ±1 题，不能用来判断改变分块规则的改动是否有效。
3. 表格题也受分界影响（480 下的 PO-25-19-Q002），并非只有正文题。

## 0. 需要你拍板的问题

### 已确定（2026-10-14 讨论）

- 列表不再单独成块，与相邻正文按 token 预算合并，规则与正文合并相同。
- 不加"引导句与列表绑在一起"的约束：引导句靠规则（冒号结尾、标题）判定，换到更大范围的文档容易判错，可靠判定需要 LLM。
- 表格保持单独成块，不并入引导句。理由同上；放错的内容在长表格的每一块都会重复，代价比不放大。引导句并入后续"由 LLM 理解表格结构并序列化"的改造一起做，只调用一次 LLM。

### Q1 怎么判定这一版有效

**事实**：列表合并后，部分 chunk 变长、混入更多条款，可能让无关 chunk 更常进入前 3（roadmap 第 4 节 E2）；也可能让原来单独成块、恰好排前的列表块排名下降。24 题，1 题 = 4.2 个百分点。

**推荐规则**：

1. structured 的命中、完整覆盖都不低于基线（V3.9，混合检索：命中 21、完整覆盖 19），差距不超过 1 题视为持平；且"变好"题数多于"变差"题数，才算有效。
2. 纯向量检索（`--retriever semantic`）同样报告，作参考，不参与判定。
3. 有效则合并；无效则在本文记录原因，分支不合并。

（2026-10-14 确认。按此规则判定无效，但预算扰动对照实验表明它分辨不出分界偶然移动，2026-10-15 修订为 Q2。）

### Q2 修订的判定规则：多预算配对比较（2026-10-15 实施中提出）

**事实**：见"预算扰动对照实验"。规则不变、只改预算，就有 0–2 题改变状态，方向有正有负；V3.10 的净效果（−1 题）在这个波动范围内。

**做法**：structured 的两套规则各在 5 个预算下全量入库并评估，其他设置不变。

| 预算（token） | 448 | 480 | 512 | 544 | 576 |
|---|---|---|---|---|---|
| V3.9 规则（列表单独成块） | ✓ | ✓ | ✓（基线） | ✓ | ✓ |
| V3.10 规则（列表不单独成块） | ✓ | ✓ | ✓ | ✓ | ✓ |

预算取 512 上下约 12%，只移动分界，不明显改变 chunk 长度，避免混入长度效应（roadmap E2）。

**判定**（指标为混合检索的完整覆盖题数；命中、MRR、纯向量检索同样报告，不参与判定）：

1. 扰动范围 N：V3.9 在 448、480、544、576 下与 V3.9@512 的完整覆盖之差，取绝对值最大者。
2. 每个预算 b 下，Δ(b) = V3.10@b − V3.9@b。Δ > 0 记为"同向变好"，Δ < 0 记为"同向变差"。
3. 有方向性：变差的预算数减去变好的预算数 ≥ 3，或 5 个 Δ 之和 < −N，判为方向性变差，不接受，深究原因；反过来判为方向性变好，作为改进接受。
4. 其余情况视为随机扰动：按"列表与正文同类，不应单独成块"的设计理由接受，写入决策文档，注明接受依据是设计理由而非指标提升。
5. 逐题补充（不参与判定）：在至少 3 个预算下朝同一方向改变状态、且没有反向的题，记为系统性变化，写入发现。

## 1. 目标

1. 列表项与它前面的引导句、条目标签在预算内落进同一 chunk，不再产生只有一行标签的短块。
2. 预期 CONTRACT-105-Q004（各 Ítem 履约保证金的出具机构）在 K=3 内完整覆盖：第十条的 c0021–c0026（共 493 token，roadmap 2.2 已验证合并后对原问题排第 1）合并成 1 块。

## 2. 改什么

**分块（`structured_tokens`）**：按阅读顺序，把正文节点和列表项当作同一串单元合并：

1. 单元依次放入当前块，再放一个就超过上限时，当前块结束，从这个单元起开新块。正文节点之间用空行连接，列表项之间用换行连接，正文与列表项之间用空行连接。
2. 列表项是不可拆的单元：列表超过剩余预算时，在列表项之间断开。
3. 列表项有上级项时（嵌套列表），开新块的那一项前面重复它的上级项，登记为重复上下文；上级项太长放不下时，用 `〔上级项：第N项〕` 代替。这与现行规则相同，只是现在跨块的位置由合并决定。上级项指解析器给出的嵌套关系（Docling 的列表组里嵌套的子列表组），不做推断。当前 5 份文档中没有嵌套列表项，这条规则由测试覆盖。
4. 单个列表项本身就超限时，在项内切分，规则不变。
5. 表格仍然单独成块：遇到表格时，当前块结束。

**其他**：

- `RULES_VERSION` 提升为 `v3.10`；structured 需 `ingest --force` 重建（约 6 分钟）。plain_text 用 `characters` 分块，不受影响。
- `docs/rules/chunking.md` 按上述规则改写列表部分。
- 实施后在本文"实施中的发现"里记录：
  - CONTRACT-105-Q004 第十条的实际切分结果，以及该题的覆盖情况；
  - c0004（"2.4 EL CONTRATISTA ha cumplido…"，roadmap E1 中因编码年份排前的短块）合并后的去向，以及它进入前 3 的次数；
  - 无关 chunk 进入前 3 的次数，与基线对比（E2）。

## 3. 不改什么

- 表格的分块、文本化不变；表格前后的引导句、表注不并入表格。
- 正文节点的合并、超长切分与重叠规则不变；标题仍按普通正文节点合并（标题落在块末尾的问题不在本版处理）。
- 解析器不变：列表的识别和嵌套关系仍以 Docling 的列表组为准。
- 编码器、检索器、检索范围规则、评估数据集（3.2.0）不变。
