# V4.2 提案：Word（.docx）与文件内地址（主题"文档类型扩展"之二）

状态：**已定稿，待实施（V4.1 合并后开工）**　｜　分支：从 `main` 建 `docx-parser`　｜　基线：V4.1　｜　日期：2026-11-10

主题总览、共同原则与已定事项见 [v4.1.md](v4.1.md)。

## 目标

1. `documents/` 中的 .docx 入库、检索、问答、评估。
2. 系统的"位置"从只有"页码 + 框"扩展为三种，判定规则不变：PDF 的页码 + 框，Word 的文件内地址，以及 V4.3 用的 Excel 地址。
3. 用户提供的 Word 文档加入测试集（数据集 4.2.0）。
4. 现有 PDF（含 V4.1 的扫描件）的 chunk 与指标不变。

## 改什么

### 1. 多种文件类型

- `rag/ingest/sources.py` 的发现范围改为 `.pdf`、`.docx`；V4.3 再加 `.xlsx`。`SourceDocument` 增加 `file_type`（`pdf` / `docx` / `xlsx`）。
- 其他扩展名（`.doc`、`.xls`、`.csv`、`.pptx` 等）由 `status` 列为"不支持的类型"，不入库。以 `~$` 开头的 Office 临时文件照旧忽略。
- `readable_name`：PDF 的名称规则不变；其他类型在去掉扩展名后加 `-docx` / `-xlsx`，使同名的 PDF 与 Word 不冲突。
- **配置**：`[parser]` 仍是 PDF 的解析器；新增 `[docx_parser]`（`use = "docx_native"`），V4.3 新增 `[xlsx_parser]`。一份配置没有某类型的解析器时，`status` 把该类型的文档列为"此配置不支持"，评估跳过这些文档的题，报告中写明跳过的题数。七份内置配置加 `[docx_parser]`；`plain_text` 不加。表格提取器只对 PDF 运行。

### 2. 位置体系

各阶段模型中的 `PageSpan`、`ChunkRegion`、ground-truth 的 anchor 改为带种类的位置：

| 种类 | 写法 | 用于 |
|---|---|---|
| `pdf` | 页码 + 框（现有，坐标系不变） | 数字 PDF、扫描 PDF |
| `docx` | 部件 + 块号 [+ 单元格行列 + 格内段号] + 字符区间 | Word |
| `xlsx` | 工作表名 + 行 + 列 + 字符区间（V4.3） | Excel |

**Word 地址的定义**：
- **部件**：`body`、`header<n>`、`footer<n>`（n 为该部件在 `word/` 下文件名中的序号）、`footnotes`、`endnotes`。
- **块号**：部件内按顺序给段落 `w:p` 与表格 `w:tbl` 编号，从 0 开始。内容控件 `w:sdt` 不计号，它包含的段落、表格按出现位置展开计入；空段落也计号，使块号只由文件决定。
- **表格内**：加单元格的起始行号、起始网格列号（从 0 开始，按 `w:gridCol` 网格计）与格内段号。合并单元格用起始格的地址。
- **字符区间**：针对解析器按"文字规则"（第 3 节）写出的该段文字，按 Python 字符串下标计，左闭右开。
- **编号**：自动编号生成的文字单独记为该段的 `label` 部分，不计入字符区间。

**读取地址的代码独立成模块**（`rag/ingest/docx/reader.py`）：从 .docx 读出"地址 → 文字"的单元序列。解析器与 `anchors` 共用这一模块，所以两者的地址必然一致，而且 `anchors` 不依赖配置选了哪个解析器。

**模型改动**：
- `PrimaryDocument.page_count` 对 Word 为 `None`；对 PDF 不变；V4.3 中 Excel 记工作表数。
- 元素、chunk 来源、表格单元格的位置字段接受上述三种位置。
- 中间结果、`chunks.json`、ground-truth 的 schema 版本各提升一版。读取旧版 ground-truth（只有 `pdf` 位置）时按 `pdf` 种类解释，已确认的 34 题不需要重新确认。
- 向量库元数据中的 `pages` 改为位置标签：PDF 仍写页码列表；Word 写 `第 N 块` 或 `表 N`，按出现顺序去重。凡显示页码的地方（`search`、`chunks`、评估报告、审核页）都改为显示位置标签。

### 3. Word 解析器 `docx_native`（`rag/ingest/parsers/docx_native.py`）

用 python-docx 打开文件、取部件，用 lxml 读 python-docx 没有封装的 XML。

**阅读顺序**：页眉各部件 → 正文 → 脚注 → 尾注 → 页脚各部件。页眉、页脚按节的出现顺序收集 default、first、even 三种；内容完全相同的部件只保留第一个。

**文字规则**（一个段落的文字）：
- 依次拼接各文字片段 `w:t`；`w:tab` 写成一个空格；`w:br`、`w:cr` 写成换行；`w:sym` 写成对应字符；`w:noBreakHyphen` 写成 `-`。
- **修订**：计入 `w:ins` 与 `w:moveTo` 中的文字，不计 `w:del`、`w:delText` 与 `w:moveFrom`，即"接受全部修订"后的文字。
- **域**：计入域结果（`fldChar` separate 与 end 之间的文字片段，以及 `w:fldSimple` 内的文字），不计域代码 `w:instrText`。
- **文本框**：`mc:AlternateContent` 取 `mc:Choice` 一支，不取 `mc:Fallback`（VML 副本），以免重复。文本框中的段落作为独立段落，放在锚定它的段落之后，地址为锚定段落的地址加文本框内的段号。
- 超链接内的文字照常计入。图片、图表、OLE 对象跳过，记一条警告。

**元素类型**：
- **标题**：段落样式（含继承链）或段落本身的大纲级别 `w:outlineLvl` 为 0–8，或样式为内置的 Title、Heading 1–9。不按加粗、字号推断标题。
- **列表项**：段落带编号属性 `w:numPr`（直接写在段落上，或来自样式），且不是标题。`level` 取 `w:ilvl`，`ordinal` 取编号文字；项目符号的 `ordinal` 为 `None`。
- **带编号的标题**：编号文字加一个空格放在标题文字前；位置上编号仍记为 `label` 部分。
- **目录**：样式为 TOC 1–9 的段落，以及 TOC 域结果中的段落，跳过，审核页列出跳过的段数。
- **页眉、页脚、脚注**：对应 `header`、`footer`、`footnote` 类型。批注不入库。
- 空段落（文字只含空白，且没有编号）不产生元素，但照常计块号。

**自动编号**（`rag/ingest/docx/numbering.py`）：
- 由 `numbering.xml` 的 `w:abstractNum`、`w:num` 计算。计数器按 abstractNum 与层级共享；`w:num` 带 `w:lvlOverride/w:startOverride` 时，该 num 从覆盖值起独立计数。
- 某一层级计数加 1 时，更低的层级归零（遵守 `w:lvlRestart`）；起始值取 `w:start`。
- 编号文字按 `w:lvlText` 把 `%1`…`%9` 替换为各层级当前值的格式化结果；`w:isLgl` 时各层级一律用阿拉伯数字。
- 支持的格式：decimal、decimalZero、lowerLetter、upperLetter、lowerRoman、upperRoman、chineseCounting、chineseCountingThousand、ideographTraditional、decimalEnclosedCircle、bullet、none。其他格式按 decimal 输出，并记一条警告。
- **核对**：实施时用本机 Word 把测试文档另存为 PDF，比较编号文字与 Word 显示的是否相同。这只是核对手段，不进入入库流程。

**表格**：
- 网格列数取 `w:tblGrid` 的 `w:gridCol` 数；每行先跳过 `w:gridBefore` 列，单元格占 `w:gridSpan` 列（旧式 `w:hMerge` 同样处理）。
- `w:vMerge="restart"` 开始一个纵向合并，其后同网格列上的 `w:vMerge`（continue）并入，得到 `row_span`；被并入的格的文字丢弃（Word 中应为空）。
- 格内多个段落用换行连接，格内的列表项带编号文字。
- 表中嵌表：内层表格逐行写成 `a | b | c`，作为外层单元格文字的一部分，位置为外层单元格。
- `w:tblHeader`（标题行重复）作为事实记录，表头仍按规则判定。
- 表格由解析器直接给出，标记为 `parser_exact`，跳过提取、选优与续表，从规则表头判定开始，走现有的表格结构、写法、检索文本三个环节；`TableNode.origin` 增加 `parser_exact`。

### 4. chunk 来源区域与证据判定

- **来源区域**：Word 元素的区域为它的地址加 chunk 覆盖的字符区间；表格行为该行各单元格的地址；编号文字为 `label` 部分。Word 的位置都是精确的，全部记为细区域。
- **excerpt 定位**（`anchors` 读 `.docx` 文件）：
  - 单元序列由 `reader.py` 给出，按地址顺序排列；
  - 片段的匹配、拆分、找不到的报告规则与 PDF 相同；
  - 片段出现在多处时，仍取总长最小的最小生成树。两处的距离：同一段落内为字符下标之差 × 0.01；同一表格内为行差 + 列差 × 0.25；其他情况为块号之差 + 1；不同部件之间加 1000；
  - 定位提示：同一表格中表头文字所在的网格列；
  - 写入 ground-truth：每个片段的原文、地址与字符区间。
- **判定**：片段按字符区间切成词（规范化前的空白分隔）。一个词的中间字符落在某个 chunk 同一地址的字符区间内，就被该 chunk 覆盖；单元格类地址只需地址相同。最小组合、表头 excerpt 的扩展、证据组的规则不变。

### 5. 审核页

- **入库审核页**（Word 文档）：
  - "解析"标签页按阅读顺序列出元素：类型、位置标签、文字，编号文字单独着色；跳过的目录段、图片列在页首；
  - "表格"标签页显示网格，合并单元格按跨行、跨列绘制；
  - 原有的 PDF 截图部分对 Word 文档不显示。
- **excerpt 审核文件**（`tmp/anchor-review/`）：每份 Word 文档生成一个网页，按阅读顺序渲染段落与表格，高亮各片段，并标出多处出现时选中的一处。用户打开原 Word 文件对照核对。

## 实施步骤

1. **位置体系重构**：模型、来源区域、判定、`anchors`、报告中的页码显示、向量库元数据，不改任何行为。验收：七份配置重建后，现有 PDF 的 `chunks.json` 除 schema 版本外逐字节相同，指标不变。
2. 文件类型发现、`[docx_parser]` 配置、`status` 的"不支持的类型 / 此配置不支持"。
3. `reader.py`、`numbering.py`、`docx_native`。单元测试用 python-docx 合成的文档，覆盖修订、域、文本框、多级编号、覆盖起始值、纵向合并与横向合并、嵌表、页眉页脚。
4. 入库审核页（Word）；用户提供的 Word 文档入库，用 Word 另存的 PDF 核对编号，Chrome 无头截图自查。
5. **停顿点 1**：用户对照原文件审入库审核页。
6. `anchors` 的 Word 定位与审核网页；新文档标注（流程同 V4.1 第 8 步）。
7. **停顿点 2**：用户核对题目与 excerpt 位置，然后 `--write`，数据集 4.2.0。
8. 评估：`bash scripts/eval_tables.sh v4.2`，报告按文档类型分列（加入"Word"）。
9. 收尾。

## 不改什么

- 不支持 .doc、.docm、.rtf、.odt。
- 不推断标题（只认样式与大纲级别），不识别"手动编号"的文字为列表。
- 批注、修订前的文字、域代码、图片不入库。
- 不按页组织 Word 内容，不计算页码。
- PDF 的位置、判定规则与指标不变。

## 怎么验收

1. 现有 PDF 的 `chunks.json`（除 schema 版本外）与指标不变。
2. Word 文档的入库审核页与原文件逐项一致：段落、标题、编号文字与 Word 显示相同，表格合并正确。
3. 新题入库评估，报告按文档类型分列。
4. `uv run pytest` 全部通过。
