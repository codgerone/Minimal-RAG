# V4.3 提案：Excel（.xlsx）（主题"文档类型扩展"之三）

状态：**已定稿，待实施（V4.2 合并后开工）**　｜　分支：从 `main` 建 `xlsx-parser`　｜　基线：V4.2　｜　日期：2026-11-10

主题总览、共同原则与已定事项见 [v4.1.md](v4.1.md)；位置体系与多文件类型的支持在 V4.2 完成（[v4.2.md](v4.2.md)）。

## 范围的边界

本版只处理"答案写在某几个单元格或某段文字里"的查找型问题。需要对很多行计算的问题（求和、计数、筛选、排序、分组、跨表连接）由 Text-to-SQL 或 pandas 等工具完成，规整后的表格存入数据库，属于主项目，本版不做，测试集也不收这类题。

## 目标

1. `documents/` 中的 .xlsx 入库、检索、问答、评估。
2. 写进 chunk 的是单元格的显示值（与 Excel 屏幕上看到的一致）。
3. 很长的表格不再整表返回。
4. 用户提供的 Excel 文档加入测试集（数据集 4.3.0）。
5. 现有 PDF、Word 文档的 chunk 与指标不变。

## 改什么

### 1. 读取（`rag/ingest/xlsx/reader.py`，解析器与 `anchors` 共用）

- openpyxl 3.1.5 读两遍：`data_only=True` 取缓存值；默认模式取公式，用于找出"有公式但没有缓存值"的格。不用 `read_only` 模式，因为它读不到合并单元格。
- 只遍历有值的单元格，不按 `max_row` × `max_column` 遍历（格式会把已用范围撑得很大）。
- **工作表**：按工作簿顺序读取全部工作表，包括隐藏（`hidden`）与深度隐藏（`veryHidden`）的。图表工作表跳过。
- **隐藏**：工作表状态、隐藏的行（`row_dimensions[r].hidden`）、隐藏的列（`column_dimensions` 各范围的 `hidden`）作为事实记在单元格与元素上。**照常入库**（2026-11-10 用户确定），chunk 文字中不加标记，审核页标出。
- **合并单元格**：取 `merged_cells.ranges`，值在左上角格，区域内其他格视为被占用。
- **Excel Table 对象**（`ws.tables`）：其范围直接作为一个表格区域，表头行数记为事实；表头仍按规则判定。
- 图片、图表、批注、数据验证、条件格式不入库；图片、图表各记一条警告。

### 2. 显示值（`rag/ingest/xlsx/display.py`）

单元格的显示值按单元格的数字格式写出：

| 值 | 显示值 |
|---|---|
| 空 | 空，不占用该格 |
| 文字 | 原样（富文本取纯文字） |
| 布尔 | `TRUE` / `FALSE` |
| 错误值 | 原样（如 `#N/A`） |
| 有公式、没有缓存值 | 空，记警告 `formula_without_cached_value`，审核页列出 |
| 数字、日期 | 按数字格式（下述规则） |

**数字格式**：
- 按 `;` 分成正数、负数、零、文字四节，取对应的节；带条件（`[<100]` 等）的格式按 General 写出，并记警告。
- 支持的记号：`0`、`#`、`,`（千分位）、`.`、`%`、`E+`/`E-`、引号中的文字、`\` 转义的字符、`_`（留空，写成一个空格）、`*`（重复填充，忽略）、`[$符号-区域码]`（写出符号）；颜色 `[Red]` 等忽略。末尾逗号的缩放、分数 `?/?` 按 General 写出，并记警告。
- **General**：整数不带小数；其他数字最多 11 位有效数字，去掉末尾的 0，不加千分位。
- **日期与时间**：记号 `yyyy`、`yy`、`m`、`mm`、`mmm`、`mmmm`、`d`、`dd`、`ddd`、`dddd`、`h`、`hh`、`mm`（在 `h` 之后或 `s` 之前表示分钟）、`ss`、`AM/PM`。区域码 `[$-xxxx]` 指向西班牙文、英文、中文时，月份名与星期名用该语言，否则用英文。
- **跟随系统设置的内置格式**（14 号短日期、22 号日期时间）：在 Excel 中的显示随操作系统的区域设置而变。一律写成 `yyyy-mm-dd`（22 号为 `yyyy-mm-dd hh:mm`）。**标注规则**：这类格子的 excerpt 也按这一写法照抄。
- 小数点、千分位固定为 `.` 与 `,`（openpyxl 不提供区域设置；工作簿里存的格式本身就使用这两个符号）。

### 3. 区域切分（`rag/ingest/xlsx/regions.py`）

在每个工作表上，把被占用的格（有显示值的格，以及合并区域覆盖的全部格）切成区域：
1. Excel Table 对象的范围先各自成为一个区域，它覆盖的格不参与后续切分。
2. 其余被占用的格按上下左右相邻（共用一条边）求连通区域。
3. **标题剥离**：区域顶部的行若只有一个非空格（或只有一个横跨区域全宽的合并格），从区域中剥离，成为该区域之前的标题元素；逐行重复，直到遇到不满足的行。
4. **分类**：
   - 剥离后至少 2 行、至少 2 列的区域为**表格**；
   - 只有 1 行的区域写成一段文字，各格的显示值以 ` | ` 连接；
   - 只有 1 列的区域，每格写成一段文字。
5. **阅读顺序**：工作表按工作簿顺序；工作表内，区域按左上角的行号、再按列号排列。每个工作表的第一个元素是以工作表名为文字的标题元素，位置为该工作表。
6. 区域与分类结果作为事实写入中间结果。

### 4. 解析器 `xlsx_native`（`rag/ingest/parsers/xlsx_native.py`）

- 表格交给现有的规则表头判定与表格三个环节，标记为 `parser_exact`（V4.2 已有），不经过提取、选优与续表。
- `PrimaryDocument.page_count` 记工作表数。
- **位置**：`xlsx` 种类，为工作表名 + 行 + 列（从 1 开始）+ 字符区间。字符区间只在格内文字被切开时使用。
- **配置**：`[xlsx_parser]`（`use = "xlsx_native"`），七份内置配置都加；`plain_text` 不加。

### 5. 长表格的返回上限

- 新增查询设置 `[retriever] whole_table_max_tokens`（内置默认 4000；按 multilingual-e5 分词器计数，与分块预算相同）。整表文本超过上限的表格，命中时只返回命中的 chunk，与 `table_return_unit = "chunk"` 相同。它是查询设置，改动不需要重建索引；`--whole-table-max-tokens` 可临时覆盖。
- 默认值的依据：现有索引中最大的整表为 1750 token（PO 25-19 数量表，2026-11-10 测量），4000 不改变现有文档的结果；K = 3 时最多返回约 12000 token。
- 评估：超过上限的表格按 chunk 计返回单元。报告中列出超过上限的表格及其 token 数。

### 6. 证据判定与审核页

- **excerpt 定位**（`anchors` 读 .xlsx）：
  - 单元序列由 `reader.py` 与 `display.py` 给出：每个占用的格是一个单元，文字为显示值，按工作表、行、列排序；
  - 片段规范化后与格的显示值匹配。片段可以是一格的全部或一部分（长文字格），也可以按 ` | ` 跨同一行的相邻格；
  - 片段出现在多处时，仍取总长最小的最小生成树。两处的距离：同一工作表内为行差 + 列差 × 0.25；不同工作表之间加 1000；
  - 定位提示：同一表格区域中表头文字所在的列；
  - **excerpt 照抄 Excel 屏幕上的显示值**（第 2 节的内置日期格式除外）。显示值规则若写错，定位会失败，从而把问题暴露出来。excerpt 可以来自隐藏的格。
- **判定**：一个词所在的格（同一工作表、行、列）属于某个 chunk 的区域，就被该 chunk 覆盖；长文字格再按字符区间判定。其余规则不变。
- **入库审核页**（Excel 文档）：每个工作表一个标签页，显示网格。区域按分类着色（表格、文字、标题），隐藏的行、列、工作表加斜纹，以下几类格标出：公式没有缓存值的格、显示值按 General 回退的格、合并单元格。
- **excerpt 审核文件**：同样的网格网页，高亮各片段所在的格。

## 不改什么

- 不支持 .xls、.xlsm、.xlsb、.csv、.ods。
- 不做计算型查询，不把表格存入数据库（主项目）。
- 不重新计算公式，只用缓存值。
- 不按单元格的字体、颜色、边框推断结构。
- PDF、Word 的处理与指标不变。

## 怎么验收

1. 现有 PDF、Word 文档的 `chunks.json` 与指标不变（`whole_table_max_tokens` 不影响现有表格）。
2. Excel 的入库审核页与 Excel 中看到的一致：显示值、区域、合并、隐藏标记。
3. 新题入库评估，报告按文档类型分列，列出超过返回上限的表格。
4. `uv run pytest` 全部通过。
