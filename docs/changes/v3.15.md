## 需要你拍板的问题

2026-11-02：问题 1–6 按推荐确定；问题 6 先只评估 RM-T，看结果再决定其他组合。

### 1. 兜底检索的安排

**事实**：一个问题第一次检索后仍找不到证据、又不能靠派生子问题解决时，进入兜底检索。可用的方式有往下取、改写、HyDE、step-back，以及 Q0 专有的补上翻译（见"检索方式"）。每多一轮检索，就要多一次 LLM 调用（规划用模型的中位数约 5.5 秒，要读入材料的调用可能更长）。各方式在"第一次检索后仍缺的证据"上的效果，目前没有数据。

**选项**：
- A：全部兜底方式放在该问题的第二次检索中，检索次数上限为 2；
- B：分两次，第二次检索一组、第三次检索另一组，检索次数上限为 3。

**推荐**：A、B 都做成配置，与 LLM 调用上限的各档一起实验后再定。B 的分组先不定：先跑 A，按方式记下各方式找回的证据，再据此分组。两种安排都在提示词中写明各方式适合的情形。

### 2. 兜底方式全部启用，还是由 LLM 挑选

**事实**：兜底方式的文本都在同一次调用中写出，检索本身只需几十毫秒；成本在于返回的材料会使下一次调用的输入 token 增加。由 LLM 挑选时，若效果不好，分不出是方式本身无效，还是 LLM 没有选它。

**推荐**：实验时全部启用，并按方式分别记录返回的单元。根据各方式找回证据的数据，再决定保留哪些方式、是否改由 LLM 挑选。

### 3. LLM 调用上限的实验档位

**推荐**：取 2、3、4、5 四档，上限可配置。规划提示词中不告诉 LLM 还剩几次调用，使它的规划与上限无关。这样每种兜底安排只需按上限 5 跑一次：截取到第 n 次调用之前的状态，即为上限 n 时的检索结果；最后的作答按各档的截止状态分别调用一次。

### 4. 作答与判断合并，由规划用的模型作答

**事实**：现在作答用问答模型 `google/gemini-2.5-flash-lite`，规划用 `google/gemini-3.8-flash`。LLM 判断 Q0 已可回答时，若在同一次调用中直接作答，可省掉一次调用。

**推荐**：合并。作答因此改由规划用的模型完成，作答提示词的要求（只依据材料、引用来源、保留数字与单位）并入多轮提示词。

### 5. 每次检索返回的单元数

**推荐**：每个问题、每种方式、每次检索返回 K = 3 个此前没有出现过的单元（与 V3.14 验收的 K = 3 一致），可配置。实验中统计每次调用的材料 token，若总量成为问题，再考虑在兜底结果的合并处做重排对照（"不改什么"）。

### 6. 评估的组合

**事实**：每次调用的输入取决于检索到的材料，13 种组合之间无法共用 LLM 调用。每种组合约为 32 题 × 4 次生成 × 2 种兜底安排 × 最多 5 次调用。

**推荐**：只评估默认组合 RM-T（`structured`，返回整表）；其他组合视结果再定。

## 目标

1. 实现多轮检索：问题列表、各问题的状态、按检索次数选择检索方式、调用上限与终止条件；LLM 只输出判断，状态由代码维护。
2. 度量多轮检索相对单轮的效果：每轮补回的信息项、按方式的找回情况、LLM 判断的准确性。
3. 度量成本：LLM 调用次数、耗时、每次调用的材料 token。
4. 依据实验决定兜底安排与调用上限。

## 流程

```
Q0 去编码原句检索（第 1 轮，不调用 LLM）
loop:
    第 n 次调用 LLM：读入问题列表与材料，输出判断与动作
    代码执行动作、更新状态
    若 Q0 已回答 → 本次输出已含答案，结束
    若没有待检索的问题，或调用次数已达上限 − 1 → 作答调用，结束
    第 n+1 轮检索：所有待检索的问题各自检索
```

| 步骤 | 代码 | LLM |
|---|---|---|
| 检索范围 | 由 Q0 判定一次，所有问题沿用 | — |
| 第 1 轮 | 建立问题列表（只有 Q0），用去编码原句检索 | — |
| 每次调用之前 | 组装输入：问题列表、已接受的证据、本轮新材料 | — |
| 调用 | — | 对每个需判断的问题：接受哪些单元为证据、证据说明、是否可回答、缺口类别、下一步动作；新的子问题；Q0 可回答时作答 |
| 调用之后 | 校验输出；分配编号，写入 `parent_id`；累积证据；按动作与规则更新状态；把已回答问题下面未结束的子孙问题标为放弃 | — |
| 检索 | 按每个待检索问题的检索次数选择方式，检索、去重，记录尝试 | — |
| 作答调用 | 组装输入：问题列表与全部已接受的证据 | 作答，写明未找到的部分 |

**每次调用需判断的问题**：全部未结束的问题（状态为 `judging` 或 `waiting`）。父问题是否可回答不必等子问题全部可回答，派生的子问题也可能是错的，所以等子问题的问题每次也要判断。已回答、已放弃的问题不再判断。

**主动终止**：Q0 已回答。**被动终止**：调用次数达到上限（最后一次调用只作答）。另有一种：没有待检索的问题而 Q0 未回答时，下一次调用即作答调用。终止原因写入运行记录。

## 数据结构

字段名为代码中的名称；"写入方"表示由谁产生，代码写事实，LLM 只给判断。

### 问题 `Question`

| 字段 | 含义 | 写入方 |
|---|---|---|
| `id` | `Q0`、`Q1`……按产生顺序编号 | 代码 |
| `parent_id` | 直接派生出它的问题；Q0 为空 | 代码（依据 LLM 声明的派生来源） |
| `text` | 问题文本；Q0 为原问题 | LLM（Q0 为用户） |
| `translation` | 各文档语言的译文，与问题语言相同的语言跳过；Q0 为空 | LLM，在派生它的同一次调用中写出 |
| `attempts` | 每次检索的记录（`Attempt`），按时间排列；检索次数为其条数 | 代码 |
| `evidence` | 已接受为证据的返回单元编号，按接受顺序；只增不减 | LLM 判定，代码累积 |
| `note` | 证据说了什么，一两句；每次判断时可更新 | LLM |
| `gap` | 最近一次判断为不可回答时的缺口类别（见"缺口类别"） | LLM |
| `status` | 状态（见"状态"） | 代码 |
| `abandon_reason` | 放弃的原因：`parent_answered`、`parent_withdrawn`、`withdrawn`、`exhausted` | 代码 |

返回单元编号即返回单元的标识：整表为表格编号，其余为 chunk 编号。

### 尝试 `Attempt`

| 字段 | 含义 |
|---|---|
| `round` | 全局检索轮次：第 1 轮在第一次调用之前，第 n+1 轮在第 n 次调用之后。该问题自身的第几次检索由它在 `attempts` 中的位置得出 |
| `mode` | 检索方式（见"检索方式"） |
| `queries` | 实际检索的各段文本（已去编码），每段一条排名 |
| `units` | 本次交给 LLM 的返回单元：编号、来自哪段文本、在该段排名中的名次 |
| `cursor` | 每段排名已取到的名次，供往下取接着取 |

`units` 记录返回了什么，`evidence` 记录 LLM 接受了什么，两者分开：返回的单元不一定被接受；被接受的单元可以来自任何问题的返回，只要它在本次调用之前已交给 LLM。

### LLM 的输出

每次规划调用输出一个结构化对象：

- `judgements`：每个需判断的问题一条：
  - `id`；
  - `accept`：新接受的单元编号；
  - `note`；
  - `answerable`：是 / 否；
  - `gap`：不可回答时的缺口类别；
  - `action`：不可回答时的下一步，取值为：
    - `wait`：继续等子问题；只用于还有未结束子问题的问题；
    - `retry`：再检索本问题，并写出兜底方式所需的文本；
    - `derive`：派生子问题；
    - `withdraw`：撤回，并写明理由；Q0 不可撤回。
- `new_questions`：每个新问题一条：派生来源 `parent_id`、`text`、`translation`。
- `answer`：Q0 可回答时的答案，否则为空。

作答调用只输出 `answer`。

**校验**：
- 引用的问题编号必须存在；
- 接受的单元必须已交给过 LLM；
- 需判断的问题每个恰好一条判断；
- 不可回答时必须给出动作；
- `retry` 只能用于还有检索方式可用的问题，`wait` 只能用于还有未结束子问题的问题；
- Q0 可回答时必须有答案。

不合格时带着问题清单重试一次；仍不合格则本次调用记为降级：已通过校验的判断照常执行，其余问题保持原状态，单独列出。

### 运行记录

一次问答的结果：

- 问题列表的最终状态；
- 每次调用的输入 token、输出 token、耗时、是否降级，以及调用后的问题列表快照；
- 终止原因；
- 答案。

每次调用按（提示词版本、模型、输入）缓存在 `.rag/llm-cache/`。

## 状态

| 状态 | 含义 |
|---|---|
| `pending` | 待检索：下一轮检索它 |
| `judging` | 已检索，等待下一次调用判断 |
| `waiting` | 有未结束的子问题，本问题不检索；每次调用仍判断它 |
| `answered` | 已回答 |
| `abandoned` | 放弃，原因见 `abandon_reason` |

**转移规则**：
- 新问题为 `pending`。检索后为 `judging`。
- 判断为可回答 → `answered`。
- `retry` → `pending`。下一次检索的方式由检索次数决定。
- `derive` → `waiting`，新问题为 `pending`。
- `wait` → `waiting`。
- `withdraw` → `abandoned`（`withdrawn`）。可撤回任何未结束的非 Q0 问题，包括本轮没有检索的问题；适用于 LLM 发现问题规划错了或是多余的。它下面未结束的子孙问题由代码标为 `abandoned`（`parent_withdrawn`）。
- 判断为不可回答、检索方式已用尽、又不派生子问题、也没有未结束的子问题 → `abandoned`（`exhausted`）；还有未结束的子问题时 → `waiting`。系统无法事先知道文档中有没有答案，因此除了已回答和撤回，一个问题只有在用尽全部检索方式后才放弃。
- 一个问题变为 `answered` 后，它下面未结束的子孙问题由代码标为 `abandoned`（`parent_answered`），不再检索。
- 有未结束子问题的问题（`judging` 或 `waiting`）不可回答时，可 `wait`、`retry`（检索方式未用尽时，父问题与子问题同时检索）、`derive`、`withdraw`。子问题已全部结束、又不能 `retry` 或 `derive` 时 → `abandoned`（`exhausted`）。

## 缺口类别

LLM 判断问题不可回答时给出类别。提示词按类别说明对应的动作：

| 类别 | 含义 | 动作 |
|---|---|---|
| `not_found` | 没找到答案 | `retry` |
| `needs_basis` | 答案要由材料计算或推理得出，依据尚未找到 | `derive`：问计算或推理所依据的事实 |
| `needs_lead` | 下一步检索要依据已找到的线索（多跳、材料中才出现的前提） | `derive`：把线索写进新问题 |
| `partial` | 只找到一部分 | `derive`：只问缺的部分 |

## 检索方式

一个问题第 i 次检索的方式由 i 决定：

| 检索次数 | 新问题 | Q0 |
|---|---|---|
| 第 1 次 | 原句 + 翻译，RRF 融合 | 去编码原句 |
| 兜底（安排 A：第 2 次；安排 B：第 2、3 次各一组） | 下表各方式 | 下表各方式，另加补上翻译 |

| 兜底方式 | 文本 | 说明 |
|---|---|---|
| `continue`（往下取） | 不需要 | 在第 1 次检索的排名中接着往下取 |
| `rewrite` | LLM 依据已读到的材料写，问题语言与各文档语言各一段 | 用材料中的说法重新问，补上限定条件 |
| `hyde` | LLM 依据已读到的材料写 | 按材料的格式写答案可能的样子，未知的值用方括号占位 |
| `step_back` | LLM 写，问题语言与各文档语言各一段 | 去掉把问题限定到单个实例的条件，找对各实例统一的规定 |
| `translation`（只用于 Q0） | LLM 写 | Q0 第 1 次检索不翻译，兜底时补上 |

- 每段文本都先去掉 Q0 识别出的编码，再各自检索一次，得到一条排名。一种方式有几段文本时（按语言），各段的排名用 RRF 融合，作为这种方式的排名；问题已是某种文档语言时，该语言不另写。不同方式之间不融合，各自返回。
- 每种方式返回 K 个单元，跳过本次运行中已交给过 LLM 的单元。
- 第 1 次检索中，新问题的原句与译文各检索一次后 RRF 融合。
- 不同问题的返回不合并、不轮流取。同一单元在一次调用的材料中只出现一次，并标出它是哪些问题、哪种方式返回的。

## 交给 LLM 的输入

每次调用都是独立的，不带对话历史：LLM 不需要记忆，跨调用要保留的信息都在问题列表中（包括 LLM 自己写下的 `note`），由代码在每次调用时重新写入输入。

**单元表**：代码在一次运行中维护单元编号 → 单元的表，记下单元的文本、所属文档与页码、由哪些问题的哪次尝试返回、是否已交给 LLM、被哪些问题接受。证据在问题中只存编号，组装输入时由单元表换成文本。

每次规划调用的输入：

1. 问题列表：每个问题的 `id`、`parent_id`、`text`、`status`、`note`、检索次数、已用过的方式；
2. 已接受的证据：全部问题已接受的单元的文本，各出现一次，并标出编号、文档、页码、属于哪些问题；
3. 本轮新材料：本轮返回、此前没有交给过 LLM 的单元的文本，各出现一次，并标出编号、文档、页码、由哪些问题的哪种方式返回；
4. 需判断的问题清单。

作答调用的输入是问题列表与全部已接受证据的文本。

此前交给过但未被接受的单元不再出现，也不会再被检索返回。

提示词只描述任务本身，不写特定领域、文档类型或测试集中的例子。

## 评估

题目沿用数据集 3.4.1：32 道可回答题，加无答案题。

**展示序列**：一次运行中交给 LLM 的单元，按第一次交给 LLM 的先后排列。同一轮内，先按问题编号，再按方式，再按名次。

指标：

1. **按轮的覆盖**：信息项的凑齐名次按 V3.14 问题 3 的定义，在展示序列上计算；另记每个信息项在第几轮凑齐。逐题列出。
2. **与单轮比较**：与单轮检索比较：基线为 V3.14 的默认配置（与 V3.13 相同，原问题检索一次）；另列 V3.14 实测最好的单轮配置（去编码 + 原句 + 译文 RRF，决策 015）作参考。单轮按与多轮相同的返回 token 截取，看完整覆盖与各信息项是否凑齐；再按 V3.14 问题 3 的支配关系，比较两条序列的凑齐向量。
3. **判断的准确性**：
   - 已接受证据的覆盖：每个信息项的证据是否在已接受的单元中凑齐；
   - 误判可回答：Q0 判为可回答，但有信息项未在已接受的单元中凑齐。这是最危险的错误，逐题列出；
   - 证据被拒：凑齐所需的单元交给过 LLM 却未被接受，逐题列出；
   - 撤回的问题逐条列出，供核对是否撤回得对。
4. **按方式的找回**：兜底检索中，每种方式首次交出了哪些信息项的证据，以及其中被接受的部分。往下取作为基线：一种方式只有找回往下取找不回的证据，才算有贡献。
5. **无答案题**：调用次数、终止原因，是否误判为可回答。
6. **成本**：每题 LLM 调用次数、耗时、每次调用的输入 token。检索次数与耗时另报。

随机性：4 次独立生成（缓存隔离），判定稳定与否按 V3.14 的做法。

答案逐题保存。最终回答的正确性不在本版评估（roadmap 的端到端问答评估）。

审核页另出，结论先行。

## 改什么

- `rag/query/`：新增多轮检索：问题列表与状态规则、调用的输入组装与输出校验、各检索方式、运行记录。复用 V3.14 的检索、RRF 融合、去编码与返回单元。
- 新的多轮提示词（规划与判断一次，作答一次），单独编号版本。
- 配置 `[multi_round]`。
- `ask`、`eval` 可选用多轮检索。
- 评估：展示序列上的凑齐计算、上述指标与审核页。

## 不改什么

- 入库、分块、表格处理、索引、指纹；不需要重新入库。
- 文档过滤规则；BM25 权重（α = 1，决策 017）。
- 不加重排。若材料总量成为问题，再在兜底结果的合并处做对照实验。
- 不做按句检索（P4）；它要改入库，等 P4 完成后再作为一种兜底方式接入。
- 不评估最终回答的正确性。
