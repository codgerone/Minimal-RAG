# V4.4 提案：表格上下文（表前节点写入表格 chunk）

状态：**草案，待讨论（V4.3 合并后开工）**　｜　分支：从 `main` 建 `table-context`　｜　基线：V4.3　｜　日期：2026-11-16

来源：roadmap C1 的表格部分（CONTRACT-105-Q003 交货地点）；V4.3 讨论中发现 Excel 上同结构的多张表只靠表格上方的单格文字区分（2026-11-16 用户确定：统一改 PDF、Word、Excel，不按文档类型分两套分块器）。

## 需要你拍板的问题

1. **表前节点是否在表格的每个 chunk 中重复**
   - 事实：表格超过分块预算时切成多块，各块重复表头行（重复上下文，来源指向原单元格，计入来源区域）。返回整表时，整表文本（`grid_rows_v1`）不含表格之外的文字。决策 010 记录：挂错的内容在长表格的每一块重复。
   - 选项：A. 每块开头都写，整表文本开头也写；B. 只写在第一块，整表文本开头也写；C. 只写在第一块，整表文本不写。
   - 推荐：A。只有 A 能让长表格的后续块、整表返回时都带上区分各表的文字；挂错的代价由长度上限控制，在验收中统计。
   - 影响：A、B 改变整表库（`tables.sqlite`）的整表文本；C 只改变分块。
2. **取哪些节点、长度超限怎么办**
   - 事实：表格前的节点可能是标题、正文、列表项、caption；PDF 上标题未必被识别为标题，Word 上不带标题样式的标题是正文，Excel 上没有标题，只有工作表名。所以不按节点类型判定，只看位置与长度。
   - 共同条件：阅读顺序中位于表格之前；与表格之间没有别的表格；同一容器（Word 的页眉、正文、页脚，Excel 的同一工作表）；最多取 N 个节点；每个节点不超过 L token（multilingual-e5 分词器计数）。
   - 最紧邻的节点超过 L 时：A. 停止，一个都不取；B. 跳过它，继续往前取；C. 只取它的最后一句（句末标点切分，最后一句仍超过 L 时不取）。
   - 推荐：N = 2、L = 64，A、B、C 三种都实现为可选设置，按验收结果选定默认值。
3. **与 LLM 引导句的关系**（`[table_index_text] use = "rows_with_lead"`）
   - 选项：A. 表前节点在前、引导句在后，两者都写；B. 有引导句时不写表前节点。
   - 推荐：A。两者来源不同（原文与 LLM 生成），不互相替代；块的预算按两者之和预留。

## 目标

1. 表格的 chunk（以及按问题 1 的选择，整表文本）开头带上紧邻表格之前的短节点，PDF、Word、Excel 统一规则。
2. 被写入的节点仍按现行规则留在正文流中，与相邻正文按预算合并；表格 chunk 中的是重复上下文。

## 改什么

- 分块器 `structured_tokens`：表格块开头写入表前节点，登记为重复上下文，来源指向原节点（PDF 为原节点的坐标区域，Word、Excel 为原节点的文件内地址），计入该块的来源区域。表格块的预算预留表前节点的长度。
- 设置：`[chunker]` 下新增表前节点的个数、长度上限、超限处理三项，属于构建配置，进入构建记录；内置默认值按验收结果定。
- 整表库：按问题 1 的选择写入整表文本开头。
- 入库审核页：表格旁列出被写入的表前节点。
- 规则版本：分块步骤（以及问题 1 选 A、B 时的整表库）提升为 `v4.4`，全部文档重建。

## 不改什么

- 不判定哪个节点是"引导句"或"标题"（决策 010 的结论不变：按语义规则判定会挂错）。
- 正文与列表的合并规则不变；表格之外的分界不变。
- 检索、返回单元、查询侧不变。

## 怎么验收

1. 多预算配对比较（`rules/evaluation.md`，448–576 五档），新规则与 V4.3 规则在全部文档上配对；按文档类型（数字 PDF、扫描 PDF、Word、Excel）分列。
2. 超限处理 A、B、C 在同一预算序列下分别比较；按问题 1 选定的重复方式运行。
3. 另报：表格题与非表格题分列的完整覆盖；无关 chunk 进前 3 的次数（加长表格块会混入无关文字，roadmap 第 4 节 E2）；每题返回 token。
4. 目标题：CONTRACT-105-Q003 的交货地点；V4.3 收录的、需要靠表格上方文字区分的 Excel 题。逐题列出名次变化。
5. 抽查各类型文档中被写入的表前节点，列出挂错（与表格无关）的比例。
