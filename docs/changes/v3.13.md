# V3.13 提案：LLM 序列化表格、引导句、表格摘要（P2.3–P2.5）

状态：**提案，待审**　｜　分支：`llm-tables`　｜　基线：`v3.12`　｜　日期：2026-10-17

属于"检索效果优化"主题。把 roadmap 的 P2.3（LLM 序列化表格文本）、P2.4（引导句开关）、P2.5（表格摘要）放在一个版本里做：三者都是入库时调用 LLM 处理表格。目标不是选出唯一最优，而是弄清各组合的利弊与适用场景；多个维度都明显落后的组合淘汰。

## 需要你拍板的问题

**Q1 全量实施用哪个模型。** 样例阶段两个模型都跑：`anthropic/claude-sonnet-5.5` 与 `openai/gpt-6.1-sol`（OpenRouter 上同一价位，输入 2 美元 / 百万 token，输出 10 美元）。
- A（推荐）：样例审核时两个都合格，就两个都全量实施，LLM 的三套配置各建两份（入库时间翻倍，约多 20 分钟）；只有一个合格，只用它。
- B：样例审核后只选一个。

**Q2 引导句的长度上限 `lead_max_tokens` 的默认值。** 引导句写进该表的每个 chunk，占用每块的预算。推荐 **48**（按 multilingual-e5 分词器计，约一句 25–30 个西班牙文词）；配置可改。

**Q3 LLM 输出校验不通过时怎么办**（校验项见 2.4）。
- A（推荐）：把不通过的原因反馈给 LLM，重试一次；仍不通过，该文档入库失败并列出原因。
- B：该表退回规则序列化，记为"降级完成"，审核页标出。
- 推荐 A：本库只有 11 张表，失败时应改提示词或换模型；B 会让对比中混入规则序列化的表。

## 1. 组合与对比

表格的入库方式 3 种 × 返回方式 2 种，去掉"摘要 + 返回 chunk"（摘要不对应单元格，命中后只能返回原表），共 5 种组合：

| 编号 | 入库方式 | 返回方式 | 来源 |
|---|---|---|---|
| R-C | 规则序列化（`labeled_rows_v1`） | 命中 chunk | V3.11 |
| R-T | 规则序列化 | 整表 | V3.12（基线） |
| L-C | LLM 序列化 | 命中 chunk | 本版 |
| L-T | LLM 序列化 | 整表 | 本版 |
| S-T | LLM 摘要 | 整表（返回规则序列化的整表文本） | 本版 |

返回方式是查询配置，同一索引用 `--table-return-unit` 切换，所以 R-C/R-T、L-C/L-T 各共用一份索引。S-T 返回的整表文本与 R-T 完全相同，只换检索文本，差异只来自检索。

对比顺序：
1. **引导句**：L-C（不加）vs L-C（加），看指标 1、2、3。先做，总体更好的那组作为以下各组中的"LLM 序列化"。
2. R-C vs R-T：指标 2、3（V3.12 未报）。
3. L-C vs R-C：指标 1、2、3，重点指标 1。
4. L-C vs L-T：指标 2、3。
5. S-T vs L-C vs R-T：指标 1、2、3。
6. 5 种组合并列的总表，附各自的 K–覆盖–token 曲线。

实施中按结果可调整对比的组合，调整写进实施结果。

## 2. 改什么

### 2.1 三次 LLM 调用

三项各自独立调用，提示词见 [v3.13-prompts.md](v3.13-prompts.md)：

| 调用 | 输入 | 输出 |
|---|---|---|
| 序列化 | 表格网格（每格编号、行列、跨度、文字）+ 上下文 + 文档语言 + 单条记录的长度上限 | 记录列表：每条记录的文本与它引用的单元格，记录按语义分段 |
| 引导句 | 表格网格 + 上下文 + 文档语言 + `lead_max_tokens` | 一句话 |
| 摘要 | 表格网格 + 上下文 + 文档语言 + 摘要长度上限 | 一段摘要 |

- **上下文**：表格之前最近的一个标题节点，以及紧挨表格之前的一个正文或列表节点（按阅读顺序，不跨过其他表格）；只作为理解材料，不要求照抄。
- **语言**：与文档语言相同（取 BM25 分析器为该文档判定的语言）。
- **长度上限从配置读取**，扣掉固定开销后写进提示词：单条记录 = `max_tokens` − `passage: ` 前缀 − 引导句（开关打开时为 `lead_max_tokens`）；摘要 = `max_tokens` − 前缀。上限不是目标长度。代码用 multilingual-e5 分词器校验，超过时把实际数反馈给 LLM 重试。
- 引导句独立调用，所以加与不加引导句两套配置的序列化结果逐字相同，对比 1 只差引导句本身。

### 2.2 LLM 序列化（新的表格文本化实现 `llm_records_v1`）

- 一条**记录**是一个自足的单元：通常对应一行数据，带上它所属的分组标题、合并单元格的值和列名，不靠其他记录就能看懂。表头行、分组标题行不单独成记录，写进它们所管的记录；合计行单独成记录并写明合计什么。
- 记录按语义分**段**（如一个产品分组为一段），段内保持原表顺序。
- 记录的来源区域 = 它引用的单元格的区域并集（细区域），评估的坐标判定不变。
- 整表文本（返回整表时用）= 全部记录按顺序连接；开关打开时引导句写在最前面一次。

### 2.3 分块（`structured_tokens` 对 `llm_records_v1` 的处理）

- 按段打包：当前块放不下下一段时，结束当前块，下一段开新块；一段本身超过预算时，在记录之间切开。记录不再拆分（单条记录已受长度上限约束）。
- 每条记录自足，不再重复表头、不再补 `↑ 原值`。
- 引导句开关打开时，引导句写在该表每个 chunk 的开头，登记为重复上下文，没有来源区域（与分块器的定位说明相同）。
- 规则序列化的分块行为不变。

### 2.4 校验（序列化、引导句、摘要的输出都要通过）

1. 输出是约定格式的 JSON。
2. 序列化：引用的单元格都存在；每条记录逐字包含它引用的每个单元格的文字（比较前两边都做 NFKC、转小写、去掉全部空白）；表格的每个非空单元格至少被一条记录引用。
3. 引导句、摘要：出现的每串数字都在表格或上下文中出现过（防止编造数值）。
4. 长度不超过上限（multilingual-e5 分词器计数）。

### 2.5 表格摘要（配置 `[table_summary]`）

- 配置了 `[table_summary]` 时，每张表格（全部 11 张）不再生成表格 chunk，改为一个摘要 chunk（类型 `table_summary`），来源区域为整张表的全部单元格；整表库照常存规则序列化的整表文本。
- 摘要不被切分：超过上限即校验失败。
- 装配校验：配置了 `[table_summary]` 时，`table_return_unit` 不能是 `"chunk"`（`--table-return-unit chunk` 同样报错）。

### 2.6 LLM 结果的存放

- 每次调用的原始输出作为事实存入中间结果，入库审核页的表格页逐表显示记录、引导句或摘要，以及校验结果。
- 按"模型 + 提示词版本 + 输入内容 + 长度上限"的哈希缓存在 `.rag/llm-cache/`，`ingest --force` 重建时复用，结果可复现；temperature = 0。
- 模型、提示词版本、引导句开关与上限、摘要设置进入构建指纹。
- 入库用的 LLM 与问答的 `[llm]` 分开配置。

### 2.7 配置

| 配置 | 表格文本化 | 引导句 | 摘要 |
|---|---|---|---|
| `structured`（不变） | `labeled_rows_v1` | — | — |
| `structured_llm_<模型>` | `llm_records_v1` | 不加 | — |
| `structured_llm_lead_<模型>` | `llm_records_v1` | 加 | — |
| `structured_summary_<模型>` | `labeled_rows_v1` | — | 有 |

`<模型>` 为 `sonnet` 或 `gpt`。均为 512 token 单档，不做多预算配对比较（你已确定）。

### 2.8 评估：新增指标

**表格 excerpt**：词坐标落在解析器给出的表格框内的 excerpt。只依赖 PDF，各组合共用同一判断。含表格 excerpt 的证据组为**表格证据组**，含表格证据组的题为**表格题**（按当前 chunk 类型估计为 12 题，实施时按坐标确认）。

| 指标 | 定义 | 依赖 |
|---|---|---|
| 指标 1 表格 chunk 名次 | 每个表格证据组：在检索范围内的全量 chunk 排名中（返回单元映射之前），覆盖该组表格 excerpt 中任一词的 chunk 里，排名最靠前者的名次；摘要配置中为摘要 chunk 的名次 | 只依赖入库方式 |
| 指标 2 表格证据所需 K | 每个表格证据组：只看各方案中的表格 excerpt，在全量返回单元排名中全部覆盖所需的最少前几个单元，取各方案的最小值；每题取其表格证据组的最大值 | 入库方式 + 返回方式 |
| 指标 3 表格证据所需 token | 每题：全量返回单元排名中前"指标 2"个单元的 token 之和 | 同上 |
| 所需单元下限 | 每题：从每个证据组的可接受组合中各选一个，并集的最少单元数，与排名无关（当前值见 `reports/experiments/v3.13-llm-tables/min-units.md`） | 入库方式 + 返回方式 |
| K–覆盖–token 曲线 | K = 1…20 时，完整覆盖题数、表格证据完整覆盖题数、24 题返回 token 之和 | 入库方式 + 返回方式 |

指标 1 只看"最容易找到的一块"，必须与指标 2 一起看。

常规指标（K=3 的命中、完整覆盖、证据组召回、MRR、精确率、每题返回 token）照常报，作为护栏：看非表格题是否因表格 chunk 文本变化而变差，不作为判据。

### 2.9 报告

- 对比页 `reports/compare/v3.13-llm-tables/`：总表一页（5 种组合并列，表格题逐题列指标 1、2、3、下限），每组对比一页（预期与实际并排、标出变好变差），曲线一页。`compare` 现在把构建设置不同的评估分到不同标签页，本版允许只差表格设置的评估放进同一页。

## 3. 不改什么

- 规则序列化、表头判定、续表合并、正文与列表的分块；`structured` 的 chunk 逐字不变。
- 数据集 3.2.0 与 ground-truth；编码器、BM25 分析器、检索器。
- 问答的 LLM 与提示词。
- 不做多预算配对比较；不调 Top-K（曲线只用于后续权衡）。
