## 讨论中确认、需遵守的细节

- 判定：凑齐向量逐位比较，变好 / 变差 / 各有优势 / 不变互斥；与 K 无关，不设阈值；不用公式归类，13 种组合不投票（拍板问题 3、5）。
- 信息项 = 问题要求回答的内容；并列询问的几项分开；作答所需的中间事实不是信息项，出处写进方案（`rules/evaluation.md` 标注规则第 1 条）。
- 子问题与信息项的对应：所问的是该信息项要求回答的内容，或该信息项方案中的一个作答前提。多路凑齐名次：每段 excerpt 在对应各路中取最好、方案取各段最差、信息项取各方案最好。
- 去掉的做法：理想上限（与判定、指标无关）；每路固定取前 k 个（轮流取的子集，本质是预算规则，归延后的 Top-K 提案）；单独的分层评估模块（由配置框表达）。原问题一路没有"每圈最前"。
- 拆解提示词 v9 的取舍：v8 的"算出的项改问各个事实"使 PO-25-19-Q005 越界成 step-back，已去掉；描述指代的规则限定为"知道是哪一个才能找到答案"；重新生成在个别题上出现的丢限定条件、多余子问题属于生成波动，不再为此改提示词，交扰动测试统计。
- 一次检索 = 检索器排名 + 换算返回单元；之后的融合、选取、评估都以返回单元为对象。
- 写法都由问题本身生成，可叠加；串联写法不做。编码要从改写、翻译、HyDE、step-back 去掉；原句保留。不向规划 LLM 发送文档名。拆解不限个数。RRF 的 60 是常数；排名都是全量；K 是原问题返回单元的总数。
- 规划成本：命中缓存的调用记缓存中当次的费用与耗时。
- P5 移到 V3.15；跨文档的第二轮扩大检索范围、端到端问答评估记入 roadmap。
- 评估方法讨论的原始材料：`tmp/检索优化效果怎么衡量-讨论稿.md`、`tmp/RAG检索优化评估_讨论意见与实验建议.md`（不进 git）。
