# V2.0 增量需求：结构化 PDF 解析与多链路 RAG

更新日期：2026-09-18。状态：核心 RAG 增量已交付；正式检索评估闭环待按现行需求与架构完成。

本次在现有纯文本 RAG 上新增结构化处理链路，保留旧链路供对比。升级基线包含已实现的 V1.1 索引健康与引导恢复能力。下文 v1/v2 是可选择的处理链路编号。

## 1. 本次变更总览

| 环节 | 升级前 | V2.0 增量 |
| --- | --- | --- |
| 链路选择 | 只有一条处理链路 | 增加 `--pipeline v1/v2`，默认 v2，v1 保留原行为 |
| PDF 解析 | 按页提取纯文本 | 新增 Docling 版面解析与四工具表格恢复、准入、分组、选优 |
| 解析结果 | 按页文本 | 新增 ParsedDocument，融合原文结构与胜出表格 |
| 表格文本 | 与普通文本混在一起 | 规则识别表头，表达列关系、合并范围、空白和缺失 |
| 分块 | 按页、按字符数切分 | v2 按基本单元和实际 token 预算分块，支持跨页来源 |
| 索引 | 一份 collection 和 manifest | 每条链路独立保存，配置检查及重建限定同一链路 |
| 检索与问答 | 单页 chunk 来源 | 接入 v2 文本，支持多页来源、页过滤和引用 |
| 评估 | 单链路评估 | 同 PDF、同题集运行 v1/v2 对比 |

```text
v1：PDF → PyMuPDF 按页提取纯文本 → 按页递归字符分块（默认700字符、重叠目标100字符）
        → embedding → minimal_rag_documents_v1 + .rag/system-v2/pipelines/v1/manifest.json
v2：PDF → Docling 版面 + 四工具表格恢复与选优
        → 表头判定与表格文本化 → 完整 ParsedDocument → 结构分块 → embedding
        → minimal_rag_documents_v2 + .rag/system-v2/pipelines/v2/manifest.json
检索、问答、聊天和评估使用所选链路的 collection。
```

## 2. 新增链路选择

### P-01 保留 v1，新增 v2

- v1 使用 PyMuPDF 按页提取纯文本；每页单独递归分块，长度按 Python 字符串长度计算，默认最大 700 字符、重叠目标 100 字符，不跨页。分隔顺序为双换行、换行、句点加空格、分号加空格、逗号加空格、空格，最后细分到字符；分隔符保留在前一片段末尾。实际 overlap 受分隔边界影响，不保证恰好 100 字符。700/100 可由 CHUNK_SIZE/CHUNK_OVERLAP 配置；embedding 继续使用 E5 的 passage/query 前缀及向量归一化，不套用 v2 分块规则。
- v2 使用第 3—6 节的新解析和分块行为。
- **不显式提供 `--pipeline` 时，默认按 `--pipeline v2` 执行**；显式指定 `--pipeline v1` 才使用 v1。此默认规则适用于下面列出的全部命令。
- 后续增加链路编号时，不改变既有编号所代表的处理组合。

### P-02 所有相关命令支持相同选择

`documents`、`ingest`、`browse`、`chunks`、`search`、`ask`、`chat`、`eval` 均支持 `--pipeline`，输出实际采用的编号。例如：

```text
uv run python -m rag ingest --pipeline v2
uv run python -m rag search "交付数量是多少？" --pipeline v1
uv run python -m rag eval --pipeline v2
```

聊天会话内固定链路。所选链路无可用索引时，引导构建该链路索引，不自动改用另一条链路。以上接口与隔离行为均已实现。

## 3. 新增结构化 PDF 解析

### E-01 四工具表格恢复与选优

RAG 新增表格处理链路，执行顺序为：提取与归一化 → 准入 → 分组 → 评分选优。

| 阶段 | 必须实现的行为 | 输出 |
| --- | --- | --- |
| 提取 | PyMuPDF：lines、lines_strict、text；Camelot：lattice、stream、network、hybrid；Docling、Unstructured：各使用 RAG 自有表格需求规定的配置 | 原始事实、cell 级 TableCandidate、页级执行结果 |
| 准入 | 以 Docling 原生表格建立 TableSlot；候选与 slot 做同页几何比较 | 每个候选的匹配依据及准入结果 |
| 分组 | 一 slot 一组；候选必须唯一归属，不能从多个命中 slot 中随意选一个 | 分组结果，包括未进入评分的组及原因 |
| 评分 | 按文本 F1、关键 token 完整性、形状支持、空白异常四项指标选优，各占 25% | 每个非空可评分组的唯一 winner 及选择依据 |

本次必须实现的规则：

- 单元格文字、行列位置、跨度、可用 bbox 及来源证据完整迁移；不同工具的恢复方式和坐标转换保持一致。
- 页面越界容差为 **0.000001 pt**；Camelot 只对已确认属于同一合并格的重复完整文本去重。
- 候选覆盖率至少 **0.65**，slot 覆盖率至少 **0.77**，比较时各加 **1e-12** 吸收浮点尾差。多 slot 命中不能直接准入其中一个。
- 评分不增加淘汰阈值。单候选也有 winner；平分按 `pymupdf > camelot > docling > unstructured`，再按候选 ID 决胜。
- 其他工具不能为 Docling 未发现的表格自行新增 slot。

完整提取配置、工具适配、坐标、准入与评分公式见 RAG 自有的[表格提取与选优需求](../../requirements/v2.0/table-extraction-selection.md)。

### E-02 页级失败处理

某策略某页失败后继续后续页，成功页候选仍参与处理；不得丢弃整个策略。区分初始化未执行、页面失败、成功零表、成功有表。

可选工具或策略失败而 Docling 可用时，继续使用其余候选，保留诊断，不切换 v1。Docling 部分页解析失败时是否允许发布索引尚未确定，见 U-03。

### F-01 新增 ParsedDocument

以 Docling 文档解析结果为基础，保留 raw 文档，另建统一解析结果。该结果必须表达：

- 原 PDF 身份、页面来源、阅读顺序和层级。
- 文本节点的内容与类型；列表组及嵌套列表关系。
- 表格的 cell 结构、原节点引用、所用候选及选择原因。
- 可用的页码和 bbox；缺失位置不补造。

ParsedDocument 是表头判定和表格文本化完成后的完整语义结果。表格节点必须同时保留最终结构、选用来源、表头结论和文本化结果，再交给结构分块；不得先持久化不完整节点后由下游猜测或回填。

### F-02 替换原生表格内容

| 情况 | ParsedDocument 中使用什么 |
| --- | --- |
| 对应组已选出 winner | 在 Docling 原表格节点位置使用 winner 的结构，保留原节点和候选关联 |
| 原生表格未进入评分 | 使用 Docling 已有表格结果，并记录未评分原因及原生来源 |

同一表格不能以原生内容和 winner 内容重复出现。非空评分组没有 winner 不属于正常回退情况。

### F-03 文档元素范围

- 段落、标题、图注、表注、脚注、页眉和页脚均保留并进入分块。
- 图片元素不加入 ParsedDocument；独立识别的图注文字仍保留。
- 一个 Docling 列表组及其全部嵌套子列表构成完整 List；相邻独立列表不自行合并。
- Docling 已识别为同一跨页节点的内容保持完整，保留多个页面来源。

## 4. 新增表格文本化

### T-01 使用规则生成一份正文

结构表格按[结构表格文本化需求](../../requirements/v2.0/table-text-serialization.md)转换为文本，再参与分块和 embedding。不调用 LLM，不针对合同、产品或特定业务词设计转换分支；不自动改数、补单位或纠正原文。

embedding 和检索后交给 LLM 使用同一份 chunk 正文。模型所需的 passage 前缀由 embedding 适配添加。

### T-02 独立判定表头

按[表头判定需求 HD-01～HD-07](../../requirements/v2.0/table-header-detection.md)执行：检查结构 → 固定起点 → 枚举候选 → 取样比较 → 唯一性判断。类型分类规则标识为 `table_header_v1`，取样预算为 8 行，形成稳定类型至少需要 2 个独立观察；完整数字和日期词法以该需求附录 A 为准。

至少一列出现“候选最下层为文字、后续为稳定数字或日期”才提供支持。数字/日期同类型延续不否决其他列；整行空白跳过，个别空格逐列向下找，纵向合并格只算一次观察，有效文字不能跳过。工具 role 不直接决定结果。无通过候选或多个通过候选时，表头未确定。

### T-03 有表头时按列路径表达

例如两级表头“数量 → 国内、海外”，输出“数量 / 国内：100；数量 / 海外：200”。

- 按列覆盖关系从上到下建立路径，同一跨行表头格只取一次。
- 不同物理格即使文字相同，也不自动去重。
- 空白标题位置用原列编号补足；整列没有标题时用列编号。

### T-04 无可靠表头及合并格的表达

- 表头未确定时标明该事实，按原始行列编号表达全部内容，包括第一行；分块后编号不重置。
- 合并格表达原始覆盖范围和文字，适用于跨行、跨列及同时跨行列；不复制成多个独立值。
- 不依据值是数字就推断合计，也不依据文字就推断每行同值。
- 全宽行和部分跨列行按原始位置保留；本版不自动识别分组标题或汇总，不向后续行传播分组含义。

### T-05 区分空白与缺失

| 输入事实 | 表达要求 |
| --- | --- |
| 独立格内容为空 | 空白标记，不解释成 0 |
| 原文为 0、-、N/A 等 | 原样保留 |
| 位置由合并格覆盖 | 归入合并格，不另造空格 |
| 缺少位置对应的格记录 | 缺失标记，与空白区分 |

系统标记需与同名原文可区分，具体模板和转义按[结构表格文本化需求](../../requirements/v2.0/table-text-serialization.md)执行。

### T-06 跨页续表范围

本版不检测、拼接独立续表，不继承前表表头。Docling 原本就是同一个跨页表格节点时，保留已有结构和多页来源。

## 5. 新增结构化 chunking

普通文本和 List 的正文格式、递归边界、overlap、父项退化及终止条件按[普通文本、List 文本化与 V2 分块需求](../../requirements/v2.0/document-text-and-chunking.md)执行。

### C-01 用实际 embedding 输入长度控制上限

v2 使用模型实际 tokenizer 计数，当前模型上限基线为 **512 tokens**。预算包括正文、格式标签、重复上下文、overlap、passage 前缀及特殊 token。embedding 前校验最终输入，不依赖静默截断。

### C-02 完整单元的组合规则

| 单元 | 未超限时的处理 |
| --- | --- |
| 整张表格 | 独立成块，不与普通文本混装 |
| 整个 List，包括嵌套子列表 | 独立成块，不与普通文本混装 |
| 段落、标题及其他文本 | 按阅读顺序在上限内合并，允许跨章节、跨页 |

遇到表格/List，结束当前普通文本块。加入下一个完整单元将超限时，先换块，不为填满前一块切开该单元。只有单个单元本身超限才拆分。

### C-03 超长文本和列表

- 文本按段落、句子、短语等自然边界递归拆分，必要时进一步细分，长度仍由 tokenizer 校验。
- 整体 List 超限先按完整列表项拆；单项仍超限才拆内部文字。
- 嵌套列表片段附带必要父项文本及来源。
- 完整元素、完整列表项之间不 overlap。仅超长段落和超长列表项内部允许最多 **32 tokens** overlap，可配置，优先自然边界，可少于 32 或为零。标题默认无 overlap。

### C-04 超长表格

按以下顺序拆分：

1. 按完整数据行拆，重复相关表头，不重复数据行。
2. 纵向合并覆盖的多行优先同块；整体超限时允许分开，各片段带合并内容、原始覆盖范围及当前范围。
3. 单行超限时按完整单元格拆，保留原行号及对应表头/列号。
4. 单格仍超限时按自然边界拆内部文字，保留原位置和片段次序，不设置表格内容 overlap。

### C-05 重复上下文本身超限

正文通过拆分完整保留。重复表头或父项文字放不下时，退回简短行列/父项标识；完整上下文仍在其他片段保留，并记录关联。所有片段必须满足模型上限。

### C-06 拆分来源

chunk 保存原节点、原页面、父单元、片段次序、原文范围及可用 bbox。重复的表头、父项、合并上下文和 overlap 与当前片段正文可区分。不能把多页 chunk 强行归为一页或伪造跨页 bbox。

## 6. 修改 embedding、索引和查询接入

### I-01 每条链路独立索引

每条链路分别保存 collection 和 manifest。构建、增量更新、清理、状态检查、查询及重建均限定所选链路，不能覆盖或混用其他链路索引。

检索、chunks 页过滤、引用输出和评估接入 C-06 的多页来源。问答使用 T-01 的同一份正文。

### I-02 同链路构建配置检查

manifest 保存一份该链路的构建配置，包含影响结果的 parser、文本化、chunker、embedding 参数及规则修订。当前配置只与同一链路的已有记录比较。

v1 使用 `minimal_rag_documents_v1` 和 `.rag/system-v2/pipelines/v1/manifest.json`；v2 使用 `minimal_rag_documents_v2` 和 `.rag/system-v2/pipelines/v2/manifest.json`。升级前无版本号的 collection/manifest 只归档到 `.rag/legacy-system-v1/`，不作为任一新链路索引。

不一致时说明变更和影响范围，经用户确认后重建。日志、审核视图、top_k 和提示词调整不触发索引重建。

### I-03 重建范围

| 触发情况 | 重跑范围 |
| --- | --- |
| 单份 PDF 更新 | 该文档在所选链路从解析到 embedding 全部重跑 |
| 所选链路全局构建配置变化 | 该链路受影响文档全部重建，通常为全部文档 |
| 文件和构建配置未变 | 保留现有增量跳过行为 |

本版不复用中间阶段，不实现检查点或阶段恢复。保存 ParsedDocument 不意味着重建时跳过解析。

### I-04 解析产物与诊断输出

| 模式 | 保存内容 |
| --- | --- |
| 默认 | Docling 原始文档、完整 ParsedDocument、最终 chunks 及来源、包含 slot/group/winner 和最小原因链的 selection summary、manifest 中的构建配置、R-01 的逐 PDF winner 审核 HTML |
| 可选诊断 | 四工具完整 raw、全部候选、详细准入/分组/评分结果、额外的候选分组/评分审核视图 |

审核视图不作为入库或检索输入，但 R-01 视图必须默认生成，不能受可选诊断开关控制。具体产物目录、staging 发布边界及诊断目录已经进入当前架构草案，架构审阅和技术验证不得降低本节规定的默认产物范围。

### R-01 新增逐 PDF 的 winner 全过程审核视图

每份 PDF 在 v2 本次处理完成后输出**一个 HTML 文件**，集中展示该 PDF 所有经过分组选优的 winner，不按表或 chunk 拆成多个文件。文件头标明 PDF、链路、构建版本和 winner 数量，按文档顺序提供表格导航。

每张 winner 必须展示：

| 区域 | 展示要求 |
| --- | --- |
| 表格身份 | group/slot/candidate ID、胜出工具与策略、原页面来源，能够与解析结果对应 |
| 结构表格及表头 | 按实际 rowspan/colspan 展示完整表格；明确“已确定表头”或“未能确定表头”及原因。已确定时对所有表头物理格加背景色，包括多层及跨行格；未确定时不根据工具 role 猜测高亮 |
| 文本化结果 | 展示完整的规则转换文本，含未确定表头和合并范围等表达，不只给摘要 |
| 最终分块 | 展示该表关联的全部最终 Embedding chunk 正文。未拆表展示其唯一块；拆成多块则一块不漏。chunk ID、来源范围、token 数与评分明细属于诊断数据，不混入人工验收主视图 |

chunk 正文必须直接读取实际送入 embedding 的最终 chunk 数据，不在页面里另做一套转换或模拟分块。长内容不能截断或省略块；PDF 原文按文本转义，不执行其中 HTML/脚本。页面应可本地打开，核心表格、样式与文本包含在该文件内。

只有选优 winner 纳入此视图，未评分的原生回退表格不计为 winner。本次成功处理但 winner 为零时仍输出文件，明确“本次没有 winner”，不能把旧运行的表格混入。若本次存在已知缺失结果，必须显式显示缺失阶段，不以空内容冒充成功完成。

HTML 生成是 v2 单文档入库的必需步骤。生成失败时，该 PDF 本次入库失败，不发布新向量或新 manifest 记录，保留此前可用索引和旧 HTML，并记录错误阶段 `winner_review_generation`。

验收：HTML 中 winner 数及 ID 与本次评分一致；表头着色范围与判定一致；转换文本与实际输出一致；每个表格相关 chunk 的 ID、正文、数量及次序与最终分块结果一致。

## 7. 验收要求

### V-01 功能验收

| 变更 | 验收条件 |
| --- | --- |
| 多链路 | 显式 v1 保持原结果；构建/重建 v2 后 v1 仍能独立查询 |
| 表格处理 | 相同输入和配置重复运行得到一致的准入、分组和 winner；失败页不丢弃成功页结果 |
| 文档融合 | 表格替换不重复，未评分原生内容保留，图片排除、文字及层级保留 |
| 文本化 | 表头与合并、空白规则可复核，不确定表头不猜字段名 |
| 分块 | 符合独立单元、超限拆分及 overlap 规则，每个实际 passage 输入均未超限 |
| 索引与问答 | 配置检查和重建只影响所选链路；检索正文、页过滤和多页引用正确 |
| winner 审核视图 | 每 PDF 一个 HTML；全部 winner、表头状态和着色、完整文本化结果及全部最终块均可核对，不依赖开启额外诊断 |

### V-02 效果对比
