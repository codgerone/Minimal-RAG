# V3.6 提案：表头判定修正与类型词法扩充

状态：**待审**　｜　分支：`retrieval-opt`　｜　基线：`v3.5`　｜　日期：2026-10-09

属于"检索效果优化"主题。表头判定依据"文字标题 → 下方稳定为数字或日期"的类型转变，因此判断一个格子是不是数字、日期，直接决定表头认得对不对。

## 背景：PO 25-19 表四认错表头

表四（交货日期表）第 0 行是表头（列 0 空白、`DELIVERIES`、`DDP DATE`），现在被认成第 0–1 行，第一批交货那一行被当成表头，每一行的列名都写错了。原因有两个，都是代码偏离了 `rules/table-header.md`：

1. **日期写反**：规则写 `DD/MM/YYYY`，代码按 `MM/DD/YYYY` 判断。`28/02/2026` 被判为文字，其余 5 个日期第一段恰好不超过 12，被判为日期。于是第 1 行像"文字标题，下方是稳定日期"，错误候选通过。
2. **空白标题列使正确候选被排除**：代码要求候选表头**每一列**都有文字，列 0 空白，所以只取第 0 行的候选在结构检查时就被排除。规则写的是候选"至少含有一些文字"，并允许"全部为空的列没有列名"。

在现有入库结果上模拟（5 份文档 13 张表）：只修 1，表四变为认不出；只修 2，仍然认错；两个都修，表四认对第 0 行，其余 12 张表结果不变。

另外，扫描全部候选表格的单元格，以下常见写法现在都被判为文字：符号与数字之间有空格的金额（`$ 280,875.00`）、千分位符号后带空格的数（`1´ 131,056.00`）、日大于 12 的 `DD/MM/YYYY`、月份写成英文单词的日期。

## 0. 需要你拍板的问题

### Q1 写法有歧义时，一个格子算什么类型？

**事实**：扩充格式后，同一写法常能读成多种东西：`09/04/2026` 可以是 4 月 9 日或 9 月 4 日；`20260228` 既是数字也是日期；`4.56` 若收录 `DD.MM`，就既是数字也是日期。表头判定只需要知道"是不是数字/日期"，不需要知道是哪一天。

**选项**：

- A. **每个格子判出"可能的类型集合"**（推荐）：只要有一种读法合法，就把该类型放进集合；数字和日期都不成立才是文字。一列的取样格集合**有共同的非文字类型**，这一列才算稳定。
- B. 每个格子只判一种类型，按固定优先顺序（先日期后数字）取第一个。

**推荐 A**。日期的日月顺序不再需要猜，也不需要按文档语言区分；新增一种日期写法不会让原本稳定的数字列变得不稳定（`4.56` 和 `13.49` 的共同类型仍是数字）。B 会让新增格式抢走数字列，词法越扩越容易出错。

**影响**：表头判定的稳定类型条件由"类型全部相同"改为"有共同类型"，规则文档的第 5、6 步相应改写。

### Q2 本轮收录哪些格式？

**推荐收录**（数字与年月日之间的分隔符可以是 `/ - .`，也允许没有空格或有一个空格）：

| 类别 | 格式 |
|---|---|
| 全数字日期 | 年月日：`YYYY-MM-DD`、`YY-MM-DD`；日月年：`DD-MM-YYYY`、`DD-MM-YY`；月日年：`MM-DD-YYYY`、`MM-DD-YY`；年月：`YYYY-MM`；八位 `YYYYMMDD` |
| 无年份日期 | 只收 `/` 分隔：`DD/MM`、`MM/DD` |
| 月份为单词的日期 | 英文、西班牙文月份全称和缩写（大小写不限），可带序数后缀（`st/nd/rd/th`）和逗号：日月年、月日年、月年、日月、月日；西班牙文写法可带 `de` |
| 中文日期 | `YYYY年M月D日`、`YYYY年M月`、`M月D日` |
| 数字 | 千分位可用 `, . ' ’ ´ 空格`，分隔符后允许多一个空格；可带正负号（含 `−`）、括号负数、百分号或千分号（前面可有空格） |
| 金额 | 符号 `$ US$ S/ S/. € £ ¥ R$` 或三位货币代码，写在数字前或后，中间可有空格，负号可在符号前或后；后缀 `元`、`万元` |

日期的合法性按日历判断（日不超过该月天数，2 月按闰年允许 29 日）；两位年份按任意年份处理。

**不收录**：

- `.` 或 `-` 分隔的无年份日期：与小数、数量范围和编号冲突，收录后编号列会被当成日期列。
- 时刻（`14:31:15`）、带时区的时间戳：不作为日期，仍算文字。

**你可以选**：按推荐；或指出要增删的格式。

### Q3 带单位的数量（`1,000 PCS`、`220V`、`5(60)A`）算不算数字？

**事实**：订单的数量列、规格列常带单位。现在它们被判为文字，这一列不提供类型转变的支持，但也不否决候选。单位种类没有封闭清单，`2 wires`、`4G` 这类型号描述也会被误收。

**推荐**：本轮不收录，作为表头判定的后续候选（与 PO-24-12 产品表一起看）。

## 1. 目标

- PO 25-19 表四认对表头（第 0 行）。
- 类型词法覆盖 Q2 的常见格式，日期不再依赖日月顺序。
- 其余表格不因此出现新的认错。

## 2. 改什么

1. **类型词法**（`rag/ingest/tables/header.py`）：按 Q1、Q2 重写，每个格子输出可能类型的集合。
2. **稳定类型**：一列至少 2 个不同物理格的有效观察，且它们的类型集合有共同的数字或日期类型，才算稳定。
3. **类型转变**：候选最下层格的类型集合为空（只能是文字），且下方稳定，该列才支持候选。
4. **结构检查**：候选只要求至少一列有文字；表头全部空白的列允许存在，没有列名（与规则文档现有写法一致）。
5. 规则文档 `rules/table-header.md` 的"判定步骤"和"类型词法"按上面改写；`RULES_VERSION` 升为 v3.6，`structured` 重建索引。

## 3. 不改什么

- 表头候选的枚举方式、8 行取样预算、唯一性要求。
- 表格选优、表格文本格式（`labeled_rows_v1`）、分块、检索。
- 带单位的数量（Q3）、全文字表格认不出表头的问题。
- `plain_text` 不处理表格结构，不受影响。

## 4. 怎么验收

- **验收页**：表格审核页上 PO 25-19 表四显示表头识别成功，表头为第 0 行；列出 13 张表改动前后的表头结论对比，改变的表逐张说明原因。
- **评估**：`structured` 重建后跑 `eval`，与 V3.5 基线（命中率 70.8% / 完整覆盖 29.2% / MRR 45.8%）对比，逐题列出排名变化。
- 单元测试覆盖 Q2 每类格式的正例、歧义例，以及应判为文字的写法（时刻、型号、编号、电话、带单位的数量）。
